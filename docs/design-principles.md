  - **`--radius-md`(=20px, `--radius` 별칭)** — briefing.html·lecture.html 이 폴백 없이 참조하는데 정의가 없어 카드 모서리가 0 이었다(같은 사고의 작은 판). 이름을 지우지 말 것.

- Typography(`--fs-*`)·spacing(`--space-*`, 8px)·radius(8/14/20/24)·섹션 배경 리듬 전부 토큰화 — 하드코딩보다 토큰 우선. **`--fs-body-sm: 15px`(2026-07-25 신설)는 본문 17과 캡션 14 사이의 '카드 설명줄' 칸** — 캡션 14px는 보조 정보용이라 카드의 유일한 설명 줄에는 작다(승준노트 `.bf-desc`·홈 `.bp-desc`가 쓴다). ⚠️ 별도 파일에서 쓸 땐 `var(--fs-body-sm, 15px)` 폴백을 붙일 것(캐시 분리 대비 — 위 briefing.html 항목 참조).

## UI 원칙 15개 (2026-08-02 전면 재검토 — 구 '모바일 10대 원칙' 대체)

> 구 원칙은 2026-07-04 에 세운 '모바일 UI 10대 원칙'이었다. 2026-08-02 UX·UI 실측 진단에서
> **원칙 자체를 심판**했고(오너 "지금 우리가 사용하는 원칙이 최선 또는 정답이 아닐 수 있잖아"),
> 지워서 이득인 조항은 없었다. 판정: 유지 2 · 수정 6 · 교체 2 · 신설 4.
> 같은 날 오너가 후기 카드의 `1기` 조각을 짚어 **15번(값에 이름 붙이기)**을 뒤에 더했다.
> 구 조항 원문은 아래 '구 10대 원칙(폐기 기록)' 절에 그대로 남긴다.
>
> **가장 중요한 변화는 조항이 아니라 '확인 수단'이다.** 지금까지 검증이 375px 눈검사뿐이라
> **눈에 안 보이는 것이 전부 통과했다** — 입력칸 15px, 전송량 3.8MB, 비텍스트 대비 1.38:1,
> 320px 잘림. 그래서 각 원칙에 "어떻게 확인하는가"를 붙였다. 확인 수단이 없는 원칙은 원칙이 아니다.

### 1. 활자 크기 — 단위는 px, 하한은 12, 입력칸은 16
단위는 **CSS px 만 쓴다(pt 표기 금지 — 구 원칙의 '12pt+'는 실제로 px 를 뜻했다).**
지킬 것 둘: **절대 하한 12px**(법적 고지 포함), **학생이 포커스하는 입력칸은 16px 이상.**
기본 사다리는 본문 17 · 카드 설명 15(`--fs-body-sm`) · 캡션 14 — **권장값이지 기존 화면을
일괄 재조판하라는 뜻이 아니다.**
- ⚠️ **입력칸 16px 은 미학이 아니라 버그 방지다.** iOS Safari 는 15px 이하 입력칸에 포커스가
  가면 화면을 확대하고 blur 해도 되돌리지 않는다(viewport 에 maximum-scale 이 없어 반드시
  일어난다). 결제 직전 화면이 확대된 채 가로로 밀린 실사고가 있었다(2026-08-02 A-2).
- **하한 예외는 '읽는 활자가 아닌 것'뿐**: ▾ 같은 장식 글리프(aria-hidden), 아바타 원 안의
  이니셜 한 글자. 예외를 쓸 땐 CSS 에 이유를 주석으로 남긴다.
- **확인**: 375px 에서 보이는 텍스트 노드의 computed font-size 를 모아 12 미만을 센다.

### 2. 터치 표적 — 44×44, 인접 간격 8px
최소 44×44px, **인접 타깃 사이 8px 이상.** 보이는 크기와 탭 영역은 분리해도 된다 —
`nav.css` 햄버거·`briefing.html` 점 버튼의 투명 `::after` 확장이 정본이다.
44 를 못 지키는 자리도 **24×24px(WCAG 2.5.8 AA) 아래로는 안 내려가고, 그럴 땐 간격 8px 을
반드시 지킨다.**
- 기준이 왜 44 인가: WCAG 2.2 는 24px(AA)/44px(AAA), Material 3 는 48dp 를 권한다. 우리는
  **44 를 목표, 24 를 하한**으로 잡는다 — 법적 하한은 24 지만 모바일 99% 서비스에서 24 는 좁다.
- **간격 조항이 구 원칙에 없었다.** 크기만 규정하면 촘촘한 버튼 줄이 통과한다(briefing 실측
  gap 0px 쌍 8개). Material 이 크기와 간격을 같이 규정하는 이유다.
- **확인**: `elementFromPoint` 히트 테스트로 잰다(박스 크기로는 `::after` 확장을 못 잡는다).

### 3. 공용 부품 — 새로 만들지 말고 있는 것을 쓴다 *(구 '아이콘 통일감' 교체)*
아이콘 글리프(→ ✓ ▾)·바텀시트·토스트·스켈레톤은 이미 있는 것을 쓴다. 같은 것이 **두 번째**
필요해지면 복사하지 말고 먼저 쓰는 쪽을 공용 파일로 뺀다(`nav.js`·`waitlist.js`·`quickfix.js`·
`challenge-reviews.js`·`challenge-sticky.js`·`pay-return.js`·`draft-keep.js` 가 그 결과다).
픽토그램 이모지는 학생 화면에 안 쓴다(admin 예외).
- ⚠️ **새로 만들 때만 적용한다.** 지금 있는 것을 재작성하라는 뜻이 아니다 — 빌드도 테스트도
  없는 손 HTML 37페이지에서 공용 CSS 로 뽑으면 한 곳 수정이 37페이지에 번진다.
- **확인**: 같은 역할 컴포넌트의 클래스명을 세어 종류가 늘었는지 본다.

### 4. 명도 대비 — 본문 4.5:1, 큰 글자 3:1, **경계선 3:1**
본문 4.5:1, 큰 텍스트(24px+ 또는 굵은 18.66px+) 3:1.
**입력칸·버튼·탭의 경계선과 선택·활성 상태 표시는 배경 대비 3:1**(WCAG 1.4.11).
비활성 처리는 opacity 로 블록 전체를 흐리게 하지 말고, '왜 못 쓰는지' 문구는 대비를 유지한다.
- **경계선 조항이 구 원칙에 없어서** `--border`(1.38:1)가 입력칸·고스트 버튼에 그대로 쓰였다.
  경계선이 유일한 식별 수단인 자리는 **`--border-strong`**(종이 위 3.25:1 · 흰 카드 위 3.43:1).
  ⚠️ `--border` 자체를 올리지 말 것 — 카드·구분선까지 진해져 사이트가 표처럼 보인다.
- **확인**: 상대휘도 공식으로 직접 계산한다. 그라디언트·사진 배경은 스크린샷 픽셀로 잰다.
- ⚠️ **APCA / WCAG 3.0 으로 갈아타지 말 것**(2026-08-02 판단): WCAG 3.0 은 아직 Working Draft 이고
  시각 대비 항목은 알고리즘 미정 상태다. 법적 기준은 WCAG 2.2 AA 다.

### 5. 라운드 — 토큰 4종 + 알약 + 원
`--radius-xs 8` / `--radius-sm 14` / `--radius(-md) 20` / `--radius-lg 24` + 알약 999px + 원 50%.
**새 px 값을 만들지 않는다.**
- ⚠️ **앞으로 적용이다.** 현재 라운드 선언 624개 중 토큰 사용은 213개(34%), 하드코딩 고유값 18종
  (실측 2026-08-02). 일괄 치환하지 말고 **그 파일을 어차피 손볼 때 함께 바꾼다.**
- **확인**: `border-radius:` 의 고유값 개수를 센다. 늘었으면 새로 만든 것이다.

### 6. 계층 — 한 화면에 채움 CTA 하나
**같은 행동을 아래로 반복하는 것은 위반이 아니다** — 3화면(약 2,400px)을 넘는 페이지는
어디까지 스크롤해도 주 행동이 화면 안에 있어야 한다(`challenge-sticky.js` 의 하단 바).
서로 **다른** 행동이 같은 무게로 경쟁하면 하나만 채움으로 둔다.
- 목적상 CTA 를 두지 않기로 한 화면(챌린지 허브 — 오너 확정)은 대상 아님.
- 같은 행동이 **동시에 두 개 보이는 것**은 여전히 금지 — 히어로 버튼이 보이는 동안 하단 바를
  숨기는 이유다.
- **확인**: 문서 좌표로 버튼 y 위치를 뽑아 '버튼 없는 최장 구간'을 잰다.

### 7. 하단 고정 자리는 주 행동이 쓴다 *(구 '하단 내비 제외' 교체)*
하단 고정 자리를 **내비게이션에 내주지 않는다.** 화면을 자주 오가는 도구 화면은
**상단 서브내비(상위 복귀 + 현재 위치)**로 해결하고 같은 형태를 쓴다
(`polish.html`·`ai-killer.html`·`program.html` 의 `.subnav` 가 정본). 상단 nav 는 항상 보이게 유지한다.
- 구 조항은 "앱 개발 단계로 이월"이라 **왜 안 되는지가 없었다.** 이유는 이것이다:
  MONC 는 앱이 아니라 랜딩 겸 도구 사이트이고, 하단 자리를 이미 주 행동(신청·저장·다듬기)이
  쓰고 있다. 드로어는 375×812 에 스크롤 없이 들어가고(755px) 항목 19개가 전부 44px 초과다.
- ⚠️ **스크롤 방향 감지 헤더 숨김도 금지** — 오너 지시("무조건 다 보이게")와 정면 충돌하고,
  허브형 사이트라 헤더가 사라지면 현재 위치 표시를 설계한 의도가 무너진다.

### 8. 여백 — 읽는 화면은 넉넉히, 조작하는 면은 밀도가 가독성 *(유지 + 예외 명문화)*
읽는 화면(홈·상세·기록물)은 섹션 상하 60px+, 카드 내부 16px+.
**단 신청·결제·목록처럼 한 화면에서 비교하고 조작하는 면은 예외**(apply.html 의 섹션 패딩
14px 은 위반이 아니다).

### 9. 정보 그룹핑 *(유지 + 확인 수단 추가)*
섹션·연한 배경면·카드로 묶는다. 묶음의 경계를 선 하나로만 표현할 때는 그 선이 배경 대비 3:1.
- **확인**: 375px 가로 넘침 0 **+ 320px 에서 잘림 없음**까지 본다.
  `overflow-x:clip` 이라 잘려도 스크롤바가 안 생겨 **조용히 잘린다**(briefing 실사고).

### 10. 큼직한 레이아웃 — 길이를 늘리면 대가를 같이 낸다
덩어리는 크게 하되, 늘어난 만큼 **주 행동과 결정 근거(가격·코치·일정)가 스크롤 어디에서든
손에 닿아야 한다.**
- ⚠️ **페이지 길이 자체에 상한을 두지 않는다.** 상한을 정하면 오너가 쓴 커리큘럼 10일치와
  전후 음성 7쌍을 '초과'라는 이유로 덜어내는 수정이 정당화된다. 재는 것은 길이가 아니라
  '지금 이 화면에서 다음 행동을 할 수 있나'다.

### 11. 상태를 사실처럼 말하지 않는다 *(신설 — 로딩·비어 있음·실패)*
화면은 모르는 것을 아는 척하지 않는다. 로딩·비어 있음·실패를 **서로 다른 문구로 구분**하고,
**데이터를 못 받았을 때 하드코딩 값으로 확정 문구를 만들지 않는다**(모르면 '확인 중').
실패는 alert 이 아니라 문제가 난 **그 자리에** 인라인·토스트·시트로 띄우고 다음 행동을 같이 준다.
결과를 기다리는 동안 무엇을 기다리는지 화면이 말한다(`pay-return.js`).
- **근거(2026-08-02 실사고 A-1)**: `recruit.js` 폴백 날짜가 과거라 조회가 실패하면
  **전 챌린지가 '마감'으로 확정 표시**됐다. 오류처럼 안 보여서 방문자는 재시도하지 않았다.
- **확인**: 데이터 계층을 실패로 목(mock)해 놓고 화면을 연다. '마감'·'0건' 같은 **단정**이
  나오면 위반이다.

### 12. 결정에 필요한 것은 결정하는 화면 안에 둔다 *(신설)*
값(가격) · 다음 행동(버튼) · 판단 근거(누가 가르치나·언제 하나)가 그 화면에 다 있어야 한다.
다른 페이지로 넘어가야 알 수 있는 값은 없는 것과 같다.
- 적용 대상은 **결정을 유도하는 화면(챌린지 상세 4종·특강 상세·이용권 구매)**이지
  목록·허브가 아니다(허브 CTA 는 오너 확정 반대).
- **금액은 반드시 DB 를 읽는다**(`site_config.challenge_price` 등). 조회 실패 시 숫자를
  지어내지 말고 비운다 — 광고가와 청구가가 어긋난 사고 기록이 있다.
- **근거(A-3)**: 상세 4종에 가격이 0회 등장했고, 보신각은 8,551px 동안 누를 버튼이 없었다.

### 13. 성능·전송량 예산 *(신설)*
미디어가 여러 개 들어가는 페이지는 **올리기 전에 실제 전송량을 잰다.**
**오디오·비디오는 `preload="none"`**, 이미지는 `loading="lazy"` + 크기 예약(CLS 방지).
첫 로드 **500KB** 를 자체 기준선으로 삼고, 넘으면 이유를 적는다.
- **근거(A-4)**: challenge-voice 가 재생 버튼을 누르지 않아도 3,854KB 를 받았다 →
  `preload="none"` 한 단어로 178KB.
- 이 사이트는 웹폰트를 2,009KB→610KB 로 낮추고 실측을 주석에 남긴 전례가 있다.
  성능을 볼 줄 아는데 조항이 없어 화면마다 다시 판단하고 있었다.
- **확인**: Playwright 로 `response` 이벤트의 content-length 를 합산한다.

### 14. 포커스와 키보드 *(신설 — 우선순위는 위 셋 다음)*
조작 요소에 **눈에 보이는 포커스 링**(3px 이상, 배경 대비 3:1 — `nav.css` 공통 규칙).
화면을 덮는 것(모바일 메뉴·바텀시트·모달)은 **열 때 포커스를 안으로 옮기고, 열려 있는 동안
뒤를 `inert` 로 막고, 닫을 때 열었던 버튼으로 되돌린다.** 셋 중 하나만 하면 반쪽이다.
전 페이지에 **본문 바로가기**(`.skip-link`)를 둔다 — 평소엔 숨고 포커스되면 화면에 나타난다.
**`div` 에 click 핸들러만 달지 않는다** — `role="button"` + `tabindex="0"` + Enter·Space
키 핸들러 + 여닫는 것이면 `aria-expanded` 까지가 한 벌이다.
- **근거**: 크로미움 기본 링은 웜페이퍼 위 1px 주황이라 거의 안 보였다(실측).
- **근거(2026-08-02)**: 챌린지 상세 4종의 커리큘럼 아코디언이 `div`+click 뿐이라
  키보드로 열리지 않았다. 1주차만 기본 열림이라 **2주차 DAY 6~10 에 아예 닿지 못했다** —
  구매를 결정하는 화면에서 상품 설명 절반이 막혀 있던 셈이다.
- **확인**: 마우스를 쓰지 않고 Tab → Enter 로 그 화면의 모든 기능을 한 번씩 눌러 본다.

### 15. 화면의 값에는 그것이 무엇인지 붙인다 *(신설 — 2026-08-02 오너 지적)*
숫자·짧은 값을 홀로 두지 않는다. 카드 구석의 `1기`, 태그 하나짜리 `대한항공` 처럼
**값만 남은 조각은 오타로 읽히거나 다른 뜻으로 읽힌다.**
- **근거**: 챌린지 상세 후기 카드에 `1기` 만 떠 있었다(오너 "저게 오타인지 기수를
  알려주는건지를 모르잖아"). 실제로는 코드가 `r.name` 을 읽는데 컬럼명이 `reviewer_name`
  이라 **이름이 한 번도 안 붙어** 기수 조각만 남은 것이었다.
- **근거**: 합격 수기 태그가 `[대한항공] [1기]` 라 **'대한항공 입사 1기'로 읽혔다.**
  실제 뜻은 몬크 참여 기수 → `[대한항공 합격] [몬크 1기]`.
- **확인**: 카드 한 장만 캡처해 잘라 놓고 읽어 본다 — 제목·주변 없이도 뜻이 서면 통과다.
  후기·수기 카드는 실제로 캡처돼 DM 으로 돌아다닌다.
- ⚠️ 값을 붙이는 것은 **DB 컬럼명이 아니라 화면 문구로** 한다. 값이 비었을 때 무엇이
  남는지(이름 없는 후기 → `영합각 2기 참여자`)까지 정하고 나서 화면에 올린다.

### 규칙이 아니라 '앞으로만' 적용하는 것 — 일괄 수정 금지 목록
아래는 **새로 쓰는 코드에만** 적용한다. 지금 있는 것을 일괄 치환하면 375px 전수 재검증
비용이 이득보다 크다(2026-08-02 판단).

- 학생 대면 `alert()` 84곳(apply 24 · lecture 17 · program 16) → 원칙 11.
  **돈이 오가는 apply.html 의 제출 검증은 2026-08-02 에 인라인으로 이미 교체했다.**
  나머지는 그 파일을 손볼 때 함께 바꾼다.
- `font-size` 전면 rem 전환 → 선언 2,689곳. 하려면 `--fs-*` 토큰 6개만 rem 기반으로 바꾸고 점진 이관.

## 적용 방법

- 대상: **학생이 보는 모든 페이지 + admin.**
  ⚠️ 구 문장은 "admin 은 데스크톱 도구라 터치는 자주 누르는 컨트롤 위주"였다. **폐기한다** —
  오너는 admin 을 **아이폰에서 쓴다**(2026-08-02 지적). 이 예외 조항 때문에 입력칸 26개가
  16px 미만, 조작요소 102개가 44px 미만으로 남아 있었다. admin 도 학생 화면과 같은 기준이다.
  다만 **데스크톱 밀도는 유지**한다 — 하한 규칙은 `@media(max-width:960px)` 안에만 둔다.
- **375px 모바일에서 먼저 검증.** 로컬: `python3 -m http.server 5500`.
- **눈검사만으로는 절반이 통과한다**(2026-08-02 교훈). 올리기 전에 아래를 같이 잰다 —
  전부 Playwright 한 번에 돌아간다.

| 무엇을 | 어떻게 | 관련 원칙 |
|---|---|---|
| 활자 하한 | 보이는 텍스트 노드의 computed font-size 를 모아 12 미만을 센다 | 1 |
| 입력칸 | `input`·`textarea` 의 font-size 가 16 이상인지 | 1 |
| 터치 표적 | `elementFromPoint` 히트 테스트(박스 크기 아님) + 인접 간격 | 2 |
| 대비 | 상대휘도 공식으로 직접 계산 · 그라디언트는 스크린샷 픽셀 | 4 |
| 넘침 | 375px **과 320px** 에서 `scrollWidth − clientWidth` | 9 |
| 실패 화면 | 데이터 계층을 실패로 목(mock)하고 열어 '단정'이 나오는지 | 11 |
| 전송량 | `response` 이벤트의 content-length 합산 | 13 |
| 포커스 | Tab 을 눌러 링이 보이는지 · 덮개에서 포커스가 갇히는지 | 14 |

- 목(mock) 데이터를 **행이 그려질 만큼** 채우고 본다. 빈 목록으로는 레이아웃 버그가 안 보인다
  (연구실 자료·후기 탭에서 두 번 놓쳤다 — `docs/notes/admin.md`).
- **⚠️ 규칙을 넣은 뒤 반드시 세어 본다 — '썼다'와 '먹는다'는 다르다.**
  admin 의 16px 규칙은 2026-08-01 에 넣고 문서에도 적었지만, 입력칸 24개의 **인라인
  `style="font-size:14px"`** 에 져서 **한 번도 적용된 적이 없었다.** 인라인 스타일·더 구체적인
  선택자·`!important` 셋 중 하나에 막히면 규칙은 있어도 없는 것이다.

  사파리 문제가 실제로 있다(하단바 잘림·라벨 겹침). 재현이 안 되면 원인을 좇는 대신
  **그 구조가 실패할 수 없게 바꾼다**(한 줄에 몰아넣은 flex → 줄 분리).
