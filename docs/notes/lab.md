## 자료 파일 — 회원 전용·비밀번호·워터마크 (2026-08-01 설계·구현 시작)

오너 요구: "회원만 다운로드, 특정 자료는 비밀번호, 자료가 여기저기 퍼지는 걸 방지." 오너 확정: **자료마다 다운로드/열람 전용을 섞고, 받는 파일에 받은 사람을 찍는다.**

**설계의 핵심은 파일을 공개 버킷에 두지 않는 것이다.** 공개 버킷은 주소만 알면 로그인 여부와 무관하게 받아지므로 화면의 로그인 검사가 무의미해진다. 그래서:

- 버킷 `lab-files` 는 **비공개**. `storage.objects` 정책도 만들지 않는다(= service_role 만 접근).
- **브라우저는 파일 경로를 모른다** — 목록 RPC `lab_resource_list()` 가 `storage_path`·`password_hash` 를 반환하지 않는다. 목록 자체는 비회원도 본다(원장 화면 문구와 일치).
- 파일로 가는 유일한 문은 **`lab-file` Edge Function** 이 발급하는 **60초 서명 URL**.
- `lab_resources` 본문에는 **RLS 정책을 하나도 만들지 않는다**(비밀번호 해시·경로가 그 안에 있다). 정책을 추가하지 말 것.
- **비밀번호 대조는 `lab_check_password()` — service_role 전용 grant.** 회원에게 주면 브라우저에서 맞을 때까지 시도할 수 있다. 연속 실패 5회면 10분 잠금(`lab_downloads.kind='fail'` 로 센다).
- **워터마크는 PDF 만.** pdf-lib 기본 폰트가 한글을 못 그려 이메일·회원 id 앞 8자·날짜만 ASCII 로 찍는다(한글 이름은 폰트 임베드가 필요 — 2단계). 원본은 건드리지 않고 `wm/<uid>/<resid>.pdf` 사본을 만들어 그 사본을 내준다. 사본 생성이 실패하면 원본을 내준다(열람을 막지 않는다).
- **열람 전용(`delivery='view'`)도 완벽한 차단은 아니다.** 브라우저가 파일을 받아야 보여주므로 저장 자체를 원천 차단할 수는 없다 — 워터마크가 실질적 억제 장치다. 이 한계를 오너에게 숨기지 말 것.
- 모든 열람·다운로드·비밀번호 실패는 `lab_downloads` 에 남는다(유출 추적 근거).
- 숫자 연결: `lab_shelf_counts()` 가 붙으면 허브 목차 5줄·원장 현황 스트립이 실제값이 된다 — 그때 예시 foot-note 를 걷어낸다.

**⚠️ 관리자는 service_role 이 아니다.** admin.html 의 관리자도 그냥 로그인 사용자라, 정책을 하나도 두지 않은 첫 마이그레이션만으로는 **자료를 올릴 수조차 없다.** `20260801130000` 이 `is_admin()` 에게만 문을 연다(자료 전권 · 열람 기록 조회 · `lab-files` 버킷 · `lab_set_password` 실행). **`authenticated` 전체에 여는 정책을 만들지 말 것** — `password_hash`·`storage_path` 가 노출된다. `lab_check_password` 는 관리자에게도 주지 않는다(브라우저에서 부를 수 있으면 시도 제한이 무의미).

### 영상관 = 유튜브 링크 (2026-08-01 오너 확인 "주로 유튜브 링크를 넣을거거든")

첫 설계는 파일 업로드 전용(`storage_path` NOT NULL)이라 링크를 못 받았다. `20260801140000` 이 `external_url`·`duration_sec` 을 더하고 `storage_path` 를 nullable 로 바꿨다(둘 중 하나는 있어야 한다는 check).

- **썸네일은 유튜브에서 바로 가져온다 = 목록이 영상 id 를 내준다**(2026-08-01 오너 확정 — "썸네일이 와줘야하는데 파일명만 달랑 올라가네? 이러면 아무도 안보지. **영상 아이디는 노출해도 되니까** 유튜브 썸네일을 그대로 가져오는 방향으로"). `lab_resource_list` 가 `external_url` 에서 11자 id 를 뽑아 `video_id` 로 반환하고, 화면이 `i.ytimg.com/vi/<id>/maxresdefault.jpg` 를 조립한다(없으면 `hqdefault` 로 폴백 — **error 이벤트는 버블링하지 않아 캡처 단계로 받는다**).
  - **⚠️ 이 결정의 대가**: 영상 id 가 목록에 실리므로 **일부공개(미등록) 영상도 id 를 아는 사람은 볼 수 있다**(회원 여부 무관). 영상에 남는 통제는 '누가 눌러 봤는지' 기록뿐이다. **정말 새면 안 되는 내용은 유튜브가 아니라 파일로 올린다**(비공개 버킷 + 워터마크).
  - **링크 전체(`external_url`)는 여전히 목록에 안 나간다** — 재생은 `lab-file` 을 거쳐야 열람 기록이 남는다. 목록에 나가는 건 썸네일용 id 뿐.
  - 잠깐 검토했던 **'썸네일을 우리 버킷(`lab-thumbs`)에 복사'** 안은 폐기(단계가 많고 복사가 실패하면 썸네일이 아예 없다). 이 프로젝트엔 만든 적 없어 치울 잔재도 없다.

- `lab-file`(`2026-08-01f`)이 파일 여럿이면 **`pick_file` + 목록**을 돌려주고, 화면이 바텀시트로 고르게 한 뒤 `fileId` 로 다시 부른다. ⚠️ **`fileId` 는 그 자료의 파일 목록 안에서만 찾는다**(남의 자료 파일 id 를 넣어도 안 걸리게). ⚠️ 경로는 목록에 절대 싣지 않고, `label` 이 없으면 '파일 1·2'로 부른다(저장 파일명은 난수라 보여줄 게 못 된다).

- admin: 고른 파일 전부가 한 자료에 붙는다(제목을 비우면 첫 파일명). **수정에서 파일을 고르면 기존 파일에 '더해진다'**(교체 아님), 붙어 있는 파일은 목록에서 개별 삭제. 자료를 여러 건으로 나누려면 한 번씩 올린다.
- 목록 카드는 파일이 2개 이상이면 `파일 3개`로 표시한다.

### ⚠️ 파일을 `window.open` 으로 열지 말 것 (2026-08-01 실제 제보)

학생 제보: **"인스타보고 무료배포 읽어보려니 이렇게 팝업 뜨고 안들어가는데 해결방법이 있을까요?"** — 서버 응답은 성공해 '받으신 분 정보가 표시된 파일이에요' 토스트까지 떴는데 파일 창만 안 열렸다.

원인은 **인앱 브라우저(인스타·카톡)의 팝업 차단**이다. `lab-file` 호출이 끝난 뒤 여는 구조라 사용자 제스처가 끊겨 차단이 더 잘 걸린다. 인스타 프로필 링크로 유입되는 무료 배포가 통째로 막히는 자리다.

- **받기(`mode:'download'`)는 `location.href` 로 연다** — 서명 URL 이 `Content-Disposition: attachment` 라 화면은 그대로 있고 받기만 시작된다.
- **열람·영상은 새 창을 시도하되 `null` 이면 같은 탭으로 넘어간다**(`openUrl()`).
- 받기일 때 '파일 받기를 시작했어요' 토스트를 띄운다 — 화면이 안 바뀌면 실패한 줄 안다.
- 값의 기준선·함정 전체는 `docs/superpowers/specs/2026-08-01-lab-paid-materials-design.md`.

## 상세 페이지 — lab-shelf.html (①안 서류철, 2026-08-01 오너 확정 "1안으로 진행")

**한 파일이 서가 5종을 다 그린다**: `lab-shelf.html?shelf=airline|video|question|report|calendar`. 특강 `lecture.html?id=` 와 같은 사상 — 페이지를 5개로 나누면 머리 모양 한 번 고칠 때 5번 고쳐야 한다. **서가를 늘릴 땐 파일 안 `SHELVES` 표에 한 줄만 더한다**(idx·name·desc·noun·unit·airline·type).

- 화면: 다크 머리(허브 연구실 카드와 같은 면) + 픽커 + 종이 목록. 원장 카드 5장이 각각 여기로 온다.
- **필터는 픽커+바텀시트**(news.html 과 같은 규칙 — 칩 나열 회귀 금지). 픽커 옵션은 **데이터에 실제로 있는 값만**(눌러도 0건인 선택지를 만들지 않는다). 옵션이 1개뿐이면 픽커 자체를 감춘다.
- **목록은 비회원도 본다**(원장 문구와 일치). 로그인 요구는 '열람 시점'에만 — `need_login` 코드가 오면 `login.html?returnTo=` 로 보낸다.
- 비밀번호 자료는 같은 시트 뼈대를 재사용해 입력받는다(`need_password`→시트, `bad_password`→시트 안 오류, `locked`→버튼 잠금).
- **숫자는 `lab_shelf_counts()` 가 채운다** — 허브 목차 5줄·원장 스트립·상세 머리 전부. 자료 0건인 서가는 숫자 대신 **'준비 중'**(0 을 내걸지 않는다). 예시값·예시 foot-note 는 이때 전부 걷어냈다.

### 링크 미리보기 — 서가별 주소 `lab-<key>.html` (2026-08-01)

오너 요구: 카톡·DM 에 서가 링크를 보내면 **서가별 제목·사진**이 떠야 한다. 그런데 크롤러는 JS 를 안 돌리므로 `?shelf=` 로는 다섯 서가가 전부 같은 미리보기가 된다(주소 뒤 값을 읽으려면 JS 가 필요하다).

- 그래서 서가마다 **og 만 든 얇은 파일 `lab-airline|video|question|report|calendar.html`** 을 뒀다. 본문은 링크 한 줄뿐이고 `location.replace('lab-shelf.html?shelf=…')` 로 상세로 넘긴다. **화면은 여전히 `lab-shelf.html` 한 파일이 그린다 — 위 '한 파일' 원칙은 그대로다.**
- `lab-shelf.html` 은 서가를 정한 뒤 `history.replaceState` 로 주소를 `lab-<key>.html` 로 바꾼다. **주소창을 그대로 복사해 붙여넣어도 미리보기가 살아 있게 하려는 것**(오너는 주소창에서 복사한다). 원장 카드 링크는 `?shelf=` 그대로 둔다 — 스텁을 거치면 왕복이 하나 늘 뿐이다.
- ⚠️ 스텁을 **하위 폴더로 옮기지 말 것**(`/lab/airline/` 등). replaceState 로 경로 깊이가 바뀌면 페이지 안 상대 링크가 전부 어긋난다. 지금은 루트로 깊이가 같아 안전하다.
- ⚠️ **meta refresh 를 쓰지 않는다** — 일부 크롤러가 따라가 `lab-shelf.html` 의 공용 og 를 읽어 버린다. 이동은 JS 로만.
- 미리보기 이미지 `images/og/lab-<key>.png`(1200×630) 는 사이트 팔레트 그대로(웜 페이퍼 + 네이비 + MONC 워드마크 + 색인·서가명·설명). 생성 스크립트는 남기지 않았다 — 문구가 바뀌면 `SHELVES` 표를 보고 다시 만든다.
- **서가를 늘리면 세 곳이 한 벌이다**: `SHELVES` 표 한 줄 · 스텁 파일 하나 · og 이미지 하나.
