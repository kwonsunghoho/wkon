## 01 서가 이름 = '취업 자료실' (2026-08-09 오너 지시)

## 서가 합치기 — 자료실 + 기출문제 (2026-08-03 오너 확정·구현)

오너: **"항공사 자료실이랑 기출문제가 따로있을 이유가없어보여서. 둘이 합치되 효율적으로 구분할 수 있는 장치를 만들면 좋아보이는데"** → 3안 목업 비교 후 **"a안으로 가면 되겠다"**(갈래 단추 한 줄).

두 서가는 이미 같은 표에 `shelf` 값만 다르게 들어가 있었고 고르는 축(항공사·유형)도 같았다. 그래서 **화면만 합치고 DB 는 그대로 뒀다.**

- **DB·마이그레이션 변경 0건.** `lab_resources.shelf` 는 여전히 `airline`·`question` 두 값이다. admin 도 그대로 두 서가로 등록·조회한다(칩·열람 이력 그대로). ⚠️ **표를 합치거나 shelf 값을 갱신하지 말 것** — 되돌릴 수 없게 된다.
- **상세(`lab-shelf.html`)**: `SHELVES.airline` 이 `shelves: ['airline','question']` 과 `branches`(전체·자료·기출)를 갖는다. 목록은 **RPC 를 shelf 마다 한 번씩 부른 뒤 `published_at` 내림차순으로 다시 정렬**한다(RPC 는 서가별로만 정렬해 준다). ⚠️ **하나라도 실패하면 부분으로 그리지 않는다** — 반쪽 목록은 '기출이 없다'로 읽힌다.
- **갈래 값은 DB shelf 값 그대로**(`all`·`airline`·`question`) — 변환표를 두지 않아야 어긋날 자리가 없다. 줄의 갈래는 `r.shelf` 로 본다.
- **줄 구분 두 가지**: 기출은 **아이콘 면을 `--accent-dark` 로 채우고**(말풍선 물음표), **'전체'일 때만** `기출` 태그를 단다(기출만 보고 있으면 반복하지 않는다 — admin 열람 이력과 같은 규칙).
- **유형 픽커는 갈래를 따른다** — 이름도(`자료 유형`/`질문 유형`/전체일 땐 `유형`) 옵션 목록도 갈린다. 갈래를 바꾸면 **유형은 반드시 푼다**(안 풀면 0건 화면), 항공사는 새 갈래에도 그 값이 있으면 지킨다.
- ⚠️ **한쪽 갈래가 0건이면 갈래 줄을 감추고 '전체'로 되돌린다.** 빈 갈래에 갇혀 '자료가 없다'로 보이는 화면을 만들지 않는다(픽커의 '0건 선택지 금지'와 같은 규칙).
- **건수는 화면에서 더한다** — 허브 목차·원장 카드의 취업 자료실 숫자는 `lab_shelf_counts()` 의 두 값 합계, '최신 1건'도 둘 중 더 최신인 것. **단위는 `건` 으로 통일**(기출문제가 쓰던 `개` 는 없어졌다).
- **색인 재배열**: 01 자료실 · 02 영상관 · 03 현장 리포트 · 04 채용 캘린더. og 사진 `lab-report.png`·`lab-calendar.png` 의 숫자도 같이 고쳤다(원본 픽셀을 두고 머리말 줄만 다시 그렸다 — 생성 스크립트가 없어서 로고·괘선을 새로 굽지 않았다).
- **`lab-question.html` 스텁은 남긴다** — 카톡·DM 에 뿌린 링크가 그 주소다. `?shelf=airline&kind=question` 으로 보내 **기출 갈래로 열리고**, 구 주소 `?shelf=question` 도 같은 자리로 해석한다. 상세는 갈래에 따라 주소를 `lab-airline.html`/`lab-question.html` 로 바꾼다(주소창을 복사해 보내도 미리보기가 그 갈래를 말한다).

### 합친 뒤 남아 있던 옛 5서가 두 자리 (2026-08-03 오너 "왜 아직도 안 고쳐지냐")

오너가 **"기출문제가 따로 있던 옛 연구실이 순간순간 깜빡인다"**(PC 크롬)고 지적. 확인해 보니 서버가 주는 파일은 최신이었고, 원인은 둘이었다.

- **bfcache** — 뒤로/앞으로 가면 크롬은 **떠날 때 그리던 화면을 그대로 되살린다**(파일을 새로 받지 않는다). 배포 전에 열어 둔 탭·기록이 있으면 옛 목차 5줄·옛 서가 카드 5장이 그대로 뜬다. → `lab.html`·`lab-archive.html` 에 `pageshow` + `e.persisted` → `location.reload()` 를 달았다(answers·mypage·login 과 같은 규칙). **입력값이 없는 화면이라 통째로 다시 받아도 잃을 게 없다.** ⚠️ `lab-shelf.html` 은 **일부러 제외** — 그 `pageshow` 는 결제(포트원)에서 돌아왔을 때 버튼을 되돌리는 자리라, 통째 reload 로 바꾸면 결제 복귀 흐름을 건드린다.
- **`nav.js` 연구실 드롭다운 설명** — `자료실·영상관·기출문제·채용 캘린더` 로 남아 있었다(합치기 커밋이 nav 를 안 건드렸다). 메뉴를 열 때마다 옛 구성이 보이던 자리라 `자료실·영상관·현장 리포트·채용 캘린더` 로 고쳤다. **서가를 늘리면 이 줄도 같이 고친다.**
- ⚠️ **남는 한 가지 — GitHub Pages 는 HTML 에 `cache-control: max-age=600` 을 강제한다.** 푸시 후 10분 동안은 브라우저가 서버에 묻지도 않고 제 캐시의 옛 HTML 을 쓴다. 레포에서 손댈 수 없으니 **배포 직후 확인은 강력 새로고침(Ctrl/Cmd+Shift+R)** 으로 한다. 이걸 없애겠다고 모든 페이지에 no-cache 를 걸거나 뒤로가기마다 reload 를 걸지 말 것 — 전송량·되돌아오기 속도를 상시로 깎는 거래다.

오너: **"간결하게 연구실 / 연구진 이렇게 두개 카드만 딱 나와야지 그게 허브 아니냐고."**

- **허브 카드 표면은 ②안 '콘솔'(같은 날 확정 — "뭔가 밋밋하지않냐? 연구실인데" → 3안 목업 `outputs/lab-hub-flavor-mockup.html` 중 "2안이 좋어보인다")**: 연구실 카드 = 다크 네이비 콘솔(#1E4079→#142C52) + 서가 목차 4줄(점선 리더, lab-archive 와 같은 순서·수치) + '연구 진행 중' 라이브 점 + 흰 알약 화살표(다크 위 CTA 규칙). 연구진 카드 = 레터프레스 종이 + **얼굴 6개**(`researchers-data.js` 에서 JS 생성 — 인원수도 배열 길이로 갱신, 페이지에 복사 금지). 기각된 ①색인(종이만)·③연구노트(모눈+탭)는 목업 파일에 기록.
- **허브 제목은 '몬크 연구실 & 연구진'**(2026-08-02 오너 지시). `<title>`·og·twitter 제목도 같이 바꿨다 — 카드 두 장이 곧 이 페이지의 내용이라 제목이 둘을 다 말한다.
- **넓은 화면(≥760px)은 좌우 2단, 폭은 6:4**(2026-08-02 오너 "위아래 보다는 좌우로 보여지게하면 어때?" → 5안 비교 후 **"C안으로 가자"**). 히어로 = 제목(왼쪽) + 설명(오른쪽, 첫 줄 베이스라인 맞춤), 카드 두 장 = 나란히 하되 **연구실이 넓다**. `.wrap` 은 이때만 560→920px. 기각안 4종(A 균등 2단 · B 히어로는 위아래 · D 카드 안이 좌우 · E 페이지 전체 좌우)은 `outputs/lab-hub-layout-mockup.html` 에 기록.

## 자료 파일 — 회원 전용·비밀번호·워터마크 (2026-08-01 설계·구현 시작)

오너 요구: "회원만 다운로드, 특정 자료는 비밀번호, 자료가 여기저기 퍼지는 걸 방지." 오너 확정: **자료마다 다운로드/열람 전용을 섞고, 받는 파일에 받은 사람을 찍는다.**

**설계의 핵심은 파일을 공개 버킷에 두지 않는 것이다.** 공개 버킷은 주소만 알면 로그인 여부와 무관하게 받아지므로 화면의 로그인 검사가 무의미해진다. 그래서:

- 버킷 `lab-files` 는 **비공개**. `storage.objects` 정책도 만들지 않는다(= service_role 만 접근).
- **브라우저는 파일 경로를 모른다** — 목록 RPC `lab_resource_list()` 가 `storage_path`·`password_hash` 를 반환하지 않는다. 목록 자체는 비회원도 본다(원장 화면 문구와 일치).
- 파일로 가는 유일한 문은 **`lab-file` Edge Function** 이 발급하는 **60초 서명 URL**.
- `lab_resources` 본문에는 **RLS 정책을 하나도 만들지 않는다**(비밀번호 해시·경로가 그 안에 있다). 정책을 추가하지 말 것.
- **비밀번호 대조는 `lab_check_password()` — service_role 전용 grant.** 회원에게 주면 브라우저에서 맞을 때까지 시도할 수 있다. 연속 실패 5회면 10분 잠금(`lab_downloads.kind='fail'` 로 센다).
- **워터마크는 PDF 만.** pdf-lib 기본 폰트가 한글을 못 그려 이메일·회원 id 앞 8자·날짜만 ASCII 로 찍는다(한글 이름은 폰트 임베드가 필요 — 2단계). 원본은 건드리지 않고 `wm/<uid>/<resid>.pdf` 사본을 만들어 그 사본을 내준다. 사본 생성이 실패하면 원본을 내준다(열람을 막지 않는다).
- **열람 전용(`delivery='view'`)도 완벽한 차단은 아니다.** 브라우저가 파일을 받아야 보여주므로 저장 자체를 원천 차단할 수는 없다 — 워터마크가 실질적 억제 장치다. 이 한계를 오너에게 숨기지 말 것.
- 모든 열람·다운로드·비밀번호 실패는 `lab_downloads` 에 남는다(유출 추적 근거).
- 숫자 연결: `lab_shelf_counts()` 가 허브 목차 4줄·원장 현황 스트립을 채운다(2026-08-01 연결 완료 — 예시 foot-note 는 그때 걷어냈다).

**⚠️ 관리자는 service_role 이 아니다.** admin.html 의 관리자도 그냥 로그인 사용자라, 정책을 하나도 두지 않은 첫 마이그레이션만으로는 **자료를 올릴 수조차 없다.** `20260801130000` 이 `is_admin()` 에게만 문을 연다(자료 전권 · 열람 기록 조회 · `lab-files` 버킷 · `lab_set_password` 실행). **`authenticated` 전체에 여는 정책을 만들지 말 것** — `password_hash`·`storage_path` 가 노출된다. `lab_check_password` 는 관리자에게도 주지 않는다(브라우저에서 부를 수 있으면 시도 제한이 무의미).

원인은 **인앱 브라우저(인스타·카톡)의 팝업 차단**이다. `lab-file` 호출이 끝난 뒤 여는 구조라 사용자 제스처가 끊겨 차단이 더 잘 걸린다. 인스타 프로필 링크로 유입되는 무료 배포가 통째로 막히는 자리다.

- **받기(`mode:'download'`)는 `location.href` 로 연다** — 서명 URL 이 `Content-Disposition: attachment` 라 화면은 그대로 있고 받기만 시작된다.
- **열람·영상은 새 창을 시도하되 `null` 이면 같은 탭으로 넘어간다**(`openUrl()`).
- 받기일 때 '파일 받기를 시작했어요' 토스트를 띄운다 — 화면이 안 바뀌면 실패한 줄 안다.
- 값의 기준선·함정 전체는 `docs/superpowers/specs/2026-08-01-lab-paid-materials-design.md`.

## 상세 페이지 — lab-shelf.html (①안 서류철, 2026-08-01 오너 확정 "1안으로 진행")

**한 파일이 서가 4종을 다 그린다**: `lab-shelf.html?shelf=airline|video|report|calendar`(기출은 자료실 안의 갈래 — 위 '서가 합치기' 절). 특강 `lecture.html?id=` 와 같은 사상 — 페이지를 나누면 머리 모양 한 번 고칠 때 그 수만큼 고쳐야 한다. **서가를 늘릴 땐 파일 안 `SHELVES` 표에 한 줄만 더한다**(idx·name·desc·noun·unit·airline·type).

- 화면: 다크 머리(허브 연구실 카드와 같은 면) + 갈래(합친 서가만) + 픽커 + 종이 목록. 원장 카드 4장이 각각 여기로 온다.
- **필터는 픽커+바텀시트**(news.html 과 같은 규칙 — 칩 나열 회귀 금지). 픽커 옵션은 **데이터에 실제로 있는 값만**(눌러도 0건인 선택지를 만들지 않는다). 옵션이 1개뿐이면 픽커 자체를 감춘다.
- **목록은 비회원도 본다**(원장 문구와 일치). 로그인 요구는 '열람 시점'에만 — `need_login` 코드가 오면 `login.html?returnTo=` 로 보낸다.
- 비밀번호 자료는 같은 시트 뼈대를 재사용해 입력받는다(`need_password`→시트, `bad_password`→시트 안 오류, `locked`→버튼 잠금).
- **숫자는 `lab_shelf_counts()` 가 채운다** — 허브 목차 4줄·원장 스트립·상세 머리 전부. 자료 0건인 서가는 숫자 대신 **'준비 중'**(0 을 내걸지 않는다). 예시값·예시 foot-note 는 이때 전부 걷어냈다.

### 링크 미리보기 — 서가별 주소 `lab-<key>.html` (2026-08-01)

- 미리보기 이미지 `images/og/lab-<key>.png`(1200×630) 는 **구 웜 페이퍼 팔레트로 만들어 둔 것이라 2026-08-05 쿨 화이트 전환과 어긋나 있다**(카톡·DM 미리보기라 사이트에서는 안 보인다 — 다시 만들 때 순백 배경으로). 구성은 배경 + 네이비 + MONC 워드마크 + 색인·서가명·설명). 생성 스크립트는 남기지 않았다 — 문구가 바뀌면 `SHELVES` 표를 보고 다시 만든다.

## 04 채용 캘린더 — 공채 회차 (2026-08-04 오너 확정 "무료로 가고")

**이 서가만 `lab_resources`(파일)를 쓰지 않는다.** 채용 타임라인은 파일이 아니라 날짜라서, PDF 로 올리면 아래 계산이 전부 불가능해지고 화면이 사진 한 장이 된다. 전용 표 `recruit_rounds` 를 쓴다(migration `20260804120000_recruit_rounds.sql`).

### 항공사가 여러 곳 쌓이면 — 픽커가 갈래를 대신한다 (2026-08-04 오너 질문)

**갈래 줄(`shSeg`)을 새로 만들지 않는다.** 항공사 픽커가 이미 그 일을 한다 — 자료에 실제로 있는 회사만 옵션이 되고(`buildOpts`), **두 곳 이상일 때 자동으로 나타난다**(`optAir.length > 1`). 대한항공 하나뿐인 지금 픽커가 안 보이는 것이 정상이다.

- **'전체'는 회사를 섞어 최신순**으로 세운다. 카드마다 회사 이름이 붙어 있어 섞여도 읽힌다 — '요즘 어디가 뽑았나'를 보는 화면이다.
- **패턴 띠는 '전체'에서 사라진다.** 전형 수가 다른 회사끼리 평균을 내면 뜻을 잃기 때문이다(위 규칙). 회사를 고르면 그 회사 것으로 다시 나온다.
- 6회차(대한항공 3 · 진에어 2 · 제주항공 1)를 넣어 375·320px 실측(2026-08-04): 픽커 자동 노출, '전체' 6장 최신순, 진에어 선택 시 2장 + 진에어 패턴(5일 / 8일 / 2개월 · 간격 211일), 1회차뿐인 제주항공은 **계산되는 칸 하나만**(15일) 그리고 '연속' 주장 없음. 가로 넘침 0.
- 이 검증에 쓴 하네스는 `lab-shelf.html` 의 Supabase 호출 한 줄만 가짜 배열로 바꾼 사본이다(스크래치패드 전용 — 레포에 넣지 않는다).
- ⚠️ 이때 드러난 것 둘을 같이 고쳤다: **회사 이름 뒤 조사**(`진에어은` → `josa()` 로 은/는), **'최종 합격까지'가 '전체'와 같은 숫자면 안 쓴다**(최종 합격이 마지막 단계인 회차 — 입과가 뒤에 붙는 회차만 두 값이 갈린다).

- ⚠️ **이름·연락처를 묻지 않는다.** `challenge_waitlist` 와 다르다 — 저기는 연락이 목적이라 개인정보가 필요하지만 여기는 **일정만** 받는다. 로그인 상태면 `member_id` 만 붙는다(연구진이 되물을 용도, admin 만 읽는다). 화면에도 "이름·연락처 같은 개인정보는 적지 마세요"를 적어 뒀다.
- ⚠️ **넣기 전용 창구다.** RLS 는 insert 만 anon·authenticated 에 열고 select 는 관리자뿐이다. **제보를 학생 화면에 되읽어 보여주는 코드를 만들지 말 것** — 검수 전 주장이 화면에 뜨는 순간 사실이 된다(화면 문구 "연구진이 기록합니다"와 어긋난다).
- ⚠️ **`recruit_rounds` 에 자동 반영하지 않는다.** 제보는 '확인 전 주장', 회차는 '연구진이 확인한 기록'이다. admin 에서 읽고 손으로 고친다.
- **공개 INSERT 창구의 방어 3중**: DB check(본문 5~1000자·상태 고정) · `with check (status='new' and handled_at is null)`(처리 완료로 위장해 숨는 것 차단) · 화면의 미끼 칸(봇). 브라우저 쪽 한 화면 5건 제한은 완화책일 뿐 방어가 아니다.
