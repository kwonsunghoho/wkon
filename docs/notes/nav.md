## '지금 여기' 표시가 후기 목차에서 두 줄에 붙었다 (2026-08-05 오너 신고)

- **증상**: `reviews-list.html?kind=consult` (상담 후기)를 보고 있는데 목차에서 **챌린지 후기와 상담 후기 둘 다** 밑줄이 그려졌다(오너 *"상단 네비에 줄이 두개가 되네? 상담후기를 눌렀는데 위에가 챌린지후기가 왜 줄이 생기니?"*). 데스크톱 목차·모바일 아코디언 양쪽 다.
- **원인**: `nav.js` 의 `curFile()` 이 `href.split(/[?#]/)[0]` 로 **파일명만 비교**했다. 후기 두 갈래는 파일이 같고 `?kind=` 만 다르니(`reviews-list.html?kind=challenge` · `?kind=consult`) 둘 다 현재 페이지로 판정됐다. 2026-08-02 후기 드롭다운을 만들 때부터 있던 결함이다 — 그전까지 하위 항목은 전부 파일이 서로 달랐다.
- **고친 것**: `curFile()` 이 항목의 쿼리까지 본다. 항목이 든 파라미터는 주소와 값이 같아야 하고, **주소에 값이 없거나 모르는 값이면 그 화면의 기본 갈래로 본다**(`?kind=` 없이 들어오면 `reviews-list.html` 은 challenge 를 그린다 — 그 파일 `KIND` 폴백과 짝). 기본값 표는 `nav.js` 의 `QUERY_DEFAULT`, 메뉴에 실린 값 목록은 같은 곳 `QUERY_VALUES`(SUB 배열에서 자동 수집).
- **⚠️ `?`로 갈래가 갈리는 하위 항목을 새로 넣으면 `QUERY_DEFAULT` 에도 한 줄 넣는다** — 빠뜨리면 그 화면에서 현재 표시가 아무 줄에도 안 붙는다.
- **다른 자리에도 있나 — 없다.** 메뉴 항목 15개(승준노트 6·챌린지 4·연구실 2·후기 3)를 훑어 **같은 파일이 두 번 쓰인 곳은 `reviews-list.html` 뿐**이다(2026-08-05 실측). 상단 항목 표시(`SECTION_OF`)는 파일→섹션 1:1 이라 애초에 두 곳에 붙지 않는다. 서가(`lab-shelf.html?shelf=`)는 메뉴에 없다 — 목차에 실으면 이 결함이 바로 재발할 자리이므로 그때 `QUERY_DEFAULT` 를 같이 채운다.
- 실측(2026-08-05): `?kind=consult` → 상담 후기 한 줄만(구 동작은 두 줄) / `?kind=challenge`·**파라미터 없음**·`?kind=zzz`(모르는 값) → 챌린지 후기 한 줄 / `?kind=consult&foo=1` → 상담 후기 한 줄 / 1280px 목차에서 밑줄 폭 = 설명글 폭 134px(표시 없는 줄은 226px 전체 폭 유지) / 375px 아코디언도 상담 후기만 표시 / 콘솔 에러 0.

## 769~819px 전용 블록 신설 — '넘침 0' 기준이 어긋나 있었다 (2026-08-04 재측정 · **2026-08-06 폐기**)

> ⚠️ 이 절의 블록은 2026-08-06 6항목 분리로 **삭제됐다**(그 구간이 통째로 햄버거가 됐다 — 맨 위 절).
> 스크롤바·측정 방법 교훈은 그대로 유효해 기록으로 남긴다.

- **결론**: 769px 구간은 이미 **모자란 상태**였고, 스크롤바가 있는 환경에서는 **'신청하기'가 11.5px 잘려** 있었다. `nav.css` 에 `769~819px` 전용 블록을 새로 넣어 고쳤다. 아래 두 '실측 769px 넘침 0' 기록(2026-07-31 · 2026-08-03)은 **폐기 — 현행은 이 절이다.**
- **언제 어긋났나.** 2026-07-31 기록은 맞는 값이었다. 그 뒤 **2026-08-02 '후기'가 드롭다운으로 승격되며 화살표만큼 +21px** 늘었는데, 그날 확인은 **1000px 만** 했다(1059 로 상한을 올린 작업). 769px 하한은 다시 안 쟀고, 2026-08-03 확인은 아래 '어떻게 재야 하나'의 잘못된 방법으로 통과했다.
- **필요 폭 계산**(구 값 column-gap 28 · 메뉴 gap 16): 로고 87.6 + 28 + 메뉴 352.5 + 28 + 버튼 249.4 + 좌우 여백 40 = **785.5px**. 769px 에서 쓸 수 있는 자리는 729px 이라 **오른쪽 여백 20px 을 16.5px 잠식**한다(왼쪽 20 · 오른쪽 3.5 로 어긋난다).
- **⚠️⚠️ 진짜 문제는 스크롤바다 — 미디어쿼리와 레이아웃이 서로 다른 폭을 본다.** 크로미움은 미디어쿼리를 **스크롤바 포함** 폭으로 재고, 레이아웃은 **스크롤바를 뺀** 폭으로 잡는다. 실측(2026-08-04 · terms.html · 창 769px): `innerWidth 769`(→ `min-width:769px` 켜짐) 인데 `clientWidth 754`(스크롤바 15px). 그 결과 785.5px 짜리 바가 754px 자리에 들어가 **`.nav-right` 오른쪽 끝 765.5 · 오른쪽 여백 −11.5px**, `.nav-inner` scrollWidth 766 > clientWidth 754. **nav 는 `position:fixed` 라 가로 스크롤도 안 생긴다 — 그냥 잘린 채로 보인다.** 2026-07-31 기록의 '769px 인데 clientWidth 754' 도 같은 현상이다(그때는 알고 쓴 값이 아니었다).
- **⚠️ 그래서 어떻게 재야 하나.** ① `document.documentElement.scrollWidth` 로 '가로 넘침 0' 을 확인하는 방법은 **이 자리에서 무효**다 — fixed 요소의 넘침은 문서 스크롤에 안 잡힌다(2026-08-03 확인이 이걸로 통과했다). **`.nav-inner` 의 `scrollWidth` vs `clientWidth`, 그리고 오른쪽 여백**을 본다. ② **스크롤바가 있는 페이지에서 잰다**(terms.html 등). 개발 브라우저가 오버레이 스크롤바면 `clientWidth === innerWidth` 라 이 결함이 아예 안 보인다. ③ 목표 폭은 769 가 아니라 **752px**(창 769 − 스크롤바 17).

## 드롭다운 목차의 '지금 여기' 선은 자기 줄에 붙인다 (2026-08-04 오너 지적)

- **증상**: 목차를 열면 현재 페이지 줄의 밑줄이 **다음 줄 제목 코앞**에 떠서, 아래 항목의 선으로 읽혔다(오너 *"선이 너무 아래쪽이라 밑 카테고리로 오해할 수 있음"*).
- **원인**: 하위 링크도 `.nav-links` 안의 `<a>` 라 **상단 항목용 규칙을 그대로 물려받았다.** 상단 항목에서 `bottom:-7px` 는 글자 바로 밑이지만, 하위 링크는 `display:block` + 패딩 12/14 라 같은 값이 **항목 상자 바깥 7px** = 자기 글자에서 19px, 다음 제목에서 5px 인 자리가 된다(실측). 거리가 소속을 뒤집었다.
- **고친 것 둘**: ① 상단 항목 규칙을 `#navbar .nav-links > li > a[aria-current]` 로 **직계 자식에만** 묶었다 ② 하위 링크는 설명글(`span`)에 `width:fit-content` + `::after(bottom:-3px)` 로 **글자 폭·글자 밑 3px** 에 긋는다. 제목(`b`)도 `--accent-ink` — `a b` 가 `--text` 를 직접 칠해서 `a` 쪽 색 규칙이 안 먹고 있었다(모바일 아코디언은 `b` 에 색이 없어 원래부터 네이비로 보였다 — 그쪽과 짝을 맞춘 것).
- **⚠️ `display:inline-block` 으로 폭을 줄이지 말 것** — 줄 상자에 기준선 여백이 붙어 그 항목만 57 → 57.5px 로 부푼다(실측). 흐름을 안 건드리는 `width:fit-content` 를 쓴다.
- 실측(2026-08-04 · 1280px): 선이 제 글자에서 3px·다음 제목에서 19px(구 19px/5px 에서 뒤집힘) / 선 폭 = 설명글 폭(news 140px, lab-archive 217px, 항목 상자는 254px) / 목차 6줄 높이 전부 57px·다섯 항목 잉크 중심 33.00px·바 67px 그대로 / 상단 항목 밑줄 그대로(특강 29.2px, 드롭다운 버튼 58.4px·`right:21px`) · 가로 넘침 0 · 콘솔 에러 0.

### 같은 날 모바일(햄버거)에서도 같은 문제 — 오너 2차 지적

- **증상**: 펼친 메뉴에서 선이 층져 보였다(오너 *"모바일에서 저 선 위치가 삐뚤어졌잖아"*). 원인 셋이 겹쳤다. ① 구 표시가 `inset 3px` + `padding-left:12px` 이라 **현재 줄만 글자가 12px 안으로 밀려**, 상단 목록에서 '승준노트'만 들여쓰기된 것처럼 보였다 ② 하위 줄은 자기 테두리(레일 2px) **안쪽**에 막대가 그려져 상위 줄 막대와 **2px 어긋났다**(x=24 vs 26) ③ 그 막대가 회색 레일과 겹쳐 이중선이 됐다. 하위 줄 글자도 형제보다 2px 왼쪽(38 vs 40).

## 상위 메뉴 → 허브: 마우스 있으면 한 번, 없으면 두 번 (2026-08-02 오너 지시로 데스크톱만 변경)

**현행 규칙**(2026-08-02 오너 *"웹에서는 상단 네비게이션 두번 클릭해야 허브로 이동하잖아? 그거 한번 클릭으로 바꿔줘 … 근데 모바일은 두번 클릭이 좋지않을까? 모바일은 한번에 이동하면 하위탭이 의미가 없잖아"*):

| 기기 | 누름 | 목차는 어떻게 보나 |
|---|---|---|
| 마우스 있음(데스크톱) | **한 번 → 허브** | 마우스만 올리면 열린다(`:hover`) |
| 마우스 없는 ≥769px(터치 태블릿) | 두 번(열기 → 허브) | 첫 누름이 여는 유일한 길 |
| 모바일 ≤768px(햄버거 아코디언) | 두 번(펼치기 → 허브) | 첫 탭이 여는 유일한 길 |

- **가르는 기준은 폭이 아니라 `matchMedia('(hover: hover)')`** (`nav.js` 의 `hasMouse()`). 같은 1024px 라도 노트북과 아이패드는 필요한 동작이 다르다 — 미디어쿼리 폭으로 가르면 아이패드 가로에서 드롭다운을 열 방법이 사라진다. 클릭 시점에 물어봐 기기 상태 변화도 따라간다.
- **데스크톱에서 첫 클릭이 하던 일이 원래 없었다.** 목차는 `nav.css` 의 `:hover`/`:focus-within` 이 이미 열고 있어서, '여는 클릭'은 이미 보이는 것을 다시 여는 헛클릭이었다. 그래서 한 번으로 줄여도 잃는 게 없다.
- ⚠️ **`:hover` 상태 판정은 여전히 금지.** 구 규칙(2026-07-31 '어디서나 두 번')이 거부한 것은 *"지금 호버 중이면 이미 열린 걸로 친다"* 였다 — 호버가 남아 있는지가 애매해 첫 누름이 제멋대로 이동한다. 지금 보는 건 **상태가 아니라 기기 능력**이라 값이 흔들리지 않는다. 둘을 헷갈려 `:hover` 판정으로 되돌리지 말 것.
- ⚠️ **모바일 아코디언(`.mm-acc-btn`)은 건드리지 않았다.** 드롭다운을 고칠 때 같은 코드로 보이는 아코디언까지 한 번으로 바꾸면 하위 항목을 볼 방법이 사라진다(오너가 먼저 짚은 지점).
- **드롭다운 목록 맨 위의 '승준노트 한눈에'·'챌린지 한눈에'는 뺐다.** 오너 지시 *"그거 없애주고, 한번 누르면 목차열리고 두번누르면 그냥 한눈에 보이는 허브로 이동"*(2026-07-31). 허브 주소는 `nav.js` 의 `BRIEFING_HUB`·`CHALLENGE_HUB`·`LAB_HUB` 상수 → 상위 버튼의 `data-hub` 속성. **목록 첫 줄에 허브 링크를 다시 넣지 말 것**(그러라고 뺀 자리다).
- 실측(2026-08-02 · reviews.html 기준): 1280px 마우스 → 승준노트·챌린지·연구실 세 버튼 모두 **첫 클릭에 허브 도착**, 호버로 목차 열림 유지 / 1024px 터치(hover 없음) → 첫 클릭 이동 0건·목차 열림, 두 번째에 허브 / 375px → 첫 탭 펼침(패널 높이>0)·두 번째 탭에 허브. 키보드 포커스만으로 목차 열림 + Enter 로 허브 이동, 하위 항목 클릭은 그대로 하위 페이지, 콘솔 에러 0.
- **닫는 길**: 데스크톱은 바깥 클릭·Esc(기존 그대로), 모바일은 **다른 항목을 펼치면 먼저 것이 접힌다**(이번에 추가 — 버튼이 접기를 안 하게 됐으니 접는 길이 하나는 있어야 한다). 데스크톱은 원래부터 한 번에 하나만 열린다.
