## nav 공용화·활자·정렬(구 CLAUDE.md 랜딩 절에서 이관)

- **⚠️⚠️ nav 는 2026-07-30부터 전 페이지 공용 — `nav.js`(마크업 주입 + 동작) + `nav.css`(스타일) 두 파일이 유일한 원본이다. 페이지에 nav 마크업을 복사해 넣지 말 것.** 오너 지시 *"다른 페이지나 허브로 이동할 때 상단 네비게이션은 무조건 다 보이게"*. 쓰는 법은 `<link rel="stylesheet" href="nav.css">` + `<script src="nav.js" defer></script>` 두 줄뿐이고, 그 페이지의 기존 nav 마크업·CSS·햄버거 JS 는 지운다(둘이 겹친다). 메뉴 항목은 `nav.js` 상단의 `BRIEFING_SUB`/`CHALLENGE_SUB` 배열, 현재 위치 표시는 `SECTION_OF` 표에서 고친다. **구 '문구 하나 바꿀 때 index·researchers·challenges 세 파일을 맞춰라'는 규칙은 폐기** — 실제로 자주 어긋나서 공용화한 것이다. 안전장치로 `#navbar`가 이미 있으면 주입을 건너뛰고, `supabase-config.js`가 없는 페이지(terms·privacy)에서도 조용히 로그아웃 상태로 뜬다. **싣는 페이지 20곳**(index·challenges·상세 4종·apply·briefing·news·sojae·ai-killer·polish·answers·lecture·lectures·researchers·reviews·mypage·terms·privacy). ⚠️ **admin·login·onboarding 은 일부러 뺐다** — 관리·가입 흐름이라 사이트 메뉴가 붙으면 안 된다. ⚠️ **페이지 인라인 최상위 코드에서 `#navbar` 를 즉시 조회하지 말 것** — nav.js 가 defer 라 파싱 중엔 아직 없어 null 이 잡힌다(index 네비바 스크롤 그림자가 이걸로 동작하지 않았던 회귀 — 2026-07-30 lazy 캐싱 + `DOMContentLoaded` 초기 호출로 수정).
- **⚠️ nav 활자 크기(2026-07-30 2차 — 오너 "크기가 너무 크지 않니")**: 메뉴 21→**17px** · 신청하기 21→**16px** · 로그인 18→**15px** · 로고 30→**26px** · 드롭다운 18/15→16/14px · 메뉴 gap 26→24 · 두 버튼 사이 12→10 · 세로 여백 12→11px → **바 높이 73→66px**(모바일 57px 그대로). 자간 -0.015em 유지. ⚠️ **이 값들은 이제 `nav.css` 한 곳**에 있다(2026-07-30 공용화 전에는 index.css·researchers.html·challenges.html 셋을 맞춰야 했다).
  - **⚠️ 같은 날 1차로 14→21px 로 올렸다가(오너 "너무 작다") 되돌린 게 아니라 중간에 앉힌 것이다.** 21px 은 본문 17px 은 물론 소제목 `--fs-h3`(20px)보다 커서 **껍데기인 nav 가 내용보다 크게 읽혔다**(9대 원칙 6번 계층 구조 위배). 17px = 본문과 같은 급이고 12pt(16px) 하한도 넘는다. **14px 로 다시 내리지도, 20px 위로 올리지도 말 것.**
  - **⚠️⚠️ `.nav-inner`는 `auto auto 1fr` — 메뉴를 가운데 두려는 시도는 두 번 다 실패했으니 되돌리지 말 것.** ① `1fr auto 1fr`(화면 정중앙) → 메뉴가 버튼에 들러붙음 ② `auto 1fr auto`(로고·버튼 사이 정중앙, 양옆 150px 균등) → 그래도 "정렬 좀 잘 해봐라". 원인은 같다 — **왼쪽 로고(87px)와 오른쪽 버튼 덩어리(245px)의 무게가 3배 차이**라 무엇을 기준으로 가운데를 잡아도 메뉴가 어디에도 안 붙은 채 뜬다. 지금은 **로고+메뉴가 왼쪽 한 덩어리, 버튼이 오른쪽 끝, 빈 공간은 가운데 한 군데**(1440px에서 388px). 빈칸이 하나면 의도한 여백으로, 둘이면 정렬 실수로 읽힌다. `column-gap: 40px`가 로고↔메뉴 간격이다.
  - **⚠️ 메뉴 간격 24px + 행간 1**: 활자의 1.4배를 넘으면 글자 폭 30px인 '특강'·'후기'보다 틈이 넓어 메뉴가 다섯 덩어리로 흩어져 보인다. 행간을 안 잡으면 링크(body 1.7 상속, 높이 29px)와 드롭다운 버튼(21px)이 달라 **'승준노트'만 2px 처진다** — `.nav-links > li`를 flex로 세우고 링크·드롭다운 버튼에 `line-height: 1`을 준 이유이자 **세로 줄 맞춤의 핵심**이다. (2026-07-30 실측: 다섯 항목·로고·두 버튼의 잉크 중심이 전부 33.0~33.3px = 오차 0.3px.)
  - **⚠️ 로그인(15px)은 신청하기(16px)보다 한 단계 작다** — 같은 크기면 오른쪽 끝에 비슷한 알약 둘이 서서 어느 쪽이 본 행동인지 안 읽힌다(9대 원칙 6번 '채움 CTA는 하나').
  - ⚠️ **버튼에 `line-height: 1.15` + `min-height: 44px`** — `.btn`은 body의 `--lh-body`(1.7)를 물려받아 그대로 두면 활자만큼 버튼이 부푼다(21px 시절 실측: 버튼 60px, 바 85px). **높이는 활자가 아니라 min-height 로 잡는다** — 활자를 줄였다고 44px(9대 원칙 2번 터치 최소치) 아래로 내려가면 원칙 위반이다.
  - ⚠️ **좁은 데스크톱 구간은 769~820px 로 좁혔고, 여기서 활자는 안 건드린다** — 활자를 줄인 뒤 한 줄에 필요한 폭이 약 1,150 → **759px**로 내려갔다(실측). 구 1180px 상한을 그대로 뒀으면 줄일 이유가 없는 노트북에서도 더 작은 nav 가 떴다. 이 구간은 간격만 좁혀(column-gap 28 · 메뉴 gap 18) 한 줄을 유지한다. ⚠️ 이 블록은 여전히 `.nav-cta`·`.btn-login-outline` **뒤에** 둘 것(특이도가 같아 앞에 두면 기본 규칙이 이긴다).
  - ⚠️ **`.mypage-pill`·`.nav-avatar`의 좁은 화면 축소는 기본 선언 *뒤*의 별도 미디어 블록에 둔다** — 구 1180px 블록 안에 있던 두 줄은 뒤에 오는 기본 규칙에 밀려 **한 번도 적용된 적이 없었다**(2026-07-30 발견). researchers·challenges 에 있던 같은 두 줄은 그 페이지에 마이페이지 알약 자체가 없어(index만 생성) 죽은 코드라 삭제.
  - ⚠️ **햄버거는 보이는 크기 38×32px + `::after` 투명 히트영역 44×44px**(2026-07-30). 보이는 크기를 키우면 모바일 바가 57→68px로 부푼다 — news.html 스크랩 알약과 같은 방식으로 히트영역만 넓혔다. 지우면 9대 원칙 2번 위반으로 되돌아간다.
  - ⚠️ nav 높이를 또 바꾸면 **`.msn`의 `scroll-margin-top`(모바일 60 / ≥769px 78)과 `.mobile-menu`의 `top: 60px`**도 같이 볼 것 — 착지점이 바 밑에 깔린다.

## '연구실' 항목 추가(2026-07-31) — 메뉴 6항목, 폭 실측 기록

- 순서: **승준노트 · 챌린지 · 연구실 · 특강 · 연구진 · 후기**(데스크톱·모바일 동일). '연구실'(lab.html)은 드롭다운 없는 일반 링크 — 하위 페이지가 생기면 승준노트처럼 드롭다운으로 승격 검토. `SECTION_OF` 에 `lab.html: 'lab'` 등록.
- '연구진'과 붙이지 않았다 — '연구실 연구진'이 이어 보이면 같은 것 두 개로 읽힌다.
- **⚠️ 6항목이 되면서 769~840px 폴백이 넘쳤다**(769px 실측 scrollWidth 808 > clientWidth 754, 신청하기 잘림). nav.css 에 **769~840px 전용 블록**(column-gap 18 · 메뉴 gap 12 · CTA 패딩 16 · 로그인 패딩 13)으로 해결 — 활자·min-height 44px 은 안 건드렸다. 수정 후 769px 넘침 0 · 간격 20px.
- **⚠️⚠️ 정중앙 구간의 여유가 10px 뿐이다**(1000px 실측: 메뉴 425px, 메뉴↔버튼 간격 10px). **일곱 번째 항목을 넣으면 1000px 부근에서 버튼과 겹친다** — 항목을 또 늘리려면 정중앙 시작 폭(현재 1000px)을 같이 올리거나 항목을 빼야 한다.
- 1280px 실측: 메뉴 중심 오차 0px, 메뉴↔버튼 88px. 모바일(375px)은 행 57px·현재 위치 표시 정상. 아코디언 상한(560px)은 상위 항목 추가와 무관해 그대로.

## 상위 메뉴 '한 번 = 목차 / 한 번 더 = 허브'(2026-07-31 오너 지시)

- **드롭다운 목록 맨 위의 '승준노트 한눈에'·'챌린지 한눈에'는 뺐다.** 오너 지시 *"그거 없애주고, 한번 누르면 목차열리고 두번누르면 그냥 한눈에 보이는 허브로 이동"*. 허브 주소는 `nav.js` 의 `BRIEFING_HUB`·`CHALLENGE_HUB` 상수 → 상위 버튼의 `data-hub` 속성으로 들어간다. **목록 첫 줄에 허브 링크를 다시 넣지 말 것**(그러라고 뺀 자리다).
- **판정은 `is-open` 클래스 하나** — 눌렀을 때 이미 열려 있으면 `location.href = data-hub`, 아니면 연다. 데스크톱 드롭다운·모바일 아코디언 **양쪽 같은 규칙**이다. ⚠️ 마우스 호버로 열린 상태(`:hover`)를 '이미 열림'으로 쳐서 한 번에 보내는 안은 **일부러 안 썼다** — 기기마다 횟수가 달라지고, 호버가 애매한 터치 겸용 노트북에서 첫 누름이 그냥 이동해 버린다.
- **닫는 길**: 데스크톱은 바깥 클릭·Esc(기존 그대로), 모바일은 **다른 항목을 펼치면 먼저 것이 접힌다**(이번에 추가 — 버튼이 접기를 안 하게 됐으니 접는 길이 하나는 있어야 한다). 데스크톱은 원래부터 한 번에 하나만 열린다.
- **열림 표시는 화살표 회전뿐**(`.nav-dd:hover / :focus-within / .is-open` → `rotate(180deg)`, 모바일은 원래 있던 `.mm-acc-chev`). 버튼이 토글이 아니게 됐으니 **이 회전을 지우면 열린 줄 모른 채 두 번째를 누르게 된다.**
- 실측(2026-07-31): 하위 항목 승준노트 6 · 챌린지 4, 첫 누름 이동 0건, 두 번째 누름에 briefing.html·challenges.html 도착, Esc·바깥 클릭 닫힘 정상, 375px 아코디언 패널 442px(상한 560px 안, 잘림 없음), 콘솔 에러 0.

## 모바일 메뉴 '챌린지' 아코디언

- **모바일 메뉴 '챌린지' 아코디언**(2026-07-22, index·researchers 양쪽 동일): 탭하면 `#challenges`로 튀지 않고 챌린지 4개(`.mm-sub`: 이름+한줄설명)를 펼쳐 **상세 페이지로 직행**. ⚠️ **토글은 반드시 `<button class="mm-acc-btn">`** — 햄버거 IIFE가 `mm.querySelectorAll('a')` 전부에 '클릭 시 메뉴 닫기'를 걸어놔서 `<a>`로 만들면 **펼치는 순간 메뉴가 통째로 닫힌다.** 펼침은 `max-height` 전환(구형 iOS 사파리에서 grid `0fr→1fr`이 동작하지 않아 펼침이 안 됨), 상한 460px는 실측 콘텐츠 298px(4칸×72px+여백)보다 넉넉히 잡은 값이라 **항목을 추가하면 같이 올릴 것**(모자라면 마지막 칸이 잘린다). 접힘 시 `visibility:hidden`으로 키보드 포커스도 차단. 데스크톱 nav엔 '챌린지' 링크가 그대로 `#challenges`. `vertical-align:middle` 보정은 유지(점이 첫 요소면 기준선이 점 하단으로 잡혀 뜬다 — 실측 어긋남 0.49px) — 빼면 3px 뜬다.
