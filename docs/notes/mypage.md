# 마이페이지 — 상세 기록

## 답변형 챌린지가 둘이 됐다 — 제목 표식 (2026-09-04)

승.자.각과 댄.특.완은 **둘 다 답변을 `answers` 저장소에 쌓는다.** 두 챌린지 모두 DAY 1~10 이라
'DAY 1' 만으로는 어느 챌린지의 것인지 알 수 없다 — 그대로 두면 승자각 DAY 1 을 쓴 순간
댄특완 DAY 1 까지 '작성됨'으로 뜬다.

- **가르는 방법 = 제목 앞 표식.** `CH_DAY_MARK = { answer: '', culture: '댄.특.완 ' }`.
  mypage·submit 이 문항을 누를 때 `?title=` 에 표식을 붙여 보내고, 작성 판정(`dayNoOf(title, ch)`)은
  ① 표식이 있는 챌린지 = 표식이 있어야 내 것 ② 표식 없는 챌린지(승자각) = 남의 표식이 붙었으면 남의 것
  으로 먼저 거른 뒤에 종전대로 DAY 번호·낱말을 본다.
- **⚠️ 이름이 바뀌면 옛 표식을 버리지 말 것.** 2026-09-04 '대.문.각 → 댄.특.완' 개명 때
  `CH_DAY_MARK_OLD = { culture: ['대.문.각'] }` 를 뒀다. 표식은 **학생의 답변 제목에 이미
  박혀 있어서**, 새 표식만 보면 개명 전에 쓴 답변이 전부 '쓰기'로 되돌아간다.
  새 제목에 붙이는 것은 `CH_DAY_MARK`, 알아보는 것은 둘 다 — 역할이 다르다.
- **⚠️ 승자각 표식은 빈 문자열이다 — 붙이지 말 것.** 이미 쌓인 답변 제목이 전부 표식 없는 모양이라,
  붙이는 순간 옛 답변이 전부 '쓰기'로 되돌아간다. 새 답변형 챌린지를 넣으면 그때 고유 표식을 준다.
- **⚠️ 학생이 저장소에서 제목을 고쳐 표식을 지우면 그 답변은 다시 '쓰기'로 보인다.** 알고 택한 쪽이다 —
  번호·낱말만으로 가르면 반대로 **남의 챌린지 답변이 '작성됨'으로 잘못 뜬다**(더 나쁘다).
- **mypage·submit 두 파일이 같은 블록을 글자 그대로 갖고 있다**(ANSWER_CHS ~ loadDayLessons) — 한쪽만 고치지 말 것.
- 실측(2026-09-04 · 스텁 하네스): 승자각 DAY1·3 작성 + 댄특완 DAY2 작성 상태에서
  승자각 2/10 · 댄특완 1/10, 서로 새지 않음. 375px 오버플로 0 · 문항 터치 45px · 콘솔 에러 0.

## 연락처 저장은 saveMyProfile 경유 (2026-08-20)

'내 정보' 연락처 저장이 직접 `members.update` 에서 **`MONC.saveMyProfile()`(서버 RPC — 중복
번호 차단)** 로 바뀌었다. 다른 계정(구글↔카카오 이중 가입)에 등록된 번호면 서버가 막고
어느 로그인의 계정인지 안내한다. 저장형은 하이픈 표준형으로 통일. 직접 update 로 되돌리지
말 것 — 배경·규칙은 `docs/notes/auth-consent.md` '전화번호 필수' 절.

## 챌린지 처음/끝 학생 직접 제출 (2026-08-20 오너 확정)

오너 지시: "처음과 끝만 입력할 수 있도록. 내가 다 하면 일이 많아지니까 학생들이 직접. 영상도.
단, 승자각 같은 답변은 내 답변집에 쌓이도록." 설계 원장: `docs/superpowers/specs/2026-08-20-challenge-before-after-design.md`,
표·정책: migration `20260820120000_challenge_submissions.sql`(적용 여부는 implementation-status.md).

- **'내 챌린지 제출' 카드(`#chSubs`)** — 결제완료·무료(미환불) 신청의 챌린지마다 1장. 오늘 카드 바로 아래.
  ⚠️ **기수 시작일 전엔 문항·제출 칸을 그리지 않는다**(2026-09-03 — 아래 '시작 전 잠금' 절). 잠긴 카드는 '○월 ○일에 시작해요' 한 줄뿐.
  보신각·스피닝=음성, 영합각=영상(1~2분·50MB 안내), 슬롯은 '처음/끝' 두 개 — 올리면 그 자리 재생, 다시 올리면 교체.
  **스피닝만 첫날 녹음 2개**(2026-08-24 오너 "첫날에 녹음본 두 개 … 마지막날은 똑같이 녹음본 하나") — 칸 셋:
  첫날 ①(`before` · 첫 녹음본)·첫날 ②(`before2` · 발음을 신경 써서 다시 읽은 녹음본)·끝(`after` · 마칠 무렵 그대로).
  어려운 발음 단어 표시 원고 사진·발음대로 적은 원고 사진 등 나머지 첫날 제출물은 **오픈챗 운영** — 사이트 칸은 녹음 2개만 받는다(사진 칸 만들지 말 것).
  `before2` 는 migration `20260824170000`(type check 스피닝 한정 + storage 파일명 패턴)이 열어 준다 — 미적용이면 첫날 ② 업로드만
  "업로드하지 못했어요"로 막히고 나머지는 그대로 돈다. admin 회원 상세·타임라인도 같은 이름표를 쓴다(두 화면을 같이 고칠 것).
- **오픈챗 공유용 제출 입구 `submit.html`**(2026-08-24 오너 "링크 하나 주면 로그인해서 올리고, 올린 회원 마이페이지에도 남게") —
  저장하는 곳이 mypage 제출 카드와 완전히 같아서(`challenge_submissions`·`recordings` 버킷·answers) **여기로 올려도 마이페이지에 그대로 보인다**(동기화 코드 없음 — 같은 표를 읽을 뿐).
  링크 규칙: `?t=before`(시작 무렵)·`?t=after`(마칠 무렵)로 시기를 좁히고 `?ch=voice|expression|spinning|answer` 로 챌린지를 좁힌다 — 없으면 참가한 전부.
  **기수는 링크에 안 싣는다** — 각자 신청에서 자동으로 붙는다(round). 승자각은 DAY 문항 목록으로 그린다(`answers.html?title=…#new` — mypage 카드와 같은 규칙).
  미로그인은 requireSession 이 login 으로 보내고 **returnTo 가 쿼리까지 들고 돌아온다**(`safeReturnTo` 정규식이 `?…` 허용 — 실측). 비참가 계정은 안내 카드(신청 계정 재로그인 안내).
  `data-nav-offset` 필수(빼면 제목이 고정 nav 에 가려진다 — 실측). **칸 이름·업로드 규칙을 바꿀 땐 mypage.html·admin.html·submit.html 세 곳을 같이 고친다.**
  오너가 쓸 공유 주소는 **admin 신청자 현황의 챌린지 탭 아래 '제출 링크' 패널**에서 복사한다(admin.md '제출 링크 패널' 절 — 주소를 따로 적어 둘 필요 없음).
  승자각은 파일 대신 **DAY1~10 문항 목록 + 작성 N/10** — 문항 클릭 → `answers.html?title=…#new`(제목 자동 채움).
- **문항 정본은 `challenge_lessons`**(2026-08-24 — admin '챌린지' 탭 → 승자각 DAY 문항). `renderChSubs` 가 판정 전에 `loadAnswerLessons()` 로 받아 `ANSWER_DAYS`·`ANSWER_DAY_WORDS` 를 덮어쓴다.
  ⚠️ 코드에 적힌 10줄은 **폴백**이다 — 표가 없거나 0줄이면 덮어쓰지 않는다(지우지 말 것).
  같은 표를 `challenge-answer.html`·`apply.html` 도 읽는다(admin.md 절이 원장).
- **작성 판정은 `dayNoOf()` 의 느슨한 읽기**(2026-08-23 — 구 '제목 정확 일치'를 대체).
  순서는 ① 제목에 `DAY 3`·`3일차` 같은 **번호**가 있으면 그것 ② 없으면 **문항 이름에서 만든 낱말**.
  낱말은 `wordsOf(문항 이름)` 한 곳에서 만든다 — `'장점/단점' → ['장점','단점']`. `ANSWER_DAY_WORDS` 는 그 결과일 뿐이다.
  ⚠️ **낱말을 손으로 적는 목록·admin 칸을 다시 만들지 말 것**(2026-08-24 오너 "헷갈려"로 폐지 — admin.md).
  비교 전 `normTitle()` 이 공백·마침표·괄호를 걷어낸다. 제목은 `title` → `questions.content` 순으로 본다(소재 발굴 답변은 title 이 비어 있다).
  ⚠️ **정확 일치로 되돌리지 말 것** — 학생이 저장소에서 제목을 고치면('자기소개'·'장점과 단점') 이미 쓴 답변이 다시 '쓰기'로 보였다.
  `ANSWER_DAYS` 는 이제 **프리필 제목의 정본**이다(answers.html `?title=`). 문구를 바꾸면 낱말표도 같이 본다.
  **'작성됨' 줄은 `answers.html` 로 보낸다**(`?title=…#new` 로 보내면 같은 제목의 빈 답변이 또 생긴다).
  답변 조회는 `loadAnswerNotes()` 의 promise 를 재사용한다(추가 요청 없음 — 함수가 data 를 return 하는 이유).
- **참가 판정의 원장은 DB**: `challenge_submissions` RLS 의 `is_challenge_participant()`
  (applications 에서 member_id=auth.uid() + 결제/무료 + 전액 미환불 + 그 챌린지 포함). 화면 partOf 는 카드를 그릴지만 정한다.
  ⚠️ **부분 환불(중도 해지)은 참가 유지다**(`20260822140000` — 그전엔 함수가 부분 환불을 배제해, 화면은 카드를 열어 주는데 업로드가 42501 로 죽었다. 다건 챌린지 결제 후 1건만 환불한 회원의 나머지 챌린지까지 막혔던 원인). 전액 환불만 배제 — 화면 partOf 와 같은 기준을 유지할 것.
  ⚠️ 비회원 신청(전화 매칭)은 대상이 아니고 **admin 대리 업로드도 없다**(오너 "내가 대신 올려주는 건 없어") — apply 의 로그인 유도 강화 + 가입 뒤 admin [이 회원에 연결]로 직접 업로드 길을 연다(전화 조회 창구 금지 원칙 + 프로필 번호 바꿔 남 행세 차단은 그대로).
- 업로드 경로 `<uid>/<챌린지>-<before|after>.<ext>`(storage 정책이 패턴·참가까지 검사). 확장자가 바뀐 재업로드는 옛 파일을 지운다.
  조회는 **`.eq('member_id', me)` 필수** — 빼면 admin 계정에서 전 회원 행이 내려온다(chsub_admin_all).
- **degrade**: 표 미생성(PGRST205 등)이면 슬롯이 '제출 준비 중' 안내로 내려간다(업로드 버튼 없음). 승자각 카드는 무관하게 돈다.
- **같은 날 화면에서 정리한 것(데이터는 보존)**: '2주 미션' 진행 바(progCard)·14일 격자(sec-days)·코치 코멘트(sec-comments)와
  admin 의 일차 입력 패널. `daily_records` 표·데이터는 그대로 있다 — 되살리려면 화면만 다시 붙이면 된다.
- legacy `recordings`(회원당 한 쌍·admin 업로드)의 `sec-ba` 접이는 **행이 있을 때만** 보인다(옛 데이터 표시용).
- 제출 카드 묶음 맨 아래에 **'챌린지 후기' 카드([후기 쓰기] → review-write.html)** — 참가자에게만 보인다(2026-08-20 · 상세는 pages.md '회원 직접 제출' 절).
  안내는 **'참여한 챌린지의 후기를 남겨 주세요.' 한 줄뿐**이다 — 2026-08-23 오너가 '검토 후 후기 페이지에 올라가요' 꼬리를 뺐다.
  승인 절차 자체는 그대로다(`visible=false` 로 들어가고 admin 이 켠다 — pages.md). 화면에서 그 절차를 미리 말하지 않을 뿐이다.
- `memberState()` 의 참여 폴백은 이제 daily_records 가 아니라 **결제한 챌린지 존재**다 — 기수(cohort) 미배정이어도
  결제만 돼 있으면 active 로 본다(제출이 기수 배정에 안 막히게). 단 결제한 챌린지가 전부 시작 전이면 `prestart`(아래 '시작 전 잠금').

## 시작 전 잠금 — 결제했어도 기수 시작일 전엔 챌린지 내용을 열지 않는다 (2026-09-03 오너 지적)

배경: 4기 진행 중에 5기를 모집했는데, 5기 결제자가 결제 직후 마이페이지·submit.html 에서 승자각 DAY 문항
목록과 제출 칸(첫날 녹음 안내 등)을 그대로 봤다. 제출 카드가 **결제 여부만** 보고 그려졌고, 기수 시작일은
어디서도 안 읽었기 때문(`prestart` 판정은 admin 이 손으로 배정하는 `cohort_id` 에만 걸려 있었다).
환불 규정의 근거 사실("미션 콘텐츠는 시작과 동시에 제공" — apply-and-payment.md 맨 위 절)과도 어긋났다.

- **규칙**: 신청한 기수의 **시작일 전엔 문항·제출 칸을 그리지 않는다.** 잠긴 카드는 챌린지 이름 + 기수 +
  '○월 ○일에 시작해요. 문항과 제출 칸은 시작일에 열려요' 한 줄. **무엇을 하게 될지(첫날 녹음 두 개 등)도 적지 않는다.**
  전부 시작 전이면 '챌린지 후기' 입구도 없다.
- **판정 파일은 `round-gate.js`(`window.MONC_GATE`) 하나** — mypage·submit·admin 이 같이 싣는다(`?v=1`). 페이지에 복사하지 말 것.
  스크립트가 못 실렸으면 종전 동작(최신 기수·열림)으로 떨어진다.
- **시작일 규칙 `roundStartOf(r, all)`**: ① `program_start` ② 없으면 **모집 마감(recruit_end) 다음 날 — 선착순도 같다**
  (모집 중인 기수는 시작 전이다) ③ 둘 다 없는 선착순은 **같은 챌린지에 더 높은 기수가 있으면 시작한 것으로 보고 연다**
  (5기를 열었다면 4기는 시작했다), **가장 높은 기수면 시작일 미정 = 잠김**(`pending`) — 공개 화면도 그 기수를 '선착순 모집 중'으로
  말하므로 회원 화면만 열어 두면 앞뒤가 안 맞는다. admin 에서 '프로그램 시작'을 넣으면 그날부터 열린다.
  조회 실패(startMap null)는 연다 — 진행 중인 기수를 장애로 잠그지 않는다.
  ⚠️ 첫 판(2026-09-03 오전)은 "선착순+시작일 없음 = 연다"였다 — 그런데 **실제 5기가 선착순**(home.md 실측 '5기 · 선착순 모집 8/24~9/6')이고
  구 admin 폼이 선착순의 시작일을 비워 저장했으므로 그 규칙으로는 5기가 계속 열렸다. 같은 날 위 규칙으로 바꿨다.
- **같은 챌린지에 기수가 여럿이면 `pickContentRound()`** — 시작한 기수 중 최신(4기 진행 중 + 5기 결제 → 4기 카드 유지),
  하나도 안 시작했으면 가장 먼저 시작할 기수(시작일 미정은 맨 뒤)를 잠근 채.
- **'오늘 한 칸'도 같이 본다**: 결제한 챌린지가 **전부** 잠겨 있으면 cohort 미배정이어도 `prestart`('○월 ○일에 시작해요',
  시작일 미정이면 '챌린지 시작 전이에요' — 사이트가 모르는 날짜를 지어내지 않는다). 신원 줄은 '챌린지 시작 전'.

## 비참여자 화면 재배치 (2026-08-06 오너)

  - **승준 코스 줄이 맨 위**(2026-08-06 오너 "마이페이지에서도 승준 코스로 보내는 자리") — '뭐부터 할지'가 시작 안내의 첫 질문이라 챌린지 줄 위다. 배지 없음. 코스를 골라 뒀으면 부제가 `지금은 ○○ 코스예요 · 이어서 준비하기`로 바뀐다. course 는 공용 `getMyProfile()` 셀렉트에 없어(미적용 400 방지 규칙) `setupGoCard(uid)` 가 `members` `select('*')` 별도 조회 — 실패·없음·모르는 코드는 기본 문구(`내 상황에 맞는 준비 순서 정하기`) 유지.

  - **특강 줄은 모집 중일 때만** 그린다: `special_lectures` `visible=true` + 모집 기간 내 + `seats_left !== 0`. 1개면 제목, 여러 개면 'N개'. 없으면 줄 자체가 없다 — **항상 펼쳐 두지 말 것**(오너 지시).
- 배지 색은 전역 팔레트(`--action`+`--action-ink`)만 — 알림용 빨강 점을 새로 만들지 않았다.

## 지키는 규칙

- **오늘 한 칸의 문장은 사이트가 아는 사실만.** 미션 인증은 카톡 오픈챗에서 일어나므로 "오늘 미션이 아직 안 올라왔어요" 같은 제출 여부 문장은 못 쓴다(2026-07-31 오너 확정 — 문구를 아는 사실로 낮추는 안 선택). 큰 버튼은 '오늘의 소재 발굴'.
- **일차는 시작일=1일차.** 7.20 시작이면 7.31은 12일차. 목업 속 '11일차'는 픽션 오차 — 코드 계산이 정본.
- **접이(fold)는 데이터가 있는 줄만 보인다** — 빈 껍데기 금지(신규 회원 0·0·0 나열이 이 개편의 발단). 예외는 '내 정보' 하나(항상). ※ Before/After 접이의 '챌린지 상태면 항상' 예외는 2026-08-20 폐지 — legacy 행이 있을 때만 보인다(예고 역할은 제출 카드가 맡는다).
- **역량검사 게임 접이(`#sec-games`)** — `game_scores` 본인 행이 있을 때만(2026-08-26 오너 지시). 게임별 실전/연습 최고점, 줄 클릭 → `games.html#게임id`. 표·RPC·kind 경계는 games.md '회원 점수 기록' 절이 원장.
- 접이는 **한 번에 하나만** 열린다(스크롤 통제). 답변노트는 미리보기 3개 + 전체 링크. (구 '뉴스 스크랩' 접이는 2026-08-28 뉴스 폐지로 제거.)
- **답변노트 접이 = '대화 중' → '작성 중' → '완료' 순, 셋 합쳐 3줄**(2026-08-05 오너 요청). '대화 중'은 소재 발굴에서 되묻기만 하고 답변은 아직 안 쓴 문제로, 원장은 `discovery_sessions`(stage≠done) 다. **최대 2줄** — 세 자리를 다 먹으면 정작 쓴 답변이 안 보인다. 미리보기는 그 세션에서 마지막으로 내가 쓴 말 한 줄. ⚠️ `answers` 에 행이 있는 문제는 제외한다(같은 문제가 '대화 중'과 '작성 중'으로 두 줄이 된다). ⚠️ 세션마다 메시지를 조회하지 말 것 — 두 세션 것을 `in()` 한 번으로 받아 나눈다. ⚠️ 이 줄이 필요해진 이유는 소재 발굴이 **빈 초안 행을 더 이상 안 만들기** 때문이다(credits.md) — 그 변경을 되돌리는 대신 여기서 보여준다.
- **'내 기록'은 흰 카드 묶음**(2026-07-31 오너 "가장 많이 쓰게 될 곳인데 존재감이 없다") — 그림자·라운드 24px, 제목 18px, 줄 64px, 줄마다 연네이비 아이콘 배지 38px. 종이 위 맨 줄 나열로 되돌리지 말 것. 접이 안 항목은 `--surface2`(흰 카드 위 흰 항목은 경계가 안 보인다), 기본 칩은 흰 배경+헤어라인.
- **접이 오른쪽 값은 16px·800·네이비**(같은 날 오너 "너무 작아서 존재감없다" — 12~13px 로 되돌리지 말 것).
- **전화 마스킹은 `+82` 국제 표기를 0 으로 정규화한 뒤 건다** — 정규식만 믿으면 `+8210…` 원문이 그대로 노출된다(실사고).
