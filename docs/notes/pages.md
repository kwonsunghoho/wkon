# 기타 페이지(후기·연구진·상세 4종·오디오) — 상세 기록

## 커뮤니티 오픈챗 모집 카드 — community-card.js 공용 (2026-08-16 오너 확정)

- **카드가 실리는 곳 3곳뿐**: lab-shelf·news·tools 본문 맨 아래(`<div data-community-card>` + `community-card.js?v=`). 오너 확정 — "덕지덕지 금지". **홈에는 넣지 않는다**(홈 커뮤니티 섹션은 부활 금지 목록). 카드 문구·모양·동작은 전부 `community-card.js` 한 파일 — 페이지에 복사 금지, 수정 시 세 페이지 `?v=` 동반 상향.
- **nav 소셜 줄에는 '오픈채팅 커뮤니티' 항목이 있다**(2026-08-16 오너 "모바일 햄버거에 좀 추가" — 같은 날 '넣지 않는다'에서 뒤집힘). 단 **오픈챗 직링크가 아니라 `tools.html#community`(도구 허브 카드 착지점) 내부 링크**라 회원 게이트는 그대로다 — 방 주소를 nav 에 직접 걸지 말 것. 상세는 nav.md 소셜 절.
- **⚠️ 입장 주소·참여코드는 레포 반입 금지**(공개 레포 — 커밋하는 순간 게이트 무의미). `community_config` 표(RLS: **authenticated 만 select**, anon 정책 없음)에서 회원만 받는다. 값 변경은 콘솔 SQL(대화창 전달). 비회원 클릭 → `login.html?returnTo=`, 표 미생성(`PGRST205`)·실패 → '아직 준비 중' 안내로 조용히 degrade.
- **아래 '문의 창구' 절과 별개다** — 문의는 카카오 **채널** `/chat` 하나, 이 카드는 **커뮤니티 오픈챗**(회원 전용). 커뮤니티 방 주소를 문의 자리에 쓰거나 그 반대로 섞지 말 것.
- tools.html 은 이 카드 때문에 supabase-js+supabase-config 를 싣기 시작했다(2026-08-16 전엔 없었다).
- 참여 인원수 표시 없음(카카오가 숫자를 안 내려줌 — 손 관리 = 거짓 숫자). 계측은 `community_card_click` 하나(page_events 직접 insert, 이벤트명 규칙 준수).
- bfcache: 카드가 `pageshow(persisted)`에서 스스로 초기화한다 — lab-shelf 가 통째 reload 예외(결제 복귀)라서, 로그아웃 뒤 뒤로가기로 펼쳐진 참여코드가 되살아나는 걸 막는 처리다. 지우지 말 것.
- 실측(2026-08-16 · 미러): 375px 세 페이지 카드 렌더·버튼 44px·활자 14.5/12.5px / 320px 넘침 0(버튼이 제 줄로 래핑) / 비회원 클릭 → login.html?returnTo 이동 / 가짜 세션 + 표 미생성 → '준비 중' 안내·콘솔 에러 0(PGRST205 404 는 예상 응답) / pageshow(persisted) 합성 이벤트로 초기화 확인. 서가는 주소를 `lab-airline.html` 스텁으로 다시 쓰므로 returnTo 가 스텁 경유로 돌아온다(스텁이 서가로 전달 — 정상).
- 설계 원장: `docs/superpowers/specs/2026-08-16-community-card-design.md`, 마이그레이션 적용 여부: implementation-status.md.

## 문의 창구 = 카카오톡 채널 하나 (2026-08-09 오너 "다 교체해라")

- **⚠️ 링크는 반드시 `/chat` 을 붙인다 — `https://pf.kakao.com/_iajxnX/chat`.** 채널 **홈은 '비공개' 상태**라 `/chat` 없는 주소는 브라우저에서 *"페이지를 찾을 수 없습니다 — 비공개 또는 삭제된 프로필"* 이 뜬다(2026-08-09 오너 신고로 확인). 채널 ID 자체는 정상이다(없는 ID 는 `<title>` 에 채널명이 안 뜨는데 이 ID 는 '몬크 면접 연구소'가 뜬다). `/chat` 은 비공개 상태에서도 열려 '카카오톡에서 시작하기'로 이어진다. 오너가 채널 관리자센터에서 홈을 공개로 바꾸면 홈 주소도 살지만, **문의 목적이면 `/chat` 이 그대로 맞다**(한 번에 채팅으로 간다).

## 챌린지 상세 — 지어낸 지표 제거 + 실제 후기 노출 (2026-08-02)

- **'수료율 95% · 평균 성과 87%' 4종 삭제.** 네 페이지가 글자까지 같은 값이라 지어낸 것으로 읽혔고, 사이트가 다른 곳에서 지킨 '숫자를 꾸며내지 않는다'가 정작 결제 화면에서만 깨져 있었다. 각 페이지가 실제로 가진 사실로 교체 — 보신각 `전후 음성 7쌍 공개` · 스피닝 `전후 음성 4쌍 공개` · 영합각 `전후 영상 공개` · 승자각 `완성 답변 10개`, 공통 `2주 · 미션 10회차`. **실측 없는 성과 지표를 다시 넣지 말 것**(수료율은 daily_records 실측이 쌓이면 그때).
- **후기 노출 = `challenge-reviews.js` 공용 1파일**(오너 "후기 보여지게해봐"). 상세 4종에 `<section id="chReviews" data-challenge="보신각" hidden>` 한 줄 + 스크립트 한 줄. 스타일도 이 파일이 주입한다 — 상세 4종 인라인 CSS 에 복사하지 말 것. 인용문 있는 후기 우선 3개 + '후기 N건 전체 보기'(reviews-list.html?kind=challenge). **0건이면 섹션을 안 그린다.** 조회는 `select('*')` + 클라이언트 필터(`kind` 컬럼 미적용 환경 400 방어 — reviews-list.html 과 같은 규칙), 상담 후기는 제외(실명 미노출 규칙).
- ⚠️ **후기가 뜨려면 `reviews.challenge` 가 채워져 있어야 한다** — 어드민 '여러 장 한번에' 업로드는 이 값을 안 채우고, 미지정이면 섹션이 조용히 숨겨진다(화면에 아무 표시도 안 남는 게 이 설계의 값). 그래서 admin 후기 탭에 챌린지별 건수 요약(`#rvChSum`)을 붙였다 — 안 뜬다는 신고가 오면 거기 숫자부터 본다. `data-challenge` 문자열과 admin `RV_CH_OPTS` 는 **같이** 고친다.
- ⚠️ **승자각 Before/After 는 만들지 않는다**(2026-08-02 오너 "승자각은 비포애프터가 애매하잖아"). 글은 음성·영상처럼 전후 대비가 안 서서, 승자각의 증거는 후기 섹션이 맡는다.

## 후기 — 허브 + 종류별 목록(2026-08-01 개편)

후기는 **한 장짜리 페이지가 아니라 허브 아래 세 갈래**다(오너 요청 2026-08-01).

⚠️ **후기 사진(`reviews-list.html .rv-shot img`)·수기 커버(`story.html .st-cover`)가 뜰 때 아래 글이 밀리는 것은 그대로 둔다 — 2026-08-03 오너 확정("그대로 둬").** 자리를 미리 잡으려면 비율을 못 박고 잘라내야 하는데 **둘 다 사람이 올리는 사진이라 비율을 모른다.** 잘려 보이는 쪽이 더 나쁘다는 판단이다. **버그로 보고 aspect-ratio 를 넣지 말 것.** 같은 판단이 특강 커버에도 적용된다(lectures.md).

| 파일 | 역할 |
|---|---|
| `reviews.html` | **허브.** nav '후기'의 목적지. 종류 카드 + 종류당 미리보기 3개 + 전체 합계 |
| `reviews-list.html?kind=challenge\|consult` | 챌린지·상담 후기 목록 **공용 한 파일**(매스너리 그리드·필터·라이트박스) |
| `stories.html` | 합격 수기 목록(긴 글이라 카드 그리드가 아니라 줄 목록) |
| `story.html?id=` | 합격 수기 상세 |

- **⚠️ 종류마다 HTML 을 새로 만들지 말 것.** 목록은 `?kind=` 한 파일이 정본이다(`lab-shelf.html?shelf=`·`lecture.html?id=` 와 같은 규칙). 챌린지 상세 4종이 인라인 CSS 를 글자 그대로 복사해 겪는 문제를 반복하지 않는다.
- **파일명 `reviews.html` 을 바꾸지 말 것** — nav '후기'·이미 공유된 카톡 링크·og:url 이 이 이름을 물고 있다. 허브로 성격만 바꿨다.
- **데이터 0건인 종류는 카드를 아예 안 그린다.** '준비 중' 빈 카드를 두지 않는 건 오너 방침이다(스피닝 비포&애프터의 빈 인용 자리표시자를 삭제한 것과 같은 기준 — "올릴 내용 없으면 칸 자체를 삭제"). 합격 수기는 자료가 생기는 순간 카드가 나타난다.
- 목록 미리보기는 **한줄평(quote) 있는 것을 먼저** 고른다(`pickPreview`). 없으면 스크린샷 조각. 허브가 이정표가 아니라 내용으로 읽혀야 해서다.

### 종류 구분 — `reviews.kind`
`challenge`(기본) / `consult` 두 값. migration `20260801180000_reviews_kind.sql`(오너 실행). 기존 108건은 default 로 자동 `challenge` — 백필 update 가 없다.
- **⚠️ 목록은 `select('*')` 뒤 JS 에서 거른다.** `.eq('kind', …)` 로 서버 필터하면 마이그레이션 미적용 환경에서 400 이 난다. 미적용이면 전부 `challenge` 로 떨어져 챌린지 목록은 그대로 돌고 상담 목록만 0건이 된다.
- 같은 마이그레이션이 `image_path` 의 not null 을 풀어 **글만 있는 후기**를 허용한다(상담 후기는 캡처와 글이 섞여 있다 — 오너 확인). 대신 `reviews_body_required` check 로 '이미지도 글도 없는 행'을 막는다.

### 상담 후기 — 실명 미노출(오너 확정 2026-08-01)
챌린지 후기는 공개 카페 글이라 실명이 나가지만, **상담은 1:1 이라 이름을 화면에 띄우지 않는다.** 이름 대신 `review_date` 를 `YYYY.MM` 으로만 붙인다(언제 받은 상담인지는 남긴다). 대체 텍스트에서도 이름을 뺀다.
- **⚠️ 스크린샷 안에 박힌 이름·번호·프로필 사진은 코드가 가릴 수 없다** — admin 업로드 칸에 경고 문구를 띄워 두었다.
- 상담 후기엔 챌린지·기수 축이 없어 **필터바를 두지 않는다**(건수가 쌓이면 그때).

### reviews 테이블 분류 컬럼
`reviews`에 `challenge`(보신각/영합각/스피닝/승자각)·`cohort`(smallint, NULL=미상)·`reviewer_name`·`review_date`·`quote` 컬럼 (migration `20260710130000_reviews_classify.sql` + 기존 108건 백필, owner 실행). 챌린지 후기 목록 필터에 사용. admin '후기 관리'에서 수정.
- `quote` 는 **이제 화면에 뜬다**(카드 앞면 한줄평). 구 "저장만·미표시" 설명은 홈 커뮤니티 섹션 시절 기준이라 무효다.

### 합격 수기 — `success_stories`(별도 표)
`reviews` 에 넣지 않은 이유: 긴 본문·제목·항공사·상세 페이지가 필요해 `image_path` 중심 목록과 렌더가 아예 다르다.
- 컬럼: `title`·`body`(평문, 빈 줄이 문단 구분)·`author_name`·`airline`·`cohort`·`thumb_path`·`published_at`·`visible`·`sort_order`.
- **`visible` 기본값이 false** — 올린 즉시 공개되지 않는다. admin 에서 검토 후 켠다. `story.html` 도 `.eq('visible', true)` 를 같이 걸어 주소를 알아도 비공개 글은 안 열린다(RLS 와 이중 방어).
- **⚠️ 본문은 `textContent` 로 그린다(`innerHTML` 금지)** — 사람이 쓴 글이라 `<` `>` 가 섞여 들어올 수 있다.
- 표 없음 판정은 `42P01` 이 아니라 **`PGRST205`** — 마이그레이션 미적용이면 '아직 없음'으로 조용히 떨어진다(허브 카드 미노출·목록 빈 문구).

### admin '후기 관리'
한 탭에서 셋을 다 본다: 업로드 3종(여러 장·1장·**글만**)에 종류 셀렉트, 목록 위 종류 필터 칩(전체/챌린지/상담), 카드마다 종류 셀렉트, 그리고 맨 아래 **합격 수기** 줄 목록(펼침 편집).
- 업로드 insert 는 `kind` 컬럼이 없으면(`42703`/`PGRST204`) **kind 를 빼고 한 번 더 시도**한다 — 마이그레이션 전에도 업로드가 막히지 않게.
- 이미지 없는 행은 `<img>` 자리에 `.rv-noimg` 로 글을 세운다(깨진 이미지 아이콘 방지).

### 커뮤니티/후기 (홈 섹션은 2026-07-29 삭제)

### 비포/애프터 재생 — `ba-audio.js` (2026-08-02 · 오너 "재생박스 너무 커, 동시 재생이 되는데?")

네이티브 `<audio controls>` 를 그대로 쓴 탓에 두 가지가 같이 났다.
- **크기**: iOS 사파리는 폭이 좁으면 컨트롤을 큰 회색 덩어리로 그린다 — 셀 높이 **168px**.
  `::-webkit-media-controls-*` 는 iOS 에서 안 먹어 **CSS 로는 못 줄인다.**
- **동시 재생**: 오디오 요소끼리는 서로를 모른다. 비포를 켠 채 애프터를 켜면 겹쳐 들렸다.
  전·후를 비교하라고 만든 화면에서 기능이 망가진 상태였다.

`ba-audio.js` 한 파일이 둘 다 맡는다.

| | 방식 | 적용 |
|---|---|---|
| 동시 재생 차단 | `document` **캡처 단계**의 `play` 리스너(미디어 이벤트는 버블링 없음) | 전역 — voice·spinning·mypage·admin |
| 콤팩트 UI | `.ba-cell` 안의 오디오를 우리 버튼으로 교체 | voice 14 · spinning 8 |

- **실측**: 셀 높이 **168 → 57px**(-66%), 버튼 52px(터치 44 이상), 라벨 12px,
  대비 비포 5.19:1 · 애프터 9.26:1, 아이콘 원 9.99:1 · 9.26:1. 320~1280px 가로 넘침 0.
  오디오 요청 0건 유지(전송 234KB / 228KB).
- ⚠️ **마크업의 `controls` 를 지우지 말 것.** 스크립트가 안 뜨면 네이티브 컨트롤이 남아
  **소리는 들린다.** controls 를 빼면 스크립트 실패 = 증거 소실이다(결제 결심 화면).
- ⚠️ `preload="none"` 이라 **재생 전에는 길이를 모른다.** 그래서 시간 표시를 만들지 않고
  진행 막대만 쓴다 — '0:14' 같은 값을 지어내지 말 것(원칙 11).
- ⚠️ **320px 에서는 1열로 쌓는다**(`.ba-grid` + `!important`). 그 폭에서 셀이 110px 까지
  좁아져 'BEFORE' 가 말줄임됐다. 활자 12px 하한을 지키려면 칸을 넓히는 수밖에 없다.
  격자가 페이지 인라인 style 이라 `!important` 가 필요하다.
- mypage·admin 은 `.ba-cell` 이 없어 **UI 는 그대로**이고 동시 재생 차단만 걸린다.
  mypage 의 음성은 서명 URL 이라 나중에 DOM 에 꽂히는데, 캡처 리스너라 그것도 잡힌다.

### 2026-08-02(저녁) 하단 바가 푸터를 가리던 문제 — 오너 신고
오너 스크린샷: 챌린지 상세 맨 아래에서 바가 푸터 위를 지나가며
'주소: … 고객센터: 070-' 줄이 **가로로 잘려** 보였다.

**내가 놓친 것**: `body { padding-bottom }` 이 붙었는지만 확인하고, **맨 아래까지
스크롤했을 때 마지막 줄이 바 위로 올라오는지는 재지 않았다.** 375px 데스크톱
크로미움에서는 `env(safe-area-inset-bottom)` 이 0 이라 재현도 안 됐다.

**고친 것 셋**
1. **푸터가 보이면 바를 내린다.** 히어로 버튼 하나만 보던 IntersectionObserver 를
   '가리면 안 되는 것' 집합(히어로 버튼 · 마지막 신청 버튼 · 푸터)으로 넓혔다.
   통신판매업자 표시는 법적 고지라 반쯤 가린 채 두면 안 된다.
2. **배경을 불투명으로.** 구 `rgba(...,.94)+blur` 는 밑을 지나가는 글자가 비쳐
   '잘린 것처럼' 보였다. `--bg` 불투명 + `--border-strong` 경계선 + 위쪽 그림자.
   ⚠️ 반투명으로 되돌리지 말 것.
3. **높이를 계속 추적.** 한 번만 재면 iOS 안전영역·주소창 접힘으로 어긋난다 —
   `ResizeObserver` + `visualViewport.resize` + `resize`. 여유 8px 추가.

**검증(이번엔 제대로)**: 상세 4종 × 320/375/393+safe/430+safe = **16개 조합**에서
① 본문 중간 바 노출 ② 맨 아래에서 바 내려감 ③ **푸터 가려짐 0px** ④ 푸터 전체 노출.
안전영역은 `padding-bottom` 을 강제 주입해 흉내 냈다(크로미움은 env() 가 0).

### 2026-08-02(저녁 2차) 바 **자체**의 아랫부분이 잘리던 문제 — iOS Safari 툴바
오너 2차 신고: 바 크롭은 정상인데 화면에선 하단부가 잘려 보인다.

**원인**: `position:fixed; bottom:0` 은 **레이아웃 뷰포트**(`window.innerHeight`) 기준이다.
iOS Safari 는 스크롤 중 하단 툴바를 접었다 폈다 하는데, 접힌 동안 레이아웃 뷰포트가
**실제로 보이는 영역(`visualViewport.height`)보다 커진다.** 그래서 bottom:0 인 바가
툴바 뒤로 들어가 아랫부분이 잘린다.

⚠️⚠️ **데스크톱 크로미움에서는 두 값이 항상 같아 절대 재현되지 않는다.** 내가 두 번
놓친 이유가 이것이다. **하단 고정 요소를 새로 만들면 이 보정을 반드시 같이 단다.**

**보정**(`challenge-sticky.js` `place()` · `lecture.html` `placeSticky()` — 두 파일 동일):
```js
var gap = Math.max(0, Math.round(window.innerHeight - vv.height - vv.offsetTop));
bar.style.setProperty('--vv-gap', gap + 'px');  // CSS: transform:translateY(calc(-1 * var(--vv-gap)))
```
visualViewport 가 없으면 no-op 이라 기존 동작 그대로.
숨김 상태의 `translateY` 는 `calc(110% + 60px)` 유지 — 올려 둔 상태에서도 완전히 화면
밖으로 내려가야 한다.

⚠️⚠️ **프레임마다 쫓아가지 말 것 (2026-08-02 밤 성능 사고 — 오너 "엄청 버벅이고 깜빡임도
생겼어").** 처음 구현은 `visualViewport`·`window` 의 `resize`·`scroll` 을 rAF 로 묶어
**매 프레임** place+padBody 를 돌렸다. 툴바가 움직이는 동안 프레임마다 스타일 쓰기 +
강제 레이아웃(offsetHeight)이 나가 폰에서 스크롤이 끊기고 바가 덜덜 떨렸다(보정 1회
실측 0.7ms/맥 — 폰은 몇 배, 120Hz 아이폰의 프레임 예산은 8.3ms). 바뀐 규칙 셋:
① 같은 이벤트를 듣되 **멈추고 120ms 뒤 한 번만** 잰다(settle 디바운스, `pageshow` 포함).
② **값이 안 바뀌면 아무것도 안 쓴다**(스타일 쓰기 전부).
③ 위치는 `bottom` 이 아니라 **transform 변수(`--vv-gap`)** 로 옮긴다 — 합성 단계라
   레이아웃 계산이 없고, 기존 `.28s` transition 을 타고 미끄러져 자리 잡는다.
트레이드오프(오너 승인 2026-08-02): 툴바가 움직이는 ~0.3초 동안은 바가 안 따라가고 멈춘
직후 한 번에 자리 잡는다. 정지 상태의 위치는 프레임 추적 때와 동일하다. **rAF 프레임
추적으로 되돌리지 말 것.**

**검증 방법(재현 레시피)**: `window.visualViewport` 를 가짜 객체로 덮어
`height = innerHeight - 툴바` 로 만든다. 상세 4종 × 툴바 0/44/88px = 12개 조합에서
바 잘림 0 · 푸터 가려짐 0 · 맨 아래에서 바 내려감을 확인했고, 같은 측정이 '보정이

## 챌린지 상세 커리큘럼 아코디언 — 키보드 + 스크롤 보정 (2026-08-02)

상세 4종의 `.week-header` 는 **`div` 에 click 핸들러만** 있었다. 두 가지를 고쳤다.

- **키보드**: `role="button"` + `tabindex="0"` + Enter/Space + `aria-expanded` 를
  **스크립트가 런타임에 단다**(마크업이 4파일에 흩어져 있어 한 곳에서 관리). 1주차만 기본
  열림이라 그전엔 키보드·스크린리더로 **2주차 DAY 6~10 에 닿을 방법이 아예 없었다.**
  Space 는 기본 동작이 페이지 스크롤이라 `preventDefault()` 가 필요하다.
- **스크롤 보정**: 2주차를 누르면 위의 1주차가 접히면서 **누른 헤더가 화면 위로 474px 밀려
  사라졌다**(393px 실측). `toggle()` 이 클릭 전후의 `getBoundingClientRect().top` 차이만큼
  `scrollBy` 해서 누른 자리를 지킨다.
  - ⚠️ **`fix()` 를 동기 1회 + `requestAnimationFrame` 1회, 두 번 부른다.** 동기 한 번만
    하면 브라우저가 다음 프레임에 24px 를 도로 밀어낸다(실측). 둘 다 있어야 0px 다.
  - ⚠️ `html { scroll-behavior: smooth }` 가 걸려 있어 `behavior:'instant'` 를 명시한다 —
    보정은 눈에 보이면 안 된다.
  - `overflow-anchor:none` 도 시도했으나 **측정상 차이가 0** 이라 넣지 않았다(rAF 재보정이
    실제로 일하는 부분이다). 다시 넣기 전에 먼저 재 볼 것.
- 같은 김에 죽은 `toggleWeekModal()`(호출처 0 · `*ContentModal` 요소 없음)을 4파일에서 제거.
- **검증**: 4종 × (모바일 393 / 데스크톱 1280) × (클릭 / 키보드) = 8조합, 누른 헤더 이동
  0~1px · 콘솔 에러 0. 하단 고정바 기존 검사(툴바 12조합 · 화면폭 16조합)도 재실행해 회귀 0.
  ⚠️ 하네스 주의: playwright `.click()` 은 먼저 요소를 화면에 넣으려 스크롤한다 —
  기준값을 그 전에 재면 우리 보정이 아니라 하네스의 스크롤을 재게 된다(실제로 -78px 로
  잘못 읽었다). `scrollIntoViewIfNeeded()` 뒤에 기준값을 잡을 것.
