`briefing.html` — **면접 준비 도구 허브(2026-07-22 배포 · 2026-08-05 코스형 전면 개편).** nav '승준노트'의 목적지.

## 이름 · nav

- **이름은 2026-07-30 오너 지시로 '브리핑룸'→'승준노트'.** ⚠️ **파일명·클래스명(`.nav-briefing`·`data-pillar="briefing"`)은 그대로 둔다** — 계측 기준선이 이어져야 하고 URL 을 바꾸면 밖에 나간 링크가 끊긴다. **화면에 보이는 글자만 바꿀 것.** 영문 라벨은 `MONC NOTE`.
- nav 는 **허브 하나만** 노출한다(뉴스·소재발굴을 각각 메뉴에 올리지 말 것 — 메뉴 줄이 수용하지 못한다). ⚠️ nav '승준노트'의 문구·하위 목록(`BRIEFING_SUB`)은 **`nav.js` 한 곳**에서 고친다(2026-07-30 공용화). **하위 목록 6개는 허브의 '내 입맛대로' 서클 6개와 같은 구성으로 맞춘다.**
- 메뉴 위치는 **2번**(챌린지 다음). 구 펄스 점(`bfPulse`)은 2026-08-03 삭제 — 되살리지 말 것(모집 0인 기간이 있어 '새 것' 신호의 근거가 없다).

## 화면 구조 — 코스형(2026-08-05 전면 개편)

오너 목업 4장에서 출발해 대화로 확정했다. 설계 문서: `docs/superpowers/specs/2026-08-05-briefing-course-hub-design.md`, 시안: `outputs/briefing-course-hub-mockup.html`.

**화면은 두 상태다.**

| 상태 | 조건 | 구성 |
|---|---|---|
| A 코스 선택 전 | 비회원 · 코스 미선택 회원 | 히어로 → 코스 카드 4장 → 코스 상세 패널 → 자유 선택 서클 6개 → 무료 맛보기 |
| B 코스 선택 후 | `members.course` 있음 | 개인화 헤더(이름·코스·기록 칩) → '오늘 이어서' 카드 → (서클·맛보기는 A와 같다) |

### 코스 4종

| 코드 | 이름 | 스텝 | 시간 줄 | '오늘 이어서' CTA |
|---|---|---|---|---|
| `beginner` | 비기너 코스 | 소재 발굴 → 필수 기출 → 초급 기출 | 하루 10~15분 | 답변 소재 발굴 |
| `practical` | 실전 코스 | 답변 첨삭 → 지원 항공사 뉴스 → 고급·심화 기출 | 하루 15~20분 | 답변 첨삭 |
| `spurt` | 스퍼트 코스 | 보신각·영합각 챌린지 → AI킬러 | 챌린지 기간에 집중 | AI킬러 |
| `daily` | 데일리 코스 | 뉴스 스크랩 → 필수 기출 | 하루 5~10분 | 뉴스 스크랩 |

- **코드명은 DB 체크 제약과 짝**(`20260805160000_member_course.sql`) — 이름을 바꾸려면 마이그레이션도 같이 고친다.
- ⚠️ **스텝은 '지금도 참인 경로'만.** 없는 기능·미출시 도구를 넣지 말 것.
- ⚠️ **챌린지 스텝은 모집 여부를 단정하지 않는다** — challenges.html 로 보내고 판단은 그 페이지가 한다(모집 0인 기간이 있다). 같은 이유로 스퍼트의 CTA 는 챌린지가 아니라 **AI킬러**다.
- ⚠️ 필수 기출은 아직 기출 30문항 미입력이다 — "한 달에 30개" 같은 약속 문구는 상품이 열린 뒤에 넣는다.
- 초급·고급 기출 스텝의 목적지는 `sojae.html` 그대로(난이도 고르는 화면이 먼저 나온다). 난이도 딥링크 파라미터를 새로 만들지 않았다.

### 코스 상세는 패널 하나를 재사용한다

카드를 누르면 **패널 하나의 내용만 바뀐다**(4개를 세로로 나열하지 않는다 — 모바일 길이 통제). 카드는 실제 `<button>` + `aria-expanded`/`aria-controls`, 선택 시 패널로 초점을 옮긴다(div+click 금지 원칙).

- ⚠️ **금액을 적지 말 것**(2026-08-05 오너 확정 — 시간만). 단가·잔액은 각 도구 페이지가 말한다. 여기에 숫자를 적으면 단가·팩 가격이 바뀔 때마다 두 곳이 어긋난다(목업의 '하루 1,500원'은 실단가와 달라 뺐다: 소재 2 + 킬러 3 = 5크레딧 ≈ 1,700원).
- ⚠️ **카드·서클에 회원별 상태 문구('첫 1회 무료' 등)·근거 없는 표시('인기'·'NEW')를 달지 말 것** — 2026-07-25·07-31 오너 기각분이 그대로 유효하다.

### 코스 저장 — 계정(`members.course`)

- 기기가 아니라 **계정**에 저장한다(폰에서 고르고 PC 로 들어와도 같은 화면).
- **첫 그리기는 기기 기억(`monc_course_v1`)이 정한다** — nav.js 의 로그인 기억과 같은 수법. 서버 확인(0.3~1초)을 기다렸다 켜면 코스를 고른 회원이 매번 A→B 뒤집힘을 본다. ⚠️ 이 기억은 그리기용일 뿐 권한이 아니다. supabase 토큰이 없으면(로그아웃) 기억도 지운다.
- **비회원이 [이 코스로 시작하기]** → `sessionStorage.monc_pending_course` 에 담고 `login.html?returnTo=briefing.html` → 돌아오면 저장하고 키를 지운다. ⚠️ sessionStorage 고정(localStorage 금지 — 공용 기기).
- 저장 성공 → `location.reload()`(입력값 없는 화면이라 부작용 없음, 상태 분기가 단순해진다).
- **저장 실패를 조용히 넘기지 않는다** — 마이그레이션 미적용이면 "지금은 코스 저장이 안 돼요"를 그 자리에 띄우고 A에 머문다(성공한 척 B로 넘어가면 다음 방문에 코스가 사라져 있다).
- 조회는 `select('*')`. ⚠️ 공용 `getMyProfile()` 셀렉트에 `course` 를 넣지 말 것(major·agreed_at 전례).
- '코스 바꾸기'는 **지금 쓰는 코스를 펴 놓고** 시작한다. 저장값은 새 코스의 [시작하기]를 누를 때만 바뀐다(안 고르고 떠나면 그대로).

### 기록 칩 — 사이트가 아는 사실만

`답변 N · 대화 중 N · 스크랩 N`. **0건·조회 실패인 항목은 아예 안 그린다**(빈 껍데기 금지 — 마이페이지와 같은 규칙). 자세한 기록은 마이페이지 링크로 넘긴다(마이페이지 '내 기록' 카드를 허브에 복제하지 않는다 — 두 화면을 같이 고쳐야 하는 유지비).

⚠️ **'대화 중'의 정의는 마이페이지와 같아야 한다** — 되묻기만 하고 답변 행이 없는 문제(`discovery_sessions` stage≠done, `answers` 에 있는 문제는 제외). 한쪽만 고치지 말 것.

### 실측값(2026-08-05)

- 375px: 카드 163×219 · 서클 105 · 코스 상세 437 · CTA 47 · 가로 넘침 0 · 12px 미만 활자 0.
- 320px: 카드 144×201 · 서클 93 · 넘침 0 · 잘린 글자 0.
- 데스크톱(1280px): **열 600px 중앙**(`main.container > section` 등에 `max-width:600px`) — 안 잡으면 760px 열에서 카드 355·서클 233 으로 부푼다. **서클 격자는 따로 420px 상한**(600px 열에서도 193px 이 된다).
- '코스 바꾸기' 버튼은 `line-height:20px` 를 적어야 44px 이 된다 — 버튼은 body 행간을 물려받지 않아 기본값(약 16px)으로 계산되면 40px 에서 멈춘다(실측).

### 사진

코스 카드 4장 전부 사진(오너 확정). **오너 제공 대기** — `COURSES[].photo` 에 경로를 넣으면 카드에 얹힌다. 비어 있으면 틴트 판 + 코드 글자(BEGINNER 등)로 성립하고, `aspect-ratio` 고정이라 사진이 들어와도 레이아웃이 흔들리지 않는다. 넣을 때 webp + 카드 크기에 맞는 해상도(전송량 예산).

### 검증 방법

로그인 상태는 실데이터로 확인이 어려워 **스텁 하네스**로 검증했다(마이페이지와 같은 방식): 외부 스크립트 3개를 가짜 `MONC` 로 치환한 `_tmp-briefing.html?course=…&nocol=1&anon=1` 을 만들어 A·B·저장 실패·비회원 pending 복귀를 375/320/1280px 실측(검증 후 임시 파일 삭제).
