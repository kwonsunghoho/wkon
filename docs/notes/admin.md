## DAY 문항 편집기 — 챌린지 셀렉트 (2026-09-04)

'승자각 DAY 문항' 접이는 `LES_CH = 'answer'` 로 고정돼 있었다. 대.문.각이 생기며 **챌린지 셀렉트**가
붙었다(`#lesCh` · `LES_CH_OPTS = ['answer','culture']`) — 접이 제목도 'DAY 문항 고치기'로 바꿨다.

- **문항을 표(`challenge_lessons`)로 관리하는 챌린지만 셀렉트에 넣는다** — 보신각·영합각·스피닝은
  주차 요약뿐이라 고칠 문항이 없다. 새 챌린지를 넣으면 셀렉트 `<option>` 과 `LES_CH_OPTS` 를 같이 고친다.
- ⚠️ **챌린지를 바꾸면 저장하지 않은 편집은 사라진다**(목록을 통째로 다시 그린다). 고친 뒤 [문항 저장]을 먼저.
- 대문각 10줄은 migration `20260904120000_culture_lessons`(오너 실행 대기) — 미적용이면 목록이 비어
  '심기 구문을 실행하세요'가 뜬다. 공개 화면은 HTML 폴백으로 멀쩡히 돈다.

### ⚠️ P1 — 조용히 데이터가 사라지던 것 셋
1. **연구실 자료 '가격 0' 이 저장되지 않았다.** `if (priceVal > 0) baseRow.price = priceVal`
   한 줄이 신규·수정 두 경로를 같이 막아서, **유료 자료를 무료로 되돌리면 옛 가격이 그대로
   남고 화면은 '수정했어요'** 라고 말했다. → 수정(update)에서는 0도 반드시 보낸다.
   (컬럼이 없는 환경은 update 가 에러를 내고 기존 안내 문구가 잡는다.)
2. **'충전 상품 저장'이 `credit_packs` 배열을 통째로 덮어썼다.** 화면은 `ai_killer` 팩 하나만
   읽어 편집하는데 저장은 배열 전체를 갈아끼웠다 — 팩이 둘 이상이면 나머지가 사라지고,
   verify-payment 가 같은 값으로 금액을 검증하므로 **그 상품 결제가 막힌다.**
   → 기존 배열을 읽어 `ai_killer` 만 교체. 그리고 **가격 0원 저장을 막았다**(`price < 1` 거부 —
   전에는 칸을 비우면 `Number('')||0` 이 0원 팩으로 저장돼 충전이 공짜가 됐다).
3. **일차 배치 편집기가 배치를 지웠다.** 후보 목록(`pool`)이 `active && 같은 항공사` 라
   **숨김 처리했거나 다른 항공사 기출이 배치된 일차는 `— 비움 —` 으로 보였고, 그대로
   [배치 저장]하면 실제 배치가 삭제**됐다. → 지금 배치된 기출은 후보 밖이어도
   `[지금 목록 밖]` 항목으로 만들어 selected 로 둔다. 지우기 실패도 이제 실패로 알린다.

### ⚠️ 화면이 '모른다'를 '없다'로 말하던 것
- **조회가 실패해도 '오늘' 브리핑이 "처리할 일이 없습니다"로 단정**했다(원칙 11).
  신청·오픈알림·회원 조회가 막히면 배열이 빈 채로 남아 숫자가 전부 0이 되고, 오류처럼
  보이지 않아 오너는 재시도하지 않는다 — 그날 입금 확인을 통째로 건너뛴다.
  → `_loadErr` 세 칸으로 실패를 기억하고, 하나라도 실패면 숫자를 `–` 로 두고
  **"오늘 현황을 불러오지 못했습니다" + [다시 불러오기]** 를 띄운다.
  ⚠️ 이 짝(로더의 `_loadErr[...] = !!error` ↔ loadToday 앞머리 분기)을 끊지 말 것.
- **`loadToday()` 가 초기화 때 딱 한 번만 돌았다.** 입금 3건을 다 처리하고 '오늘'로 돌아와도
  헤드라인이 3건 그대로였다. → 탭 전환 시 `today` 면 다시 센다(캐시만 읽으므로 비용 없음).
- **회원 조회는 `error` 를 통째로 버렸다** — 실패해도 '회원이 없습니다'로 뜨고,
  신청자 배지가 **전원 '비회원'** 으로 뒤바뀐다. → error 를 받아 목록에 사실대로 적는다.

### 동선 — 숫자를 눌렀으면 그 숫자의 목록이 나와야 한다
- 신청자 현황에 **입금 필터(`#afPay` 전체/미입금만)** 신설. '오늘'의 [입금 확인 필요]와
  [오픈 알림 연락 전]이 `data-focus` 로 그 필터를 켜고 이동한다(`activateTab(name, focus)`).
  ⚠️ **'미입금' 판정식은 `loadToday` 의 `unpaid` 와 같아야 한다**(`isLiveApplication && !appPaid`).
  한쪽만 고치면 카드 숫자와 목록 건수가 어긋나 화면이 거짓말을 한다.
  ⚠️ 메뉴로 apps 를 열면 필터는 초기화된다(initTabs) — 안 그러면 나중에 열었을 때
  3건만 보이고 "신청이 왜 이것뿐이지"가 된다. activateTab 이 그 뒤에 다시 걸므로 순서가 중요하다.
- **탭을 바꾸면 맨 위에서 시작한다.** 전에는 스크롤 위치가 그대로라 연구실 자료를 1200px
  내려 보다가 감점 사전을 고르면 그 탭 중간(745px)에 떨어졌다.
- **회원 목록에 기수를 적는다.** 배정이 이 화면의 주 작업인데 '미배정만'을 켜기 전에는
  누가 배정됐는지 알 수 없었다. 정렬도 **최근 가입 먼저**로 뒤집었다('오늘 새 회원'을 눌러
  들어갔는데 그 사람이 목록 맨 끝이면 지표가 행동으로 안 이어진다).

### 기본기 — admin 만 못 받고 있던 것
admin 은 **nav.css 를 안 읽는다(의도)**. 그래서 2026-08-02 에 공개 페이지가 받은 것이 여기만 빠졌다.
- **포커스 링**: 크로미움 기본 1px 주황(`#E59700` · 흰 면 2.2:1)만 나왔다 → nav.css 와 같은
  `outline: 3px solid var(--action); outline-offset: 2px`.
- **본문 바로가기(`.skip-link`)** + `#main`(=`.smain`, `tabindex="-1"`).
- **`:disabled`**: 회원 '배정' 버튼이 disabled 인 채로 채움 네이비 CTA 그대로였다(눌러도 무반응).
  ⚠️ opacity 로 흐리지 않는다 — 글씨 대비가 무너진다. 흰 면 + `--text-dim`.
- **`accent-color: var(--action)`**: 체크박스·라디오가 브라우저 기본 파랑이라 네이비 안에서 튀었다.
- **경계선 `--border-strong`**: `--border`(흰 면 위 1.38:1)를 입력칸·고스트 버튼·칩이 그대로
  쓰고 있었다(429곳). `--border-strong` 사용 0회였다 — 원칙 4의 신설 조항이 admin 에 한 번도 안 왔다.
  ⚠️ `--border` 자체는 올리지 않는다(카드·구분선까지 진해져 표처럼 보인다).
  ⚠️ `.is-danger` 는 이 규칙에서 제외하고, 대신 테두리를 `#B3261E` 제 색으로(전 `.5` 알파 = 2.47:1).
- **바텀시트 포커스 3종**: 열 때 안으로 · 뒤를 `inert` · 닫을 때 `#mtMenu` 로 복귀.
  ⚠️ 데스크톱(>960px)에선 사이드바가 덮개가 아니므로 포커스를 건드리지 않는다.

### '오늘' 숫자 = 2열 타일 (2026-08-02 · 오너가 목업 B안 확정)

5차 진단에서 "숫자 5줄의 구분선 대비·간격은 오너 확정 목업이라 손대지 않는다"고 남겼는데,
오너가 **"1면 목업은 한 번 더 정해야겠네"** 라며 다시 고르기를 요청했다. 네 안(지금 화면 /
A 할 일 먼저 / B 숫자 접기 / C 최소 수정)을 393px 목업으로 만들어 **B안 확정**.

| | 전(세로 5줄) | 후(2열 타일) |
|---|---|---|
| 첫 행동 버튼 위치 | 749px(첫 화면 밖) | **642px**(첫 화면 안) |
| 숫자 블록 높이 | 352px | 277px |
| '오늘' 전체 길이 | 1,605px | 1,498px |
| 같은 숫자 반복 | 3번 | 2번(제목 + 타일) |

- **칸은 6개**: 입금 확인 필요 · 오픈 알림 연락 전 · 검수 대기 · 오늘 신청 · 오늘 새 회원 · **전체 회원**.
  순서는 '돈 먼저' — 손댈 것이 남은 칸이 위, 그냥 보는 숫자가 아래.
- **`data-todo="1"` 칸만 빨강 강조**(`.tb-stat.todo` — 테두리 + 숫자 `#A33D14`).
  ⚠️ **값이 0 이거나 '–'(모름)이면 강조하지 않는다** — 할 일이 없으면 눈에 띌 이유가 없고,
  못 받은 값을 '급한 일'처럼 보이게 하면 원칙 11 위반이다. 판정은 `tdSet()` 안에 있다.
- ⚠️ **`minmax` 를 150px 이상으로 올리지 말 것** — 320px 화면에서 1열로 풀려 도로 길어진다
  (본문 여백 16×2 를 뺀 288px 에 132×2+8 이 들어간다). 실측: 320px → 140px 2열, 데스크톱 우측 단 → 174px 2열.
- **리드 문장(`#tbLede`)은 정상 화면에서 접는다.** 바로 아래 타일·'지금 처리'가 같은 숫자를
  다시 말하는 줄이었다. ⚠️ **요소는 지우지 말 것** — 조회 실패 안내가 이 자리를 쓴다.
- **전체 회원 수는 독립 칸**이다. 하루 전 버전은 '오늘 새 회원'의 보조 문구(`#tdMembersTotal`)에
  얹었는데, B안에서 칸이 생기며 `#tdMembersAll` 로 옮겼다. 구 id 는 사라졌다.
- 새 숫자 칸을 만들면 **`TD_CARDS` 배열에도 넣는다** — 조회 실패 화면에서 같이 '–'로 비운다.
- 구 `.tb-stat.zero { opacity:.55 }` 는 칸 전체를 흐리게 해 글자 대비까지 무너뜨렸다(원칙 4) →
  숫자 색만 흐리게.
- 검증(실측): 320·393·1280px 전 탭 — 12px 미만 활자 0 · 44px 미만 0 · 겹침 0 · 넘침 0 · 콘솔 0.
  0건·'–' 상태에서 강조가 풀리는 것까지 확인.

### 회원 3천 명 대비 — 1000행에서 조용히 잘리던 것 (2026-08-03 · 오너 "2~3천명이 되어도 문제 없나")

**Supabase 는 한 번에 최대 1000행만 돌려주고, 넘으면 아무 말 없이 잘라 준다.** admin 은 그 배열로
숫자를 세기 때문에 잘리는 순간 **화면 전체가 같이 거짓말을 한다.** 실측(목 3,000명·1,500건):

| | 전 | 후 |
|---|---|---|
| 회원 조회 | 3,000명 중 **1,000명** | 3,000명 |
| '전체 회원' 숫자 | 1,000 | 3,000 |
| 1000명 밖 회원의 신청 배지 | 전부 '비회원'(거짓) | 정상 |
| 크레딧 탭 여는 시간 | **968ms**(DOM 32,883) | **32ms**(DOM 3,886) |

- **`fetchAll(build)`** 하나로 모았다 — `range()` 로 1000행씩 끝까지 받는다.
  적용: `members` · `applications` · `challenge_waitlist` · `reviews` · `credit_ledger` · `lab_downloads`.

  ⚠️ 조건(검색·필터)이 바뀌면 표시 수를 `_mShown`/`_aShown`/`_credShown` 처음으로 되돌린다 —

  일괄 배정은 전부에 걸린다 — 그래서 목록 꼬리에 '몇 명 중 몇 명'을 같이 적는다.

### 회원 상태 배지·필터 (2026-08-03 · 오너 "번호 없는 사람·이상한 사람을 갈라 놓자")

회원 목록에 이름·이메일·기수만 있어서 **누가 연락 가능한 사람인지 구분할 방법이 없었다.**
행에 상태 배지를 붙이고 상태 필터 칩 6개를 뒀다(구 '미배정만' 체크박스는 '기수 미배정' 칩이 대신한다).

| 필터 | 뜻 |
|---|---|
| 가입 미완료 | 번호 없음 — 로그인은 했고 이름·번호 넣는 화면에서 나간 사람 |
| 번호 확인 필요 | 번호는 있는데 형식이 안 맞음(유선·자릿수 오타) |
| 기수 미배정 | `cohort_id` 없음 |
| 신청 있음 | 챌린지·특강 신청 이력이 있음 |
| 흔적 없음 | 번호 없음 + 신청 0 + 크레딧 사용 0 + 가입 30일 경과 |

- ⚠️ **번호 판정은 `phone-check.js` 를 그대로 쓴다**(admin 에 스크립트를 추가했다).
  여기서 정규식을 따로 만들면 "가입은 통과했는데 admin 만 이상하다고 하는" 번호가 생긴다.
- ⚠️ **'흔적 없음'은 보수적으로 센다.** 신청·크레딧 원장을 아직 못 읽었으면 **아무도** 흔적 없음으로
  치지 않고 머리글에 '확인 중'을 띄운다. 모르는 것을 '없다'로 말하지 않는다(원칙 11).
  회원 목록은 초기화 순서상 신청·크레딧보다 먼저 그려지므로 **`loadCredits()` 끝에서 다시 그린다.**
- ⚠️ **삭제 버튼을 만들지 않았다.** `members` 행만 지우면 `auth.users` 가 남고, 회원 행은
  **첫 로그인 때 한 번만**(`on_auth_user_created`, after insert) 생기므로 그 사람이 다시 로그인해도
  프로필이 복구되지 않는다. 제대로 지우려면 `auth.users` 를 지워야 하고 그러면 `on delete cascade` 로
  크레딧·답변·세션·이용권까지 함께 사라진다. 접이 안내에 이 사실을 적어 두었다 — **지우는 곳은 콘솔이다.**
- ⚠️ **성능**: 신청 건수를 회원마다 `_apps` 를 훑어 세면 3,000 × 1,500 = 450만 번이라 렌더 한 번에
  **2,333ms** 가 걸렸다(실측). 검색은 글자마다 렌더하므로 그대로는 못 쓴다.
  `buildAppIndex()` 로 렌더 시작에 색인을 한 번 만들어 **16ms** 로 내렸다.
  ⚠️ 색인은 `member_id` 가 있으면 그쪽에만 센다 — 두 map 을 더하면 같은 신청이 두 번 세어진다.
- `credit_ledger` 도 `fetchAll` 로 옮겼다 — 무료 사용 한 번마다 한 줄이라 **가장 빨리 1000행을 넘긴다**
  (잘리면 잔액이 틀린다).

- **'오늘 · 최근 신청' 행에 키보드 접근** — `role="button"`+`tabindex`+**Enter/Space 위임**까지 한 벌.
  ⚠️ role·tabindex 만 붙이면 포커스는 가는데 안 열린다.
- **후기 카드 메타 5칸 전부 라벨**(종류·챌린지·기수·이름·한줄평)과 **글 후기 '받은 날짜'** 라벨.
  ⚠️ `title` 은 아이폰에서 안 뜬다 — 라벨 대용으로 쓰지 말 것.
- **행 버튼 간격 데스크톱도 6→8px**(원칙 2). 이 줄엔 '삭제'가 끼어 있다.
- **'삭제됐어요' → '삭제됨'** 통일.

**오탐으로 판정한 것**: `.lf-slot` 6열 그리드가 '삭제' 버튼을 삼킨다는 지적 — 실측 결과
데스크톱 818px 에 6열이 다 들어가고(넘침 0), 393px 에선 2열로 접힌다. 이미 `min-width:0` 정비가
끝난 자리다.

### 모바일 네비 = 상단 바 + 바텀시트 (2026-08-01 · 오너 "네비를 크게 바꾸는거 해봐")
칩 1줄 가로 스크롤(2026-07-31)을 폐기하고 **상단 바(.mtop: 로고·관리자 배지·현재 화면 이름 + '메뉴' 버튼) + 바텀시트**로 교체했다. 칩 12개 가로 스크롤은 그룹 경계가 안 보이고 뒤쪽 탭이 눈에 안 띄는 문제가 컸다. 시트는 운영/상품/콘텐츠 3그룹 12개를 2열 그리드로 한 화면에 보여준다(뉴스 필터 바텀시트와 같은 문법). 아이콘도 시트에서 유지 — 데스크톱과 같은 지도.

- **열림 제어는 `body.navopen` 하나**: 메뉴 버튼 토글·스크림(.mscrim) 탭·Esc·✕·항목 선택 전부 `navSheet()` 경유. 열려 있는 동안 body overflow:hidden. z-index: mtop 9 · 스크림 39 · 시트 40 · 토스트 50.
- ⚠️ **#tabs 인라인 display 는 '비운다'** — revealAdmin 이 `style.display = ''` 로 지우고, 레이아웃(데스크톱 flex 세로 / 모바일 grid 시트)은 CSS 가 정한다. 인라인에 'flex'/'block' 을 넣으면 모바일 시트 그리드가 죽는다. **2026-07-31 절의 "인라인 'flex'" 규칙은 이 개편으로 폐기.**

### 후기 탭 — 챌린지별 건수 요약(`#rvChSum`) (2026-08-02)
챌린지 상세(`challenge-*.html`)의 후기 섹션은 `reviews.challenge` 로 골라 담는데, **'여러 장 한번에' 업로드는 이 값을 안 채운다.** 그러면 상세 페이지는 섹션을 `hidden` 으로 두고 조용히 넘어가서, 어드민만 보고 있으면 "후기를 올렸는데 왜 안 뜨지"가 된다. 그래서 종류 필터 바로 아래에 **노출(visible)·챌린지 지정된 건수를 챌린지별로** 찍는다 — 0이면 그 상세엔 섹션이 없다는 뜻. 미지정 건수는 빨간 글씨로 따로 센다.
- **집계 기준은 `challenge-reviews.js` 의 조회 조건과 같아야 한다**: `kind==='challenge'`(null 은 challenge 로 간주) + `visible` + `challenge` 일치. 한쪽만 고치면 숫자가 거짓말을 한다.
- 챌린지 이름 네 글자는 `RV_CH_OPTS` 상수 하나로 모았다. **이 문자열은 각 상세의 `data-challenge` 와 정확히 같아야 한다**(현재 `보신각`·`영합각`·`스피닝`·`승자각`). 어느 한쪽 이름을 바꾸면 매칭이 조용히 끊긴다.
- 종류·챌린지 드롭다운을 바꾸면 **행만 메모리에서 갱신하고 요약만 다시 계산**한다(`patchRow`). 통째로 `loadReviewsAdmin()` 하면 스크롤이 맨 위로 튄다.

### 목록 행은 모바일에서 1열로 — 버튼 줄은 `.ri-actions` 로만 (2026-08-01 실사고 · 오너 "이런식으로밖에 못하냐")

### 연구실 자료 탭 — 저장 버튼 글자는 `labSyncLabel()` 로만 바꾼다 (2026-08-04)

- 검증(2026-08-04 · 검사대 8건 전부 통과): `admin.html` 에서 `guardSubmit` + 라벨 블록을 **슬라이스해**

### 3차 — 날짜 칸이 격자를 뚫고 옆 요소를 덮던 건 (2026-08-02 · 오너 "아직도 박스가 튀어나오고 정렬이 안 됐는데?")

2차 정비를 하고도 오너 화면(챌린지 탭)에서 **모집 시작·마감 칸이 삐져나오고 '추가/수정' 버튼이
'프로그램 시작' 입력 위에 올라타 있었다.** 내 검사가 놓친 이유가 분명하다.

- **잰 것**: 페이지·패널의 `scrollWidth − clientWidth`(가로 넘침) → **0 이었다.**
- **안 잰 것**: **요소끼리 겹치는지.** 칸이 트랙을 넘쳐도 페이지 폭은 안 늘어난다.
  넘친 칸은 옆 칸 *위로* 올라탈 뿐이라 넘침 검사에 안 걸린다.
- 게다가 **크로미움의 `input[type=date]` 는 min-content 폭이 좁아** 트랙에 들어간다.
  사파리의 날짜 컨트롤은 **약 168px 아래로 안 줄어든다.** 눈검사로도 크로미움 측정으로도 못 잡는다.

**원인**: `.round-form { grid-template-columns: repeat(auto-fit, minmax(120px,1fr)) }` 의 트랙은
393px 화면에서 158px, 데스크톱에서도 127px 다. 그리고 **그리드 칸의 기본 `min-width` 는
`min-content`** 라 안에 든 것이 크면 칸이 트랙을 넘친다.

**고친 것**
- `.round-form > *`·`.field` 에 **`min-width:0`**, 입력에 `min-width:0; max-width:100%`
  → 어떤 컨트롤도 자기 칸 밖으로 못 나간다. **지우지 말 것.**
- **`.field-date { grid-column: span 2; min-width:170px }`** — 날짜 칸은 두 트랙을 쓴다.
  ⚠️ 새 날짜 입력을 만들면 감싸는 `.field` 에 **`field-date` 를 같이 단다**(현재 8곳).
- 모바일에서 `.round-form > button[type=submit]` 은 **한 줄 전체**. 필드 옆 칸에 끼어 있어서
  오너 화면의 '추가/수정'이 옆 입력을 덮었다.
- 삭제 버튼 전부 `.is-danger`(빨강 #B3261E · 흰 배경 대비 6.54:1) — 2차엔 연구실 자료 한 곳만
  했었다. 지금은 12곳(오픈 알림·챌린지·특강·크레딧·후기·수기·소재·감점·기출·이용권·파일·시간대).
- 목록 줄이 `모집 undefined ~ undefined` 를 찍던 것 → `미정`(원칙 11 — 모르는 걸 단정하지 않기).

### 검사에 추가한 것 — 겹침 검사(overlap.mjs)
탭마다 **실제 조작요소끼리** 사각형이 겹치는지, **자기 `.field` 밖으로 나갔는지** 본다.
`12개 탭 × 6폭(320·375·393·430·768·1280) × 2모드`.
- ⚠️ **`.field` 같은 래퍼끼리 비교하면 안 잡힌다** — 입력칸이 래퍼를 넘쳐도 래퍼끼리는 안 겹친다
  (첫 판을 그렇게 짜서 '이상 없음'이 나왔다). **input·select·button 을 직접** 비교할 것.
- ⚠️ **닫힌 `<details>` 안의 요소는 제외**한다. `content-visibility:hidden` 이라 그려지지만
  않을 뿐 좌표는 그대로여서 겹침으로 잘못 잡힌다(답변 프로그램 4건 오탐).
- ⚠️ **iOS 폭 재현 모드**를 같이 돌린다: `input[type=date]{min-width:168px}` 를 주입한다.
  크로미움 기본으로만 돌리면 이 버그가 통과한다.

### 4차 — 날짜 입력이 카드를 뚫던 진짜 원인 (2026-08-02 · 오너 세 번째 지적)

3차에서 `.field-date { grid-column: span 2 }` 로 칸을 한 줄 전체(327px)로 넓혔는데도
**오너 화면에서 날짜 박스가 여전히 카드 밖으로 약 20px 나갔다.** 칸 문제가 아니었다.

**증거가 스크린샷에 있었다**: 날짜 칸만 **회색 민짜 박스**로 보였다. 옆의 '기수'는 흰 배경 +
테두리인데 날짜만 다르다 — **우리가 준 배경·테두리가 안 먹고 있었다는 뜻**이다.
iOS 사파리는 `input[type=date]` 를 **네이티브 컨트롤**로 그린다. 네이티브 위젯은 우리 스타일을
무시하고 **자기 고유 크기로 폭을 정하며, 우리가 준 padding 이 그 밖에 붙는다**(그래서 초과분이
정확히 좌우 padding 20px 였다). `width:100%`·`max-width:100%`·`min-width:0` 를 다 줘도 소용없다.

**고친 것 — 네이티브에게 크기 결정권을 주지 않는다**
```
.smain input[type="date"] { -webkit-appearance:none; appearance:none; box-sizing:border-box;
  max-width:100%; min-width:0; background:#fff; border:1px solid var(--border); text-align:left; }
.round-form input[type="date"], .field input[type="date"] { width:100%; }
```
- ⚠️ **`appearance:none` 을 지우지 말 것.** 이게 이 버그의 실제 수정이다.
- ⚠️ 탭하면 **날짜 피커는 그대로 열린다** — 그리기만 바뀌지 동작은 그대로다.
- ⚠️ `width:100%` 는 **격자 칸 안의 날짜에만** 준다. 후기 탭 `#rvTextDate` 는 flex 줄에 끼어
  있어 100% 를 주면 옆 입력을 밀어내고 혼자 한 줄을 먹는다(한 번 그렇게 만들었다가 되돌렸다).
- 마지막 안전장치로 `.round-form { overflow-x: clip }` — 무엇이 됐든 카드 밖으로는 못 그린다.
  `hidden` 이 아니라 `clip` 이라 스크롤 컨테이너가 안 생기고 세로 포커스 링이 안 잘린다.
  ⚠️ 이건 **backstop 이지 수정이 아니다** — 겹침 검사는 여전히 rect 로 재니 가려지지 않는다.

### ⚠️ 이 컨테이너에는 사파리 엔진이 없다 — 세 번 놓친 진짜 이유
playwright 의 `webkit` 은 설치돼 있지 않고, 프록시가 다운로드를 막는다(403 host not permitted).
크로미움만으로는 **네이티브 폼 컨트롤이 얽힌 버그를 구조적으로 못 잡는다** — date 입력이 그랬고,
하단 고정바 잘림·체크박스 라벨 겹침도 같은 부류였다.
- 그래서 **네이티브 위젯이 관여하는 자리는 '재현해서 고친다'가 아니라 '네이티브에게 결정권을
  주지 않는다'로 간다** — `appearance:none`, 줄 나누기, 명시적 박스 모델.
- 오너 스크린샷에서 **우리 스타일이 안 먹은 흔적**(배경색·테두리가 다름)을 먼저 찾는다.
  그게 '네이티브가 그리고 있다'는 신호이고, 그 순간 폭 계산도 우리 것이 아니다.

### 챌린지 탭 — 승자각 DAY 문항 편집 (2026-08-24 오너 "고칠 수 있게 해줘 빨리")

문항이 **HTML 세 곳에 손으로** 적혀 있었다(`challenge-answer.html` 커리큘럼 · `apply.html` 커리큘럼 요약 ·
`mypage.html` `ANSWER_DAYS`). 한 곳만 고치면 화면마다 다른 문항이 뜬다. 표 하나(`challenge_lessons`)를 정본으로 세웠다.

- **자리**: '챌린지' 탭, 모집일정 목록 **아래** 묶음(`#lesWrap`). 탭을 새로 만들지 않았다.
  **묶음 전체도 접이(details·기본 닫힘)** — 닫히면 '▸ 승자각 DAY 문항' 한 줄(2026-08-24 오너 "전체도 접히게").
  ⚠️ 새로고침 버튼을 summary 안에 두지 말 것 — 누를 때마다 접이가 같이 토글된다(그래서 저장 줄에 있다).
- **한 줄 = 한 DAY, 접이(details)**: 닫힌 머리는 `DAY n + 문항 이름`, 펼치면 문항 이름 · 설명 한 줄(상세 페이지 전용) 두 칸(2026-08-24 오너 "아코디언으로").
  이름 입력을 고치면 접이 머리가 실시간으로 따라간다. **닫혀 있어도 입력칸은 DOM 에 있다** — [문항 저장]의
  수집·바뀐 줄 판정은 접힘 상태와 무관하게 열 줄 전부를 본다. 접이 무늬는 sfold/mfold 와 같은 ▸/▾.
  저장은 **[문항 저장] 하나로 일괄** — 줄마다 버튼을 두지 않았다(열 줄을 한 번에 손보는 화면이다).
- **⚠️ '이렇게 써도 같은 문항으로 봄' 칸(작성 판정 낱말)은 2026-08-24 폐지**(오너 "기능 없애버려 헷갈려").
  판정이 사라진 게 아니라 **문항 이름에서 스스로 만든다**(mypage `wordsOf()` — '장점/단점' → ['장점','단점']).
  DB 컬럼 `match_words` 도 `20260824160000` 으로 지웠다. **낱말을 손으로 적는 칸을 다시 만들지 말 것.**
  대신 좁아진 것: 문항 이름과 아예 다른 제목('협업 경험' → 팀워크, '마지막으로 하고 싶은 말' → 마지막 할 말)은
  이제 못 잡는다. 번호('DAY 3')나 문항 이름이 제목에 있으면 잡힌다.
- **바뀐 줄만 update 한다** — 안 고친 줄까지 보내면 `updated_at` 이 전부 오늘로 바뀐다. 안 바뀌었으면 '바뀐 게 없어요'.
- **degrade**: 표 미생성이면 `#lesWrap` 을 통째로 숨긴다. 세 화면은 HTML 에 적힌 문항으로 그대로 돈다.
- **읽는 쪽 규칙**: 세 화면 모두 **HTML/JS 에 적힌 10줄이 폴백이자 검색엔진용**이다 — **지우지 말 것.**
  조회 실패·0줄이면 덮어쓰지 않는다. `apply.html` 은 `renderCards()` **앞에서** 부른다(다시 그리면 클릭 리스너가 날아간다).
- **⚠️ 순서를 섞지 말 것**(화면에도 적어 뒀다). mypage 작성 판정이 **DAY 번호 우선**이라, 순서를 바꾸면 학생이 이미 쓴

### 신청자 현황 — 무료(재학생) 처리 (2026-08-11 오너 확정)

재학생은 챌린지를 무료로 참여시킨다. **"냈다가 돌려주는" 흐름(결제 후 환급)은 폐지** — 돈이 안 움직이는

  보증금·환급 문구로 PG 심사에서 거절당한 전례도 있다. 재학생은 신청만 하고 입금을 안 하도록
  오너가 직접 안내하고, admin 에서 그 건을 무료 처리한다.
- **원장은 `applications.payment_status='free'` 하나.** 계좌이체(비 PG) 건의 토글 줄에
  [무료(재학생)] 버튼 — 신청자 현황·회원 상세 두 곳, 켜고 끄기 가능(끄면 'pending' 복귀).
  boolean 컬럼이 아니므로 공용 `data-field` 업데이트에 태우지 말 것(두 핸들러 다 분기 있음).
- **미입금 판정 두 곳(`appIsUnpaid`·loadToday 의 `unpaid`)이 같이 `!appFree()` 를 본다** — 한쪽만
  고치면 '오늘'과 필터 숫자가 갈린다(기존 경고와 같은 쌍). CSV 입금 칸은 '무료', '오늘' 최근 신청
  배지도 '무료', 회원 상세 요약엔 '무료(재학생)' 배지.
- mypage '내 신청내역'은 `payment_status==='free'` 를 **'무료 참여'** 로 보여준다(입금대기로 두면
  재학생 화면에 빨간 미입금이 영원히 남는다).
- `payment_status` 는 CHECK 제약 없는 text 라 'free' 추가에 마이그레이션이 필요 없다.
- **[무료 재등록] 버튼(2026-08-24 오너 "무료를 만들기 전에 환불해준 애들은 마이페이지에서 메뉴가 안뜬다")** —
  전액 환불된 신청 줄의 텍스트 동작 자리(블랙 왼쪽·`.apl-freebtn`)에 뜬다. 누르면 **환불 행은 그대로 두고**

## 소재 문제 삭제 가드 (2026-08-19)

`questions` 삭제는 FK `on delete cascade` 로 그 문제의 **학생 대화(discovery_*)와 저장 답변(answers)까지 지운다.** 삭제 버튼은 먼저 걸린 answers 수를 세서 "학생 답변 N개가 함께 삭제됩니다"를 confirm 에 띄우고, 있으면 [숨기기]를 권한다. 카운트 조회가 실패하면 0이라 단정하지 않고 "확인하지 못했다"고 말한다. **이 가드를 지우거나 confirm 을 건너뛰지 말 것** — 소재발굴 저장 유실 신고(2026-08-19)의 원인 후보였다.

## 회원 상세 — 일차 입력 폐지 · 챌린지 제출물 패널 (2026-08-20)

챌린지 산출물이 학생 직접 업로드(mypage `#chSubs` · `challenge_submissions`)로 바뀌면서 회원 상세도 같이 정리했다. 상세는 mypage.md '챌린지 처음/끝' 절과 스펙(`2026-08-20-challenge-before-after-design.md`) 참조.

- **'날짜별 미션 (1~14일)' 패널·배선 삭제** — `daily_records` 는 더 이상 조회·입력하지 않는다(표·데이터는 보존 — 마이그레이션에 drop 없음). 요약 스탯의 '미션 N/14일' 줄도 '제출물 N건'으로 교체.
- **'챌린지 제출물 (처음/끝)' 패널 신설**(`#chSubsEdit` · 접이) — **확인(재생) 전용.** 칸은 이 회원의 신청 챌린지(특강 제외) ∪ 이미 올라온 제출물. 보신각·스피닝=음성, 영합각=영상. 승자각은 파일이 아니라 답변노트 패널에서 확인. ⚠️ **admin 대리 업로드 칸을 다시 만들지 말 것** — 같은 날 오너 확정 *"직접 업로드하게끔 회원가입을 유도해. 내가 대신 올려주는 건 없어"*(1차 구현의 업로드 칸을 그날 걷어냈다). apply 의 로그인 유도 문구 강화가 같은 결정의 짝이다(signup-banner·guestNudge — apply-and-payment 영역).
- **신청 카드 [이 회원에 연결]**(member_id 없는 신청에만) — 비회원 신청을 가입한 계정에 잇는 버튼(`applications.member_id` update·confirm 후). 연결하면 학생 마이페이지에 신청 내역·제출 칸이 열려 **학생이 직접** 올린다. 전화 일치는 기존 '○ 전화매칭' 배지로 확인하고 누른다.
- **degrade**: `challenge_submissions` 미생성이면 패널에 '마이그레이션 적용 전' 한 줄(단정 금지 원칙).
- legacy 'Before / After 음성' 패널(회원당 한 쌍·`recordings`)은 **데이터가 있을 때만 + 확인 전용**(업로드 칸 제거 — 위와 같은 결정).


## 신청자 현황 — 제출 링크 패널 (2026-08-24)

오너 *"내가 매번 링크를 저장해 놓을 수 없잖아? 각 챌린지 신청현황 아랫쪽에 링크좀 넣어 주면 좋아보이거든?"*

- **챌린지 범위 탭(보신각·영합각·스피닝·승자각)을 고르면 목록 맨 아래에 `.sublink` 패널**이 뜬다 — `submit.html` 공유 주소(mypage.md 'submit.html' 절이 원장) + [복사] 네모 버튼(`.ad-sq`).
  전체·특강·자료 탭에는 안 그린다(`chSubmitLinksHtml` 이 `isChKind` 로 거른다). **신청 0명이어도 그린다** — 새 기수 시작날이 바로 링크가 필요한 날이다.
- 줄 구성: 파일 챌린지는 '시작 · 첫날'(`?ch=X&t=before`)·'끝 · 마지막 날'(`?ch=X&t=after`) 두 줄, **승자각은 '문항 쓰기'(`?ch=answer`) 한 줄**(처음/끝 개념이 없다 — DAY 문항 목록).
- **주소는 `SUBMIT_BASE`(https://monc.ai.kr) 하드코딩** — admin 을 어디서 열든 학생에게 줄 링크는 라이브 도메인이어야 한다(`location.origin` 으로 바꾸면 로컬 프리뷰에서 localhost 주소가 복사된다).
- 복사는 `navigator.clipboard.writeText` → 실패 시 textarea+execCommand → 그래도 안 되면 prompt 로 주소를 보여준다. 성공 토스트 '링크를 복사했어요'(기존 `toast()`).
- 검증(2026-08-24 스텁 실측): 스피닝 탭 두 줄·승자각 한 줄·전체 탭 없음·클릭→토스트, 375px 콘솔 에러 0. ⚠️ 스텁은 `window.MONC = {…}` 통째 교체가 아니라 **`Object.assign(window.MONC, {…})`** 로 덮는다 — 통째로 바꾸면 `isLiveApplication`·`programKey` 같은 순수 도우미가 사라져 admin 초기화가 죽는다(실측).

오너 *"너무 정돈이 안되어있는 느낌"* → *"회원들을 나눠서 볼 수 있는 필터… 진성 고객이잖아?"*
→ *"대기업이나 시스템적으로 체계적으로 관리할 수는 없니?"*
스펙: `docs/superpowers/specs/2026-08-22-admin-members-crm-design.md`. 3단계로 나눠 넣었다.

### 무엇이 문제였나
셀렉트 하나에 기준이 다른 7개가 섞여 있었고(회원이 어떤 사람인가 / 내가 할 일 / 치워 둔 곳),
**이 사람이 언제 무엇을 했는지가 한 화면에 없었고**, **내가 아는 것을 적을 칸이 admin 전체에
한 곳도 없었다.** 분류는 되는데 관리가 안 되는 상태.

### 회원 현황 5단 (`memberTier()`)
**위에서부터 먼저 걸리는 것이 이긴다. 한 사람은 한 등급만 갖는다.**

| 등급 | 판정 |
|---|---|
| 고객 `pay` | 환불 안 된 입금·무료 신청 · `credit_ledger.reason='purchase'` · `program_enrollments` |
| 참여 `use` | 제출물 · 저장한 답변 · 크레딧 사용 |
| 관심 `warm` | 전화번호 있음 **또는 신청 이력 있음(미입금 포함)** |
| 가입만 `new` | 위 아무것도 없음 + 가입 30일 이내 |
| 흔적 없음 `ghost` | 위 아무것도 없음 + 30일 지남 (`GHOST_DAYS=30`) |

⚠️ **되돌리면 사람이 잘못 보관된다 — 두 자리:**
1. **`free_use` 는 delta 0** 이다(`20260725130000_credits.sql` check 제약). `delta<0` 만 '사용'으로
   보면 **무료 한도만 쓴 회원이 '흔적 없음'으로 떨어진다.** 판정은 `delta<0 || reason='free_use'`.
2. **'관심'의 '신청 이력'을 빼지 말 것.** 구 ghost 규칙이 `!apps` 였다 — 빼면 **번호 없이 미입금
   신청만 한 사람이 '흔적 없음'** 이 된다. 지워도 되는 계정이 아니라 받아야 할 돈이다.

⚠️ 판정 자료(`_appsLoaded`·`_credRows`·`_actReady`)가 다 오기 전에는 등급을 단정하지 않는다
(`tierReady()`). 목록 라벨도 분포도 '판단할 자료를 받는 중입니다…'로 둔다.

### 화면
- **사이드바 순서**: 검색 → 회원 보기(셀렉트 · optgroup 4묶음) → **회원 현황 분포** →
  조건 더 걸기(접이) → 목록 → 더 보기 → **일괄 바(고른 게 있을 때만)** → 기수 관리(접이).
- **분포(`#mDist`)는 읽기 전용이다.** 누르면 걸리게 만들지 말 것 — 고르기는 `#mFilter` 하나다.
  막대는 **최대값 기준 비례**다(보기 좋으라고 비율을 조작하지 않는다).
- **목록 행**: 이름 + **마지막 움직임(이름 줄 오른쪽)** / 이메일 / 기수 + **현황 라벨 하나**.
  배지 4개 난립을 없앴다. 예외는 '번호 확인 필요'(고쳐야 할 값이라 빨간 라벨을 하나 더).
  실측 12행 전부 88px.
- **'흔적 없는 계정' 3문단 설명은 그 값을 골랐을 때만** 뜬다(`#mGhostHelp`).
- **상세 순서**: 머리(`.mhead` — 등급·연락처·마지막 움직임) → 수치 4칸(신청·제출물·답변·**크레딧
  잔액**) → 신청 내역 → **활동 타임라인** → **메모·태그** → 접이 3(정보 고치기·제출물·답변노트)

  칸 옆에 붙어 흐름)로 되돌리지 말 것.

### 활동 타임라인 (`#mlogBox` · DB 변경 없음)
가입 · 신청 · 제출물 · 답변 · 크레딧 · 자료 받기를 시간순 한 줄로. 20줄 + 더 보기.
⚠️ **신청과 입금을 두 줄로 쪼개지 말 것** — `applications` 에 `paid_at` 컬럼이 **없어서**(실측)
두 줄이 같은 시각에 찍힌다. 한 줄에 입금 여부를 적는다.
⚠️ 못 읽은 갈래는 조용히 빼지 않고 패널 아래에 적는다(`.tl-miss`).

### 메모·태그 (`member_notes`·`member_tags` — 20260822170000)
**관리자 전용. 회원 본인도 못 읽는다** — RLS 는 `is_admin()` 하나뿐이고 `authenticated` 정책을
만들지 않는다. 상담 메모에는 회원에게 보이면 안 되는 판단이 들어간다.
⚠️ **내용은 개인정보다** — 값 insert 를 레포에 커밋하지 않는다.
태그 중복(23505)은 실수지 오류가 아니라 조용히 넘긴다. 메모 지우기만 확인을 붙인다.
관리자가 한 명이면 작성자 이름을 안 적는다.

### 조건 저장(세그먼트) (`member_segments` — 20260822180000)
`rule = {"all":[{k,op,v},…]}` — **AND 만.** OR·괄호를 넣지 않는다(넣는 순간 질의 편집기가 된다).
지원 키 6개(`COND_KEYS`): `tier`·`cohort`·`unpaid`·`noSub`·`idleDays`·`tag`.
`tier` 값은 현황 키(`pay`·`use`…)이지 한글 라벨이 아니다.
- **거르기는 브라우저가 한다.** 돈이 걸린 판정이 아니라 '목록을 어떻게 볼까'라 서버가 소유할 이유가 없다.
- ⚠️ **모르는 키를 조용히 무시하지 않는다** — 무시하면 명단이 실제보다 넓은데 화면은 조건이 다
  걸린 것처럼 보인다. 몇 개를 못 걸었는지 `#mSegWarn` 에 적는다.
- ⚠️ 손으로 조건을 바꾸면 셀렉트가 저장된 조건을 계속 가리키지 않는다(다른 조건이므로).

### 후속 조치 → '오늘' 탭
`followup` 켠 조건이 '지금 처리'에 인원수 한 줄로 오른다. 누르면 `focus='seg:<id>'` 로 회원 관리 탭이
그 조건으로 열린다.
- ⚠️ **기존 네 줄(입금→연락→검수→제보) 아래**에 붙인다. 돈이 먼저라는 순서를 바꾸지 말 것.
- ⚠️ `segFollowups()` 는 화면에 걸린 `_cond` 를 **건드리지 않고 되돌린다** — 세는 것과 보는 것은 다른 일이다.
- ⚠️ 자료가 없으면 줄을 만들지 않는다. 0명이라 적으면 "할 일이 없다"는 거짓말이 된다.
- 부팅 때는 **조건 표만** 받고(조회 1회), followup 켠 것이 있을 때만 회원 자료를 더 받는다.

### 조회 수
부팅 33 → **34회**(후속 조치를 안 켰으면). 회원 관리 탭을 열면 +4
(`challenge_submissions`·`answers`·`program_enrollments`·`member_tags`). 회원을 고르면 상세당 +3.

### degrade
새 표 3개가 없어도 나머지는 전부 돈다 — 메모·태그 패널만 안내 문구, '저장한 조건' 묶음만 숨김.
판정은 `PGRST205`. 목 프리뷰로 실측 확인(표 있음/없음 두 경우).

`memberFlags` 의 `noPhone`/`apps`/`ghost`(현황 5단이 대신한다 — 남은 것은 `badPhone` 하나).


## 신청자 현황 — 제출물 접이 (2026-08-24 오너 "제출 녹음본 바로 볼 수 있도록 아코디언으로, 각 챌린지 별로")

챌린지 탭(보신각·영합각·스피닝)의 신청 줄마다 접이(`details.apl-subs`) 한 줄 — 닫힌 머리는
'제출물 N/M', 펼치면 칸마다 날짜·기수와 재생기가 그 자리에서 뜬다. 회원 상세로 안 들어가고
신청자 명단에서 바로 듣는 게 목적.

- **⚠️ 2026-08-22 기각된 '챌린지·기수 아코디언 묶음'과 다른 것이다.** 그건 목록 자체를 묶는
  아코디언(기수가 쌓일수록 자람 — A안으로 폐기), 이건 **한 줄 안의 제출물** 접이. 목록 묶음으로
  되돌리지 말 것.
- 칸 구성은 회원 상세 제출물 패널과 같다(처음/끝, 스피닝만 첫날 ①·②·끝). 이름표는 둘이 같이 쓰는
  `chSubTypeLabel()` 한 곳 — 바꾸면 mypage·submit 도 같이 본다(세 곳 한 벌).
- **안 그리는 자리 셋**: 승자각·전체·특강·자료 탭(승자각은 파일이 없다 — 답변노트로 확인),
  비회원 줄(제출 계정이 없다 — '비회원' 태그가 사정을 말한다). 전화매칭 줄은 `phoneMemberMap()`
  (appMembership 과 같은 `\D` 정규화)으로 회원을 찾아 그린다.
- 제출 0건인 회원 줄은 접이 대신 '제출물 아직 없음' 한 줄(`.apl-subs-none`) — 빈 접이를 열게
  하지 않되, 안 냈다는 사실은 명단에서 보이게.
- **표는 챌린지 탭 첫 진입에 한 번**(`loadChSubs()` — `select('*')`), **서명 URL 은 펼칠 때만**
  (`wireSubsFolds()` 의 toggle — 명단 전체에 미리 받으면 요청이 줄 수만큼 나간다). URL 실패는

## 신청자 현황 — 특강 셀렉트가 화면을 뚫었다 (2026-08-28 오너 신고 "특강 박스 왜 저따구냐")

특강 탭에서 페이지 전체에 가로 스크롤이 생겨 폰 화면이 축소되어 보였다.

- **원인**: 셀렉트의 고유 폭은 **가장 긴 `<option>` 만큼**이다. `.af-select` 에 `max-width:100%` 가
  있었지만 부모 `.af-field` 가 내용 크기 flex 항목이라 그 100% 가 아무것도 못 막았다 —
  `에어부산 기업분석&자소서 항목 가이던스 (22명)` 옵션이 들어오자 `#afSub` 가 363px(가용 343px)로
  늘어나 화면을 뚫었다. 5차 진단(2026-08-02)의 '가로 넘침 0' 은 **짧은 목 데이터**로 재서 못 잡았다.
- **수정**: `.af-field { min-width:0; max-width:100% }` + `.af-select { text-overflow: ellipsis }`.
  flex 항목은 max-width 가 있어야 내용 크기 밑으로 줄어든다 — 자식 쪽 max-width 만으로는 안 된다.
  긴 제목은 말줄임(…) — 전체 제목은 펼친 옵션 목록과 아래 요약 띠(.apl-sum)에서 그대로 보인다.
- 같은 `.af-field` 를 쓰는 자리(오픈 알림 `#wlFilter` · 회원 `#mFilter` · 자료 셀렉트)도 같이 잡힌다 —
  자료 제목도 특강처럼 길어질 수 있는 자리였다.
- ⚠️ **목 데이터로 넘침을 잴 때는 실데이터만큼 긴 문자열을 넣는다** — 특강·자료 제목, 문항 제목이
