### 모바일 네비 = 상단 바 + 바텀시트 (2026-08-01 · 오너 "네비를 크게 바꾸는거 해봐")
칩 1줄 가로 스크롤(2026-07-31)을 폐기하고 **상단 바(.mtop: 로고·관리자 배지·현재 화면 이름 + '메뉴' 버튼) + 바텀시트**로 교체했다. 칩 12개 가로 스크롤은 그룹 경계가 안 보이고 뒤쪽 탭이 눈에 안 띄는 문제가 컸다. 시트는 운영/상품/콘텐츠 3그룹 12개를 2열 그리드로 한 화면에 보여준다(뉴스 필터 바텀시트와 같은 문법). 아이콘도 시트에서 유지 — 데스크톱과 같은 지도.
- **전환 규약 불변**: 시트 안 버튼도 데스크톱 사이드바와 같은 `.tabbtn` 그대로 — initTabs·activateTab 규약이 그대로 먹는다. initTabs 가 클릭 시 `#mtCur`(상단 바 제목) 동기화 + `navSheet(false)` 닫기를 같이 한다.
- **열림 제어는 `body.navopen` 하나**: 메뉴 버튼 토글·스크림(.mscrim) 탭·Esc·✕·항목 선택 전부 `navSheet()` 경유. 열려 있는 동안 body overflow:hidden. z-index: mtop 9 · 스크림 39 · 시트 40 · 토스트 50.
- ⚠️ **#tabs 인라인 display 는 '비운다'** — revealAdmin 이 `style.display = ''` 로 지우고, 레이아웃(데스크톱 flex 세로 / 모바일 grid 시트)은 CSS 가 정한다. 인라인에 'flex'/'block' 을 넣으면 모바일 시트 그리드가 죽는다. **2026-07-31 절의 "인라인 'flex'" 규칙은 이 개편으로 폐기.**
- 상단 고정부는 한 줄(약 62px) 유지 — "wrap 금지" 실측 교훈 그대로. 시트에서 `.sn-logo` 숨김(로고는 상단 바가 가짐), `.sn-me`(이름+로그아웃)는 시트 맨 아래 — 구 칩 줄에선 로그아웃이 스크롤 끝에 숨어 있었다.
- 검증(375px 실측): 열기/닫기(버튼·스크림·Esc) · 항목 선택 → 패널 전환+제목 동기화+시트 닫힘 · '오늘' data-goto 경유 activateTab 정상 · 가로 넘침 0 · 콘솔 에러 0 · 데스크톱 사이드바 회귀 없음(mtop·시트머리 display:none).

### 후기 탭 — 챌린지별 건수 요약(`#rvChSum`) (2026-08-02)
챌린지 상세(`challenge-*.html`)의 후기 섹션은 `reviews.challenge` 로 골라 담는데, **'여러 장 한번에' 업로드는 이 값을 안 채운다.** 그러면 상세 페이지는 섹션을 `hidden` 으로 두고 조용히 넘어가서, 어드민만 보고 있으면 "후기를 올렸는데 왜 안 뜨지"가 된다. 그래서 종류 필터 바로 아래에 **노출(visible)·챌린지 지정된 건수를 챌린지별로** 찍는다 — 0이면 그 상세엔 섹션이 없다는 뜻. 미지정 건수는 빨간 글씨로 따로 센다.
- **집계 기준은 `challenge-reviews.js` 의 조회 조건과 같아야 한다**: `kind==='challenge'`(null 은 challenge 로 간주) + `visible` + `challenge` 일치. 한쪽만 고치면 숫자가 거짓말을 한다.
- 챌린지 이름 네 글자는 `RV_CH_OPTS` 상수 하나로 모았다. **이 문자열은 각 상세의 `data-challenge` 와 정확히 같아야 한다**(현재 `보신각`·`영합각`·`스피닝`·`승자각`). 어느 한쪽 이름을 바꾸면 매칭이 조용히 끊긴다.
- 종류·챌린지 드롭다운을 바꾸면 **행만 메모리에서 갱신하고 요약만 다시 계산**한다(`patchRow`). 통째로 `loadReviewsAdmin()` 하면 스크롤이 맨 위로 튄다.
- 검증(375px 실측): 보신각 2·영합각 0·스피닝 0(숨김 1건 제외)·승자각 1·미지정 2 — 상담 후기와 숨김 후기가 안 세어지는 것까지 확인. 챌린지 변경 → 영합각 0→1·미지정 2→1, 종류 변경 → 승자각 1→0, 가로 넘침 0, 스크롤 유지, 콘솔 에러 0.

### 목록 행은 모바일에서 1열로 — 버튼 줄은 `.ri-actions` 로만 (2026-08-01 실사고 · 오너 "이런식으로밖에 못하냐")
`.round-item` 은 '본문 1fr + 버튼 auto' 2열 그리드다. **연구실 자료 행은 버튼이 6개**(수정·이력·가격·비밀번호·숨기기·삭제)라 375px 에서 버튼 열이 폭을 다 먹고 **제목이 한 글자씩 세로로 꺾였다.** 고침 두 가지:
- 모바일 보정 블록에 `.round-item { grid-template-columns: 1fr }` — 버튼 줄(과 상태 칩)이 본문 아래로 내려온다. 버튼 정렬은 데스크톱 오른쪽 / 모바일 왼쪽(`.ri-actions { justify-content }`).
- **행 버튼 묶음은 전부 `class="ri-actions"`** 로 통일(10곳). 인라인 `style="display:flex;…"` 로 만들면 모바일 규칙이 못 잡는다 — **행 버튼 컨테이너에 인라인 flex 금지.**
⚠️ **왜 첫 정비(아래 절)에서 못 잡았나: 스크린샷 탭 목록이 8개뿐이었다**(labfiles·waitlist·terms·questions 누락). 검증은 반드시 **`data-tab` 12개 전부** 돌릴 것 — 그리고 목 데이터가 빈 목록이면 행 레이아웃 버그는 안 보인다. **행이 그려질 만큼 목 시드를 넣고 본다**(연구실 자료가 빈 배열이라 이 사고를 놓쳤다 — 후기도 같은 이유로 `reviews: []` 였고, 2026-08-02 요약 작업 때 채웠다).

### 모바일(≤960px) UX 정비 (2026-08-01 · 오너 "모바일 어드민 UXUI 가 웹에 비해 너무 떨어진다")
왜 떨어졌었나: 셸 개편(2026-07-31)이 데스크톱 목업 기반이었고 모바일은 '칩 1줄로 접는' 수준이었다. 검증 기준도 '375px 가로 넘침 0'이라 통과해 버렸다 — 공개 페이지의 375px 우선 규칙이 admin 엔 사실상 적용되지 않았던 것. 이번에 고친 것(스타일 맨 아래 `@media (max-width: 960px)` 보정 블록):
- **입력 활자 16px(모바일만)**: iOS 사파리는 16px 미만 입력을 누르면 화면을 강제 확대하고 되돌리지 않는다. 폼이 많은 admin 에서 가장 큰 손실이라 모바일만 16px. 데스크톱 밀도는 그대로.
- **액션 버튼 44px+(모바일만)**: 수정·삭제·입금·환급·후기 버튼 등. `.af-chip`(38px 합의값)·`.tabbtn`(기본에 이미 44px)은 그대로.
- **본문 좌우 여백 16px 통일**: rounds/apps/reviews-wrap·`.main` — '오늘' 탭(today-wrap)과 같은 기준.
- **신청자 툴바 줄바꿈**: 검색이 한 줄 전체, 건수·새로고침·CSV 가 아랫줄(CSV 만 외따로 떨어지던 것 정리).
- ~~**칩 줄 그룹 라벨 복원**~~ (같은 날 저녁 네비 개편으로 칩 줄 자체가 폐기 — 위 절 참조)
- **'왼쪽에서 회원을 선택하세요' → '목록에서'**: 모바일(≤820px)은 목록이 위에 있다 — 방향을 박는 문구 금지(마크업 주석 있음). 선택 시 상세로 스크롤은 기존 selectMember 에 이미 있다.
- ⚠️ **[hidden] 짝 규칙 — 전 화면 버그 수정**: `.round-editing`(CSS display:flex)·`#lrEditBar`(인라인 display:flex)가 hidden 속성을 이겨 **'취소하고 새로 추가' 빈 바가 데스크톱·모바일 모두 항상 떠 있었다**(챌린지·특강·연구실 자료 3곳). 고침: `.round-editing[hidden], #lrEditBar[hidden] { display:none }` + lrEditBar 인라인에서 display 제거. **display 를 직접 주는 요소에 hidden 을 쓰면 [hidden] 짝 규칙을 같이 두고, 인라인 display 는 금지**(인라인은 CSS 로 못 이긴다). 검증: 수정 클릭→바+라벨 표시, 취소→숨김 실측.
- 검증법: requireAdmin·MONC.sb 목 사본(admin-preview.html — 커밋 금지)으로 375px·1280px 전 탭 스크린샷, 가로 넘침 0·콘솔 에러 0 확인.

### ⚠️ 다른 페이지의 클래스를 admin 에 가져다 쓰지 말 것 (2026-08-01 실사고)
연구실 자료 탭의 서가 필터를 `news.html` 의 `.nw-chip`·`.nw-filter-row` 로 만들었는데 **admin.html 에는 그 CSS 가 없다.** 클래스만 붙고 스타일이 하나도 안 먹어 선택 표시조차 없는 민짜 버튼 6개가 나왔다(오너: "UXUI 뭐냐?"). admin 은 인라인 `<style>` 한 벌로만 그려지므로 **admin 안에 정의된 클래스만 쓴다.**
**필터 칩의 정본은 `.apq-filter > .apq-flabel + .af-row > .af-chip`**(신청자 현황·기출 은행이 쓰는 것). 개수 배지는 칩 안에 `<b>` — `#apqFilter b, #lrShelfBar b` 규칙을 공유한다(칩 그룹을 추가하면 이 선택자에 id 를 더한다). 선택은 `.on`(네이비 배경+흰 글씨), 비선택은 흰 배경. 실측: 높이 38px · 간격 6px.
**새 UI 를 붙이기 전에 `grep -c '\.클래스명' admin.html` 로 정의 유무부터 센다.**

### ⚠️ 탭을 추가할 때 — id 접두사가 이미 쓰이는지 먼저 센다 (2026-08-01 실사고)
admin.html 은 **탭 11개가 한 파일에 있고 id 가 전역이다.** '연구실 자료' 탭을 `lf*`(lab file) 로 만들었다가 **특강 폼의 `lf*`(lecture form) 와 `lfTitle`·`lfAirline` 이 겹쳤다.** `getElementById` 가 먼저 나오는 특강 칸(빈 값)을 잡아, 제목을 멀쩡히 적어도 **"제목을 입력하세요"만 반복**됐다 — 오류도 안 나서 원인이 안 보인다. 자료 탭은 `lr*`(lab resource) 로 바꿔 해결.
**새 탭의 id 접두사를 정하면 `grep -o 'id="<접두사>[A-Za-z]*"' admin.html | sort -u` 로 충돌부터 확인할 것.** 현재 쓰는 접두사: `lf`(특강) · `lr`(연구실 자료) · `q`(소재 문제) · `t`(감점 사전) · `td`(오늘 브리핑) · `ap`(답변 프로그램).

### admin.html — 사이드바 셸 + '오늘' 브리핑 개편 (2026-07-31 · 오너 목업 ⑥ "① 페이퍼 데스크 × ⑤ 데일리 브리핑" 확정)
어드민 목업 6안 중 오너가 합본안을 확정("1안 골격 + 5안 신문 1면"). 2단 네비(아래 2026-07-30 절)를 **좌측 사이드바 셸**로 교체하고 '오늘' 탭을 **브리핑형**으로 재구성했다. 폰트는 사이트와 동일하게 SUIT 하나(오너 확인 — 목업의 명조는 시안용, 실구현은 `var(--serif)`=SUIT 800).
- **셸**: 데스크톱(>960px) = `body.authed .shell` 그리드(240px 사이드바 + 본문). ~~모바일(≤960px) = 셸이 block 으로 풀리고 사이드바가 **스티키 칩 1줄 가로 스크롤**~~ **(2026-08-01 폐기 — 모바일은 상단 바+바텀시트. 맨 위 절 참조.)** 그룹 구성(운영/상품/콘텐츠)과 **"탭 추가 시 그룹부터 정한다"** 규칙은 2026-07-30 확정안 그대로 — 사이드바에선 그룹이 라벨(`.sn-glabel`)이다.
- ~~**⚠️ `#tabs` 인라인 display 는 `'flex'`**~~ **(2026-08-01 폐기 — 지금은 revealAdmin 이 인라인 display 를 `''` 로 비우고 CSS 가 정한다. 맨 위 절 참조.)** `body.authed` 클래스가 데스크톱 2열 그리드를 켠다 — 지우면 사이드바 자리가 안 잡힌다.
- **탭 전환 규약은 그대로**: `.tabbtn[data-tab]` ↔ `#panel-*` + `activateTab()`. 그룹 줄(`.tgbtn`·`.tab-row`) 로직은 삭제됐다. ap 서브탭에 `.tabbtn` 금지 규칙 유지.
- **'오늘' 브리핑**: 헤드라인 문장·리드·'지금 처리' 브리프를 **전부 실측 숫자로만 생성**(오늘 신청·미입금·연락 전·검수 대기·새 회원 — 없는 사실을 지어내지 않는다). 숫자 스택은 우측 단(모바일에선 맨 위 — 오너 "모바일은 간결하게"), '지금 처리'는 입금→연락→검수 순(돈 먼저), 이름은 가장 오래 기다린 사람(`_apps` 최신순 정렬이라 마지막 원소). id(`td*`)·`tdSet()`·`loadToday()` 호출 시점(초기화 맨 끝) 규칙은 구 카드 시절 그대로다.
- **검증법**: 미러 서버에 requireAdmin·MONC.sb 를 목으로 바꾼 `admin-preview.html` 사본(커밋 금지)을 두고 확인했다 — 탭 11개 전환·회원/답변 프로그램 패널·모바일 375px(가로 넘침 0) 실측, 콘솔 에러 0.
- **⚠️ 진입은 '한 번에' 그린다(2026-07-31 후속 · 오너 신고 "깨지듯 뒤틀렸다가 로딩된다").** 개편 직후, 인증이 끝나기 전에 `panel-today` 가 **사이드바 없는 전체 폭**으로 먼저 그려졌다가 껍데기가 붙는 순간 레이아웃이 통째로 뒤틀렸다. 원인은 ① `.tab-panel.active` 가 처음부터 보이는 것 ② 껍데기 켜기(`revealAdmin()`)가 데이터 로드보다 앞에 있던 것. 고친 방식은 **짝 규칙 2개** — CSS `body:not(.authed) .tab-panel{display:none}` + 초기화의 `revealAdmin()` 을 **`loadToday()` 까지 끝난 뒤 `finally` 에서 한 번만** 호출(멱등, 8초 안전망 타이머 · 실패해도 켜서 흰 화면 방지). **둘 중 하나만 되돌려도 뒤틀림이 돌아온다.** 진입 로더는 `#loading`(스피너+중앙 정렬)이고, 내부 목록의 `.loading` 과 다른 규칙이니 섞지 말 것. 실측: 로딩 중 패널 폭 0 → 완성 후 단일 폭(중간 단계 0회), 데스크톱·375px 동일.
  - ⚠️ 대신 첫 화면까지 **조회 5개(기수→회원→신청→오픈알림→검수 count)를 순서대로** 기다린다. 신청 조회는 회원 전화 대조(`memberPhoneSet`)를 쓰므로 **`loadMembers()` 앞으로 병렬화하면 '회원/비회원' 배지가 틀리게 그려진다** — 순서를 바꾸지 말 것.

### admin.html — 2단 네비 개편 (2026-07-30 · 오너 "기능 나열만 있고 효율적인 동선이 아니다")
탭 11개 한 줄 나열을 **그룹 3개 × 2단 네비**로 재편. 1줄 = 그룹(언더라인 탭), 2줄 = 그 그룹의 화면(알약 칩) — 신청자 현황 종류 필터와 같은 문법.
- **그룹 구성(오너 사용 빈도 기준 — 매일 보는 것이 '운영')**: 운영(오늘·신청자 현황·오픈 알림·회원 관리·크레딧) / 상품(챌린지·특강·답변 프로그램) / 콘텐츠(후기 관리·감점 사전·소재 문제). ⚠️ **탭을 추가하면 어느 그룹인지부터 정할 것** — 맨 뒤에 이어붙이면 개편 전으로 돌아간다.
- **탭 이름 변경**: '모집일정'→'챌린지', '기출문제'→'소재 문제'(소재발굴 도구에 나가는 오늘의 문제 — 답변 프로그램의 '기출 은행'과 이름이 겹쳐 혼동되던 것). '홈 커뮤니티' 탭은 삭제(위 커뮤니티/후기 절 참조).
- **⚠️ 기출 은행의 자리는 '상품 > 답변 프로그램' 서브탭이 맞다(2026-07-30 오너 확정).** 개편 직후 오너가 "기출 넣고 세팅하는 게 콘텐츠에서 빠졌다"고 물었다 — 사라진 게 아니라 상품 탭 안에 있는 것. 콘텐츠 그룹 독립 탭으로 승격하는 안을 제시했으나 **오너가 지금 위치 유지를 선택**(기출 등록과 일차 배치가 한 화면이라 조립 작업이 편하다). 같은 질문이 또 나오면 위치 안내가 답이지 구조 변경이 아니다.
- **첫 화면 = '오늘' 대시보드**(`panel-today`): 입금 확인 필요(계좌이체 미입금·환불 제외) · 오픈 알림 연락 전 · 검수 대기(→review-desk.html 링크) · 오늘 신청 · 오늘 새 회원 + 최근 신청 5건. 숫자를 누르면 해당 탭으로(`activateTab()` — 탭 버튼 클릭 핸들러가 그룹 줄까지 동기화하므로 어디서 불러도 일관). ⚠️ **`loadToday()`는 초기화 시퀀스 맨 끝** — 카드가 `_apps`/`_wl`/`members`를 재사용해서 `loadApplications`/`loadWaitlist`를 `await`한 뒤에 돈다(추가 조회는 answer_sessions count 하나 — 미적용 환경은 try/catch로 0 표시).
- ~~**⚠️ `#tabs`를 켤 때 `style.display = 'block'`** — 구 `'flex'`를 그대로 두면 그룹 줄과 알약 줄이 **가로로 눕는다**(실측으로 잡은 회귀 — 인라인 스타일이라 CSS로 못 이긴다).~~ **(2026-07-31 폐기 — 사이드바 셸로 바뀌며 정반대가 됐다. 현행은 `'flex'`가 맞다. 위 2026-07-31 절 참조.)**
- **답변 프로그램 탭 안은 서브탭 6개**(`.ap-st`/`.ap-sec`: 기출 은행·프로그램·이용권·연구원·수정 코드·진행률) — 기출 89개 시점부터 6절 세로 나열이 한 스크롤에 안 담겨 분리. ⚠️ 서브탭에 `.tabbtn` 클래스를 쓰지 말 것(initTabs가 tabbtn 전부에 패널 전환을 건다). `.ap-sec[hidden]{display:none}` 가드 유지.

- 검증법: 로그인 게이트라 프리뷰로 바로 못 본다 — `requireAdmin`을 목으로 바꾼 사본을 서버 루트에 두고 확인(이 파일은 커밋 금지). ⚠️ 프리뷰 서버 cwd가 워크트리일 수 있다 — repo 루트 파일을 고쳤는데 반영이 안 보이면 `preview_list`로 서빙 디렉토리부터 확인할 것.

## admin 모바일 UX 정비 2차 (2026-08-02 · 오너 "어드민 페이지도 uxui 신경쓰라고했지?")

오너가 아이폰으로 '연구실 자료' 탭을 열고 지적했다. 재보니 **admin 은 공개 페이지가 받은
UX 작업을 사실상 못 받은 상태**였다. 393px 실측(12개 탭 전수).

| | 전 | 후 |
|---|---|---|
| 16px 미만 입력칸(iOS 확대) | **26개** | 0 |
| 44px 미만 조작요소 | **102개** | 0 |
| 24px 미만 체크박스(WCAG 2.5.8 AA) | 6종 | 0 |
| 첫 화면을 막는 안내문(연구실 자료) | 312px | 0(접힘) |

### ⚠️ 제일 뼈아픈 것 — 규칙은 있었는데 한 번도 안 먹었다
`@media(max-width:960px){ .smain input… { font-size:16px } }` 는 **2026-08-01 에 이미 넣었다.**
그런데 admin 의 입력칸 24개가 `style="…font-size:14px"` **인라인**을 달고 있어 클래스 규칙이
전부 졌다. 즉 "고쳤다"고 기록만 남고 화면은 그대로였다.
- 그래서 지금은 **`!important`** 를 붙였다(인라인을 이기는 유일한 길). 지우지 말 것.
- **교훈**: CSS 규칙을 넣었으면 **브라우저로 세어 본다.** '썼다'와 '먹는다'는 다르다.
  검사 스크립트는 탭을 하나씩 눌러 가며 `getComputedStyle` 로 개수를 센다.

### 무엇을 고쳤나
- **모바일 공통(≤960px)**: `.smain .btn`(btn-sm 포함)·`select`·`.af-chip`·`.lf-slot-add`·
  파일/날짜 입력 **44px**, 텍스트·숫자 입력 **44px**, 체크박스·라디오 **24px**, `.tb-more` 44px.
  구 규칙은 `.ri-edit/.ri-del/.ac-tg/.rv-btn` 같은 **행 버튼만** 덮어서 정작 저장·추가·CSV
  같은 주 버튼과 모든 select 가 36~38px 로 남아 있었다.
- **`.adm-help` 접이 안내 신설** — 긴 설명은 이 부품으로 옮긴다(탭마다 새 스타일 만들지 말 것).
  적용: 연구실 자료 312px · 감점 사전 166px · 후기 관리 145px → 전부 44px 요약 줄 하나.

  ⚠️ 감점 사전은 가장 중요한 한 줄("글에 그대로 나오는 문자열로")을 summary 에 남겼다.

### 연구실 자료 탭 — 오너 화면에서 깨져 있던 것들
- **'올리자마자 공개' 글자가 '자료 올리기' 버튼 뒤로 깔렸다.** 옵션·주 버튼·진단 셋을 한
  `display:flex` 줄에 몰아넣은 구조였고, 사파리가 라벨을 줄여 버렸다.
  ⚠️ **크로미움은 재현하지 않는다**(체크박스를 28px 로 키워도 안 남). 원인을 좇는 대신
  **줄을 셋으로 나눠 구조적으로 불가능하게** 했다 — 옵션 / 주 버튼 / 진단.
  같은 모양(한 줄에 라벨+버튼 여럿)을 다른 탭에 새로 만들지 말 것.
- **'업로드 진단'이 주 버튼과 같은 무게**였다 → 테두리만 있는 보조 버튼 + 글자를
  '안 올라가나요? 업로드 진단'으로. 데스크톱에선 주 버튼도 `justify-self:start` 로 200px.

- **'자료 유형' 칸이 2열 격자의 세 번째**라 모바일에서 반쪽 폭으로 혼자 남아 깨진 칸처럼

- **placeholder 잘림**('비우면 회원이면 누구ᅡ') → '비우면 회원 누구나'.
- **행 버튼 6개가 전부 같은 모양**이고 그중 하나가 삭제였다 → `.ri-del.is-danger`
