# admin.html — 상세 기록

## 5차 — 전면 진단(2026-08-02 · 오너 "어드민 UXUI 시스템 전체 점검")

1~4차가 **모바일 치수**(활자·표적·겹침)를 잡았다면, 5차는 **동선·상태·데이터 안전**까지 봤다.
정적 분석 7관점 + 393/320px 실측을 같이 돌렸다. 확정 결함 106건 중 아래를 고쳤다.

| 잰 것 | 전 | 후 |
|---|---|---|
| 12px 미만 활자 | 6곳 | 0 |
| 44px 미만 조작요소(393px) | 7 | 0 |
| 경계선 3:1 미달(조작요소) | **429** | 0 (`.tb-stat` 구분선 5개는 의도적 예외 — 아래) |
| 인접 표적 6px 쌍 | 151 | 70(칩·행버튼 8px 로) |
| `:focus-visible` 규칙 | **0개** | nav.css 와 같은 3px 링 |
| `:disabled` 규칙 | **0개** | 흰 면 + 흐린 글씨 |

### ⚠️ P1 — 조용히 데이터가 사라지던 것 셋
1. **연구실 자료 '가격 0' 이 저장되지 않았다.** `if (priceVal > 0) baseRow.price = priceVal`
   한 줄이 신규·수정 두 경로를 같이 막아서, **유료 자료를 무료로 되돌리면 옛 가격이 그대로
   남고 화면은 '수정했어요'** 라고 말했다. → 수정(update)에서는 0도 반드시 보낸다.
   (컬럼이 없는 환경은 update 가 에러를 내고 기존 안내 문구가 잡는다.)
2. **'충전 상품 저장'이 `credit_packs` 배열을 통째로 덮어썼다.** 화면은 `ai_killer` 팩 하나만
   읽어 편집하는데 저장은 배열 전체를 갈아끼웠다 — 팩이 둘 이상이면 나머지가 사라지고,
   verify-payment 가 같은 값으로 금액을 검증하므로 **그 상품 결제가 막힌다.**
   → 기존 배열을 읽어 `ai_killer` 만 교체. 그리고 **가격 0원 저장을 막았다**(`price < 1` 거부 —
   전에는 칸을 비우면 `Number('')||0` 이 0원 팩으로 저장돼 충전이 공짜가 됐다).
3. **일차 배치 편집기가 배치를 지웠다.** 후보 목록(`pool`)이 `active && 같은 항공사` 라
   **숨김 처리했거나 다른 항공사 기출이 배치된 일차는 `— 비움 —` 으로 보였고, 그대로
   [배치 저장]하면 실제 배치가 삭제**됐다. → 지금 배치된 기출은 후보 밖이어도
   `[지금 목록 밖]` 항목으로 만들어 selected 로 둔다. 지우기 실패도 이제 실패로 알린다.

### ⚠️ 화면이 '모른다'를 '없다'로 말하던 것
- **조회가 실패해도 '오늘' 브리핑이 "처리할 일이 없습니다"로 단정**했다(원칙 11).
  신청·오픈알림·회원 조회가 막히면 배열이 빈 채로 남아 숫자가 전부 0이 되고, 오류처럼
  보이지 않아 오너는 재시도하지 않는다 — 그날 입금 확인을 통째로 건너뛴다.
  → `_loadErr` 세 칸으로 실패를 기억하고, 하나라도 실패면 숫자를 `–` 로 두고
  **"오늘 현황을 불러오지 못했습니다" + [다시 불러오기]** 를 띄운다.
  ⚠️ 이 짝(로더의 `_loadErr[...] = !!error` ↔ loadToday 앞머리 분기)을 끊지 말 것.
- **`loadToday()` 가 초기화 때 딱 한 번만 돌았다.** 입금 3건을 다 처리하고 '오늘'로 돌아와도
  헤드라인이 3건 그대로였다. → 탭 전환 시 `today` 면 다시 센다(캐시만 읽으므로 비용 없음).
- **회원 조회는 `error` 를 통째로 버렸다** — 실패해도 '회원이 없습니다'로 뜨고,
  신청자 배지가 **전원 '비회원'** 으로 뒤바뀐다. → error 를 받아 목록에 사실대로 적는다.

### 동선 — 숫자를 눌렀으면 그 숫자의 목록이 나와야 한다
- 신청자 현황에 **입금 필터(`#afPay` 전체/미입금만)** 신설. '오늘'의 [입금 확인 필요]와
  [오픈 알림 연락 전]이 `data-focus` 로 그 필터를 켜고 이동한다(`activateTab(name, focus)`).
  ⚠️ **'미입금' 판정식은 `loadToday` 의 `unpaid` 와 같아야 한다**(`isLiveApplication && !appPaid`).
  한쪽만 고치면 카드 숫자와 목록 건수가 어긋나 화면이 거짓말을 한다.
  ⚠️ 메뉴로 apps 를 열면 필터는 초기화된다(initTabs) — 안 그러면 나중에 열었을 때
  3건만 보이고 "신청이 왜 이것뿐이지"가 된다. activateTab 이 그 뒤에 다시 걸므로 순서가 중요하다.
- **탭을 바꾸면 맨 위에서 시작한다.** 전에는 스크롤 위치가 그대로라 연구실 자료를 1200px
  내려 보다가 감점 사전을 고르면 그 탭 중간(745px)에 떨어졌다.
- **회원 목록에 기수를 적는다.** 배정이 이 화면의 주 작업인데 '미배정만'을 켜기 전에는
  누가 배정됐는지 알 수 없었다. 정렬도 **최근 가입 먼저**로 뒤집었다('오늘 새 회원'을 눌러
  들어갔는데 그 사람이 목록 맨 끝이면 지표가 행동으로 안 이어진다).

### 기본기 — admin 만 못 받고 있던 것
admin 은 **nav.css 를 안 읽는다(의도)**. 그래서 2026-08-02 에 공개 페이지가 받은 것이 여기만 빠졌다.
- **포커스 링**: 크로미움 기본 1px 주황(`#E59700` · 흰 면 2.2:1)만 나왔다 → nav.css 와 같은
  `outline: 3px solid var(--action); outline-offset: 2px`.
- **본문 바로가기(`.skip-link`)** + `#main`(=`.smain`, `tabindex="-1"`).
- **`:disabled`**: 회원 '배정' 버튼이 disabled 인 채로 채움 네이비 CTA 그대로였다(눌러도 무반응).
  ⚠️ opacity 로 흐리지 않는다 — 글씨 대비가 무너진다. 흰 면 + `--text-dim`.
- **`accent-color: var(--action)`**: 체크박스·라디오가 브라우저 기본 파랑이라 네이비 안에서 튀었다.
- **경계선 `--border-strong`**: `--border`(흰 면 위 1.38:1)를 입력칸·고스트 버튼·칩이 그대로
  쓰고 있었다(429곳). `--border-strong` 사용 0회였다 — 원칙 4의 신설 조항이 admin 에 한 번도 안 왔다.
  ⚠️ `--border` 자체는 올리지 않는다(카드·구분선까지 진해져 표처럼 보인다).
  ⚠️ `.is-danger` 는 이 규칙에서 제외하고, 대신 테두리를 `#B3261E` 제 색으로(전 `.5` 알파 = 2.47:1).
- **바텀시트 포커스 3종**: 열 때 안으로 · 뒤를 `inert` · 닫을 때 `#mtMenu` 로 복귀.
  ⚠️ 데스크톱(>960px)에선 사이드바가 덮개가 아니므로 포커스를 건드리지 않는다.

### 구조 — '썼다'와 '먹는다'가 또 갈렸던 자리
- **`[hidden] { display: none !important; }` 한 줄로 통일.** `.round-editing`·`#lrEditBar` 는
  2026-08-01 에 짝 규칙으로 하나씩 막았지만 같은 사고가 `#qfRaw`(원문 접기가 안 접힘)·
  `#afSub`(비어 있어도 자리를 먹음)에서 또 났다. **자리마다 짝을 달지 말고 이 한 줄에 맡긴다.**
- **`.ri-del`·`.ri-edit`·`.ri-cancel`·`.ri-actions` 를 `.round-item` 자손에서 떼어냈다.**
  목록 밖에서 쓰던 두 곳(자료 파일 목록·이용권 지급 회원 고르기)이 브라우저 기본 회색 사각
  버튼으로 나오고 있었다.
- **`.empty` 는 38곳이 쓰는데 CSS 정의가 없었다.** 실패·빈 안내가 여백 0의 맨 글자였다
  (그래서 자리마다 인라인 style 로 때웠다). `.empty` / `.empty.err` 신설.
- **`button, input, select, textarea { font-family: inherit }`** — 개별 규칙 17곳이 이걸 빠뜨려
  같은 화면에 SUIT 와 시스템 글꼴이 섞였다.
- **인라인 `min-height:38px/36px` 제거**(일차 배치 select·date, 답변 프로그램 `<summary>` 2곳) —
  모바일 44px 규칙을 인라인이 이기고 있었다. summary 는 `.ap-sum` 부품으로(펴기/접기 표시 포함).
- **`.round-form input { width:100% }` 에서 체크박스·라디오 제외** — 데스크톱에서 '공개'
  체크박스가 폼 폭(752px)만큼 늘어났다.
- **크레딧 회원 행의 인라인 `display:flex` 제거** → `.ri-actions`. 2026-08-01 의 "행 버튼
  컨테이너에 인라인 flex 금지" 규칙을 이 줄만 안 지켜서 모바일 1열 규칙이 안 먹었다.
- **폼 제출 연타 방지 `guardSubmit(formId, handler)`** — 8개 폼 전부. 전에는 두 번 누르면
  특강·프로그램·기수·문제·기출이 두 벌씩 들어갔다. ⚠️ handler 가 async 고 return 경로가
  많아 자리마다 풀어 주면 반드시 하나를 빠뜨린다 — 리스너를 감싸고 `finally` 에서만 푼다.

### 문구
- **챌린지 이름을 학생이 보는 이름으로 통일**: `CH_LABEL` 이 `보이스·표현력·답변` 이라
  후기 탭(`보신각·영합각·승자각`)·공개 페이지와 갈려 있었다 → `보신각·영합각·스피닝·승자각`.
  select 는 `보신각(보이스)` 처럼 옛 이름을 괄호로 남긴다. **DB 값(voice 등)은 그대로다.**
- **이용권 목록의 DB enum**(`admin`/`purchase`, `active`/`expired`)이 화면에 그대로 떴다 →
  `AP_SOURCE`·`AP_ENR_STATUS` 표로 한국어.
- 후기 카드의 기수 칸이 채워지면 `2` 만 남았다(원칙 15) → `기수` 라벨을 붙였다(`.rv-lb`).
- 신청자 **전화 검색이 하이픈까지 같아야** 걸렸다 → 숫자만 남겨 비교(폰에서 `01098765432` 로 침).
- 후기 **노출/숨김이 목록을 통째로 다시 조회**해 스크롤이 맨 위로 튀었다 → `patchRow`.

### '오늘' 숫자 = 2열 타일 (2026-08-02 · 오너가 목업 B안 확정)

5차 진단에서 "숫자 5줄의 구분선 대비·간격은 오너 확정 목업이라 손대지 않는다"고 남겼는데,
오너가 **"1면 목업은 한 번 더 정해야겠네"** 라며 다시 고르기를 요청했다. 네 안(지금 화면 /
A 할 일 먼저 / B 숫자 접기 / C 최소 수정)을 393px 목업으로 만들어 **B안 확정**.

| | 전(세로 5줄) | 후(2열 타일) |
|---|---|---|
| 첫 행동 버튼 위치 | 749px(첫 화면 밖) | **642px**(첫 화면 안) |
| 숫자 블록 높이 | 352px | 277px |
| '오늘' 전체 길이 | 1,605px | 1,498px |
| 같은 숫자 반복 | 3번 | 2번(제목 + 타일) |

- **칸은 6개**: 입금 확인 필요 · 오픈 알림 연락 전 · 검수 대기 · 오늘 신청 · 오늘 새 회원 · **전체 회원**.
  순서는 '돈 먼저' — 손댈 것이 남은 칸이 위, 그냥 보는 숫자가 아래.
- **`data-todo="1"` 칸만 빨강 강조**(`.tb-stat.todo` — 테두리 + 숫자 `#A33D14`).
  ⚠️ **값이 0 이거나 '–'(모름)이면 강조하지 않는다** — 할 일이 없으면 눈에 띌 이유가 없고,
  못 받은 값을 '급한 일'처럼 보이게 하면 원칙 11 위반이다. 판정은 `tdSet()` 안에 있다.
- ⚠️ **`minmax` 를 150px 이상으로 올리지 말 것** — 320px 화면에서 1열로 풀려 도로 길어진다
  (본문 여백 16×2 를 뺀 288px 에 132×2+8 이 들어간다). 실측: 320px → 140px 2열, 데스크톱 우측 단 → 174px 2열.
- **리드 문장(`#tbLede`)은 정상 화면에서 접는다.** 바로 아래 타일·'지금 처리'가 같은 숫자를
  다시 말하는 줄이었다. ⚠️ **요소는 지우지 말 것** — 조회 실패 안내가 이 자리를 쓴다.
- **전체 회원 수는 독립 칸**이다. 하루 전 버전은 '오늘 새 회원'의 보조 문구(`#tdMembersTotal`)에
  얹었는데, B안에서 칸이 생기며 `#tdMembersAll` 로 옮겼다. 구 id 는 사라졌다.
- 새 숫자 칸을 만들면 **`TD_CARDS` 배열에도 넣는다** — 조회 실패 화면에서 같이 '–'로 비운다.
- 구 `.tb-stat.zero { opacity:.55 }` 는 칸 전체를 흐리게 해 글자 대비까지 무너뜨렸다(원칙 4) →
  숫자 색만 흐리게.
- 검증(실측): 320·393·1280px 전 탭 — 12px 미만 활자 0 · 44px 미만 0 · 겹침 0 · 넘침 0 · 콘솔 0.
  0건·'–' 상태에서 강조가 풀리는 것까지 확인.

### 회원 3천 명 대비 — 1000행에서 조용히 잘리던 것 (2026-08-03 · 오너 "2~3천명이 되어도 문제 없나")

**Supabase 는 한 번에 최대 1000행만 돌려주고, 넘으면 아무 말 없이 잘라 준다.** admin 은 그 배열로
숫자를 세기 때문에 잘리는 순간 **화면 전체가 같이 거짓말을 한다.** 실측(목 3,000명·1,500건):

| | 전 | 후 |
|---|---|---|
| 회원 조회 | 3,000명 중 **1,000명** | 3,000명 |
| '전체 회원' 숫자 | 1,000 | 3,000 |
| 1000명 밖 회원의 신청 배지 | 전부 '비회원'(거짓) | 정상 |
| 크레딧 탭 여는 시간 | **968ms**(DOM 32,883) | **32ms**(DOM 3,886) |

- **`fetchAll(build)`** 하나로 모았다 — `range()` 로 1000행씩 끝까지 받는다.
  적용: `members` · `applications` · `challenge_waitlist` · `reviews`.
  ⚠️ **`build` 는 매번 새 쿼리를 만들어 돌려주는 함수**여야 한다(supabase-js 쿼리 객체는 재사용 불가).
  ⚠️ `FETCH_CAP`(20,000)을 넘기면 `truncated:true` 를 돌려준다 — **부르는 쪽이 화면에 사실대로 적는다.**
  회원·신청 목록에 빨간 한 줄로 나온다. 조용히 자르는 코드를 다시 만들지 말 것.
- **목록은 끊어 그린다**: 회원·크레딧 `M_PAGE=100`, 신청 카드 `A_PAGE=50` + '더 보기'.
  ⚠️ **계산은 전량으로 한다** — 건수·중복 검사·CSV·'오늘' 숫자는 `members`/`_apps` 전체를 그대로 쓴다.
  화면만 끊는 것이지 데이터를 끊는 게 아니다.
  ⚠️ 조건(검색·필터)이 바뀌면 표시 수를 `_mShown`/`_aShown`/`_credShown` 처음으로 되돌린다 —
  안 하면 결과 3건짜리 화면에 '더 보기'가 남는다.

### 회원 상태 배지·필터 (2026-08-03 · 오너 "번호 없는 사람·이상한 사람을 갈라 놓자")

회원 목록에 이름·이메일·기수만 있어서 **누가 연락 가능한 사람인지 구분할 방법이 없었다.**
행에 상태 배지를 붙이고 상태 필터 칩 6개를 뒀다(구 '미배정만' 체크박스는 '기수 미배정' 칩이 대신한다).

| 필터 | 뜻 |
|---|---|
| 가입 미완료 | 번호 없음 — 로그인은 했고 이름·번호 넣는 화면에서 나간 사람 |
| 번호 확인 필요 | 번호는 있는데 형식이 안 맞음(유선·자릿수 오타) |
| 기수 미배정 | `cohort_id` 없음 |
| 신청 있음 | 챌린지·특강 신청 이력이 있음 |
| 흔적 없음 | 번호 없음 + 신청 0 + 크레딧 사용 0 + 가입 30일 경과 |

- ⚠️ **번호 판정은 `phone-check.js` 를 그대로 쓴다**(admin 에 스크립트를 추가했다).
  여기서 정규식을 따로 만들면 "가입은 통과했는데 admin 만 이상하다고 하는" 번호가 생긴다.
- ⚠️ **'흔적 없음'은 보수적으로 센다.** 신청·크레딧 원장을 아직 못 읽었으면 **아무도** 흔적 없음으로
  치지 않고 머리글에 '확인 중'을 띄운다. 모르는 것을 '없다'로 말하지 않는다(원칙 11).
  회원 목록은 초기화 순서상 신청·크레딧보다 먼저 그려지므로 **`loadCredits()` 끝에서 다시 그린다.**
- ⚠️ **삭제 버튼을 만들지 않았다.** `members` 행만 지우면 `auth.users` 가 남고, 회원 행은
  **첫 로그인 때 한 번만**(`on_auth_user_created`, after insert) 생기므로 그 사람이 다시 로그인해도
  프로필이 복구되지 않는다. 제대로 지우려면 `auth.users` 를 지워야 하고 그러면 `on delete cascade` 로
  크레딧·답변·세션·이용권까지 함께 사라진다. 접이 안내에 이 사실을 적어 두었다 — **지우는 곳은 콘솔이다.**
- ⚠️ **성능**: 신청 건수를 회원마다 `_apps` 를 훑어 세면 3,000 × 1,500 = 450만 번이라 렌더 한 번에
  **2,333ms** 가 걸렸다(실측). 검색은 글자마다 렌더하므로 그대로는 못 쓴다.
  `buildAppIndex()` 로 렌더 시작에 색인을 한 번 만들어 **16ms** 로 내렸다.
  ⚠️ 색인은 `member_id` 가 있으면 그쪽에만 센다 — 두 map 을 더하면 같은 신청이 두 번 세어진다.
- `credit_ledger` 도 `fetchAll` 로 옮겼다 — 무료 사용 한 번마다 한 줄이라 **가장 빨리 1000행을 넘긴다**
  (잘리면 잔액이 틀린다).

### 후기 탭 — 챌린지별 건수 요약(`#rvChSum`) (2026-08-02)
챌린지 상세(`challenge-*.html`)의 후기 섹션은 `reviews.challenge` 로 골라 담는데, **'여러 장 한번에' 업로드는 이 값을 안 채운다.** 그러면 상세 페이지는 섹션을 `hidden` 으로 두고 조용히 넘어가서, 어드민만 보고 있으면 "후기를 올렸는데 왜 안 뜨지"가 된다. 그래서 종류 필터 바로 아래에 **노출(visible)·챌린지 지정된 건수를 챌린지별로** 찍는다 — 0이면 그 상세엔 섹션이 없다는 뜻. 미지정 건수는 빨간 글씨로 따로 센다.
- **집계 기준은 `challenge-reviews.js` 의 조회 조건과 같아야 한다**: `kind==='challenge'`(null 은 challenge 로 간주) + `visible` + `challenge` 일치. 한쪽만 고치면 숫자가 거짓말을 한다.
- 챌린지 이름 네 글자는 `RV_CH_OPTS` 상수 하나로 모았다. **이 문자열은 각 상세의 `data-challenge` 와 정확히 같아야 한다**(현재 `보신각`·`영합각`·`스피닝`·`승자각`). 어느 한쪽 이름을 바꾸면 매칭이 조용히 끊긴다.
- 종류·챌린지 드롭다운을 바꾸면 **행만 메모리에서 갱신하고 요약만 다시 계산**한다(`patchRow`). 통째로 `loadReviewsAdmin()` 하면 스크롤이 맨 위로 튄다.
- 검증(375px 실측): 보신각 2·영합각 0·스피닝 0(숨김 1건 제외)·승자각 1·미지정 2 — 상담 후기와 숨김 후기가 안 세어지는 것까지 확인. 챌린지 변경 → 영합각 0→1·미지정 2→1, 종류 변경 → 승자각 1→0, 가로 넘침 0, 스크롤 유지, 콘솔 에러 0.

### 목록 행은 모바일에서 1열로 — 버튼 줄은 `.ri-actions` 로만 (2026-08-01 실사고 · 오너 "이런식으로밖에 못하냐")

  - ⚠️ 대신 첫 화면까지 **조회 5개(기수→회원→신청→오픈알림→검수 count)를 순서대로** 기다린다. 신청 조회는 회원 전화 대조(`memberPhoneSet`)를 쓰므로 **`loadMembers()` 앞으로 병렬화하면 '회원/비회원' 배지가 틀리게 그려진다** — 순서를 바꾸지 말 것.

## admin 모바일 UX 정비 2차 (2026-08-02 · 오너 "어드민 페이지도 uxui 신경쓰라고했지?")

### ⚠️ 제일 뼈아픈 것 — 규칙은 있었는데 한 번도 안 먹었다

- **교훈**: CSS 규칙을 넣었으면 **브라우저로 세어 본다.** '썼다'와 '먹는다'는 다르다.

### 3차 — 날짜 칸이 격자를 뚫고 옆 요소를 덮던 건 (2026-08-02 · 오너 "아직도 박스가 튀어나오고 정렬이 안 됐는데?")

2차 정비를 하고도 오너 화면(챌린지 탭)에서 **모집 시작·마감 칸이 삐져나오고 '추가/수정' 버튼이
'프로그램 시작' 입력 위에 올라타 있었다.** 내 검사가 놓친 이유가 분명하다.

- **잰 것**: 페이지·패널의 `scrollWidth − clientWidth`(가로 넘침) → **0 이었다.**
- **안 잰 것**: **요소끼리 겹치는지.** 칸이 트랙을 넘쳐도 페이지 폭은 안 늘어난다.
  넘친 칸은 옆 칸 *위로* 올라탈 뿐이라 넘침 검사에 안 걸린다.
- 게다가 **크로미움의 `input[type=date]` 는 min-content 폭이 좁아** 트랙에 들어간다.
  사파리의 날짜 컨트롤은 **약 168px 아래로 안 줄어든다.** 눈검사로도 크로미움 측정으로도 못 잡는다.

**원인**: `.round-form { grid-template-columns: repeat(auto-fit, minmax(120px,1fr)) }` 의 트랙은
393px 화면에서 158px, 데스크톱에서도 127px 다. 그리고 **그리드 칸의 기본 `min-width` 는
`min-content`** 라 안에 든 것이 크면 칸이 트랙을 넘친다.

**고친 것**
- `.round-form > *`·`.field` 에 **`min-width:0`**, 입력에 `min-width:0; max-width:100%`
  → 어떤 컨트롤도 자기 칸 밖으로 못 나간다. **지우지 말 것.**
- **`.field-date { grid-column: span 2; min-width:170px }`** — 날짜 칸은 두 트랙을 쓴다.
  ⚠️ 새 날짜 입력을 만들면 감싸는 `.field` 에 **`field-date` 를 같이 단다**(현재 8곳).
- 모바일에서 `.round-form > button[type=submit]` 은 **한 줄 전체**. 필드 옆 칸에 끼어 있어서
  오너 화면의 '추가/수정'이 옆 입력을 덮었다.
- 삭제 버튼 전부 `.is-danger`(빨강 #B3261E · 흰 배경 대비 6.54:1) — 2차엔 연구실 자료 한 곳만
  했었다. 지금은 12곳(오픈 알림·챌린지·특강·크레딧·후기·수기·소재·감점·기출·이용권·파일·시간대).
- 목록 줄이 `모집 undefined ~ undefined` 를 찍던 것 → `미정`(원칙 11 — 모르는 걸 단정하지 않기).

### 검사에 추가한 것 — 겹침 검사(overlap.mjs)
탭마다 **실제 조작요소끼리** 사각형이 겹치는지, **자기 `.field` 밖으로 나갔는지** 본다.
`12개 탭 × 6폭(320·375·393·430·768·1280) × 2모드`.
- ⚠️ **`.field` 같은 래퍼끼리 비교하면 안 잡힌다** — 입력칸이 래퍼를 넘쳐도 래퍼끼리는 안 겹친다
  (첫 판을 그렇게 짜서 '이상 없음'이 나왔다). **input·select·button 을 직접** 비교할 것.
- ⚠️ **닫힌 `<details>` 안의 요소는 제외**한다. `content-visibility:hidden` 이라 그려지지만
  않을 뿐 좌표는 그대로여서 겹침으로 잘못 잡힌다(답변 프로그램 4건 오탐).
- ⚠️ **iOS 폭 재현 모드**를 같이 돌린다: `input[type=date]{min-width:168px}` 를 주입한다.
  크로미움 기본으로만 돌리면 이 버그가 통과한다.

### 4차 — 날짜 입력이 카드를 뚫던 진짜 원인 (2026-08-02 · 오너 세 번째 지적)

3차에서 `.field-date { grid-column: span 2 }` 로 칸을 한 줄 전체(327px)로 넓혔는데도
**오너 화면에서 날짜 박스가 여전히 카드 밖으로 약 20px 나갔다.** 칸 문제가 아니었다.

**증거가 스크린샷에 있었다**: 날짜 칸만 **회색 민짜 박스**로 보였다. 옆의 '기수'는 흰 배경 +
테두리인데 날짜만 다르다 — **우리가 준 배경·테두리가 안 먹고 있었다는 뜻**이다.
iOS 사파리는 `input[type=date]` 를 **네이티브 컨트롤**로 그린다. 네이티브 위젯은 우리 스타일을
무시하고 **자기 고유 크기로 폭을 정하며, 우리가 준 padding 이 그 밖에 붙는다**(그래서 초과분이
정확히 좌우 padding 20px 였다). `width:100%`·`max-width:100%`·`min-width:0` 를 다 줘도 소용없다.

**고친 것 — 네이티브에게 크기 결정권을 주지 않는다**
```
.smain input[type="date"] { -webkit-appearance:none; appearance:none; box-sizing:border-box;
  max-width:100%; min-width:0; background:#fff; border:1px solid var(--border); text-align:left; }
.round-form input[type="date"], .field input[type="date"] { width:100%; }
```
- ⚠️ **`appearance:none` 을 지우지 말 것.** 이게 이 버그의 실제 수정이다.
- ⚠️ 탭하면 **날짜 피커는 그대로 열린다** — 그리기만 바뀌지 동작은 그대로다.
- ⚠️ `width:100%` 는 **격자 칸 안의 날짜에만** 준다. 후기 탭 `#rvTextDate` 는 flex 줄에 끼어
  있어 100% 를 주면 옆 입력을 밀어내고 혼자 한 줄을 먹는다(한 번 그렇게 만들었다가 되돌렸다).
- 마지막 안전장치로 `.round-form { overflow-x: clip }` — 무엇이 됐든 카드 밖으로는 못 그린다.
  `hidden` 이 아니라 `clip` 이라 스크롤 컨테이너가 안 생기고 세로 포커스 링이 안 잘린다.
  ⚠️ 이건 **backstop 이지 수정이 아니다** — 겹침 검사는 여전히 rect 로 재니 가려지지 않는다.

### ⚠️ 이 컨테이너에는 사파리 엔진이 없다 — 세 번 놓친 진짜 이유
playwright 의 `webkit` 은 설치돼 있지 않고, 프록시가 다운로드를 막는다(403 host not permitted).
크로미움만으로는 **네이티브 폼 컨트롤이 얽힌 버그를 구조적으로 못 잡는다** — date 입력이 그랬고,
하단 고정바 잘림·체크박스 라벨 겹침도 같은 부류였다.
- 그래서 **네이티브 위젯이 관여하는 자리는 '재현해서 고친다'가 아니라 '네이티브에게 결정권을
  주지 않는다'로 간다** — `appearance:none`, 줄 나누기, 명시적 박스 모델.
- 오너 스크린샷에서 **우리 스타일이 안 먹은 흔적**(배경색·테두리가 다름)을 먼저 찾는다.
  그게 '네이티브가 그리고 있다'는 신호이고, 그 순간 폭 계산도 우리 것이 아니다.
