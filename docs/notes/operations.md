# 학원 일정·업무 공유

## 범위와 권한

- `operations.html`은 직원 전용이다. 기존 로그인·필수 동의를 통과한 홈페이지 회원을 원장이 직원으로 연결한다. 학생의 재학생 여부와 직원 권한은 별개다.
- 원장은 `public.is_admin()`으로 판정한다. 교사에게 홈페이지 전체 관리자 권한을 부여하지 않는다. 일정, 업무·공지 메뉴를 직원별로 따로 허용한다.
- 마이페이지는 `operations_api('access')` 결과가 허용일 때 입구를 표시한다. 관리자에는 회원·수업 메뉴와 바로가기를 둔다. 실제 접근·쓰기 판단은 매 RPC에서 다시 한다.
- 업무 권한이 있는 직원끼리는 전체 업무와 공지 내용을 볼 수 있다. 개인 비밀 메시지 기능이 아니다. 직원 연락처·전체 회원 검색은 원장만 가능하다.
- 새 UI 승인과 운영 DB 적용 전에는 운영 기능으로 보고하지 않는다. 적용 상태는 `implementation-status.md`가 원장이다.

## 일정

- 일·주·월 보기, 분류, 하루/기간/매주 요일/날짜 지정 등록, 1건 또는 반복 묶음 수정, 선택 제목 수정·보관·복원.
- 등록 전 적용 날짜와 건수를 한 번 보여 준다. 최대 400건, 화면 날짜 생성 범위는 2년 이내다. 종료 시각은 시작 시각보다 뒤여야 한다.
- 수정은 기존 행을 보관하고 새 행을 만든다. 처리 전 revision과 반복 묶음 구성 전체를 확인한다. 누군가 먼저 수정했다면 변경 전체를 거절한다. 이전 행을 다시 복원하면 일정이 겹칠 수 있으므로 실제 날짜를 확인해야 한다.
- 빈자리 계산은 기존 `monk-academy/lib/schedule-slots.ts`의 동시 수업 기준을 사용한다. 화~토 13~22시, 동시 2개 반, 정규 120분·1:1 90분·상담 60분. 4/8/12주를 고를 수 있다. 상담 자체는 강의실을 차지하지 않는다.
- 종료 시간이 없으면 120분으로 계산한다. 시간 미정 수업은 경고하고 계산에서 제외한다. 일부 주차 가능 구간은 실제 날짜 대조가 필요하며 수업 예약 보장을 뜻하지 않는다.

## 업무·공지

- 담당자별 업무, 선택 검수자, 마감일, 매주/매월 반복을 지원한다. 대기 → 진행 → 검수 대기 → 완료, 검수자 없는 업무는 진행 → 완료다. 반려에는 사유가 필요하다. 완료 업무를 대기로 되돌리는 것은 원장만 가능하다.
- 같은 완료 요청을 재전송하거나 완료 후 되돌려도 반복 업무는 부모 항목당 한 번만 만든다. 다음 마감은 기존 마감 기준 다음 요일 또는 다음 달 지정일이다. 없는 날짜는 월말로 보정한다.
- 공지는 수신자마다 확인 상태를 남긴다. 관리자도 타인의 확인을 대신하지 못한다. 공지 내용 수정은 기존 확인 이력을 유지하며 재확인이 필요하면 새 공지를 작성한다.
- 최초 열람·댓글·상태 이력을 보관한다. 내용 수정과 보관·복원은 작성자 또는 원장만 한다. 처리 중 업무의 담당자·검수자 변경은 막는다.
- 비활성 직원의 기존 이력과 공지 확인은 유지한다. 신규 배정은 활성·업무 권한·회원 연결을 갖춘 직원만 가능하다.
- 목록은 미완료와 공지를 함께 불러오고 완료 업무는 선택 월의 마감일 범위로 가져온다. 공지/미완료 건수가 커지면 별도 페이지 조회가 필요하다. 현재 실시간 구독은 없으며 새로고침·탭 이동·화면 복귀 시 갱신한다. 입력 창이 열려 있으면 복귀 갱신을 미룬다.

## 저장 구조

- `20261016084235_academy_operations.sql`은 한 트랜잭션으로 새 전용 스키마와 RPC를 만든다. 최초 1회 적용 파일이다. 기존 수업·과제·결제 원장은 변경하지 않는다. 새 Edge Function이나 Storage 설정은 없다.
- 비공개 스키마 `operations_private`: `staff`, `schedule`, `items`, `history`, `comments`, `requests`. 전 테이블 RLS 활성, anon/authenticated의 직접 읽기·쓰기 차단. Supabase API 노출 스키마에 추가하지 않는다.
- 공개 진입점은 `operations_api` 하나다. 함수는 로그인·동의·직원 메뉴 권한을 검사한다. 변경 요청은 고유 ID와 payload로 재시도를 판정하고, 트랜잭션 잠금과 revision으로 덮어쓰기를 방지한다.
- 원장이 처음 진입할 때 자신의 직원 행만 생성한다. 다른 직원 권한은 자동 추정하지 않는다.
- 일정·업무 텍스트와 처리 이력은 미디어 14일/2개월 보관 규칙의 대상이 아니다. 실제 개인정보·구글 시트 원본·이전용 데이터 SQL은 공개 저장소에 넣지 않는다.

## 기존 기록 이전

- 기능 소스는 로컬 `monk-academy`에서 확인했다. 실제 운영 기록은 기존 사이트 직원 로그인 또는 관리용 구글 시트 공유가 필요하다. 현재 실데이터 이전은 하지 않았다.
- 필요한 표: `STAFF`, `SCHEDULE`, `WORK_ITEMS`, `WORK_ITEM_EVENTS`, `WORK_ITEM_COMMENTS`. 내부 게시판도 옮길 때는 `STAFF_BOARD`, 일정 변경 기록은 `NEWS_LOG`를 함께 확인한다. 공지 원문과 기존 확인/읽음 기록은 구분한다.
- 이전 전에 원본 읽기 전용 내보내기를 확보한다. 원본 ID를 `legacy_key`로 보관하고 직원 이메일→기존 홈페이지 회원 UUID를 명시적으로 대조한다. 이름만으로 회원을 연결하거나 신규 관리자 권한을 추정하지 않는다. 미가입·퇴사 직원은 계정 없는 기록용 행으로 남긴다.
- 일정의 기존 담당 이름, 반복 묶음, 날짜·시각과 업무의 작성/담당/검수자, 상태·확인 시각·댓글·처리 이력·보관 상태를 대조한다. 잘못된 시각·자기 검수·누락 담당자는 임의 보정하지 않고 별도 확인한다.
- 원본/변환 후 건수·상태별 건수·기간·수신자별 확인 건수를 비교하고 예시 몇 건을 화면에서 대조한다. 과거 완료 업무를 가져올 때 반복 업무를 새로 생성하지 않는다. 원본은 삭제하지 않는다.
- 실제 데이터를 받기 전에는 이전 SQL을 완성·적용했다고 보고하지 않는다. 이전 실행 직전에 기존 앱 입력을 잠시 멈추고 마지막 변경분을 대조한다. 외부 적용 순서는 오너에게 별도로 안내한다.

## 로컬 검증

- `node scripts/operations-tests.mjs`: 로컬 PGlite로 권한, 변경 충돌, 중복 재시도, 반복 생성, 반려, 공지 확인, 비활성 직원 경계 검사. `ACADEMY_PGLITE_MODULE`에 설치된 PGlite 모듈의 절대 경로가 필요하다.
- `node scripts/operations-slots-tests.mjs`: 반복 날짜와 동시 2개 수업, 상담 제외, 시간 읽기 경계 검사.
- `node scripts/operations-preview.mjs`: 같은 테스트 DB를 사용해 127.0.0.1:5516에서 합성 화면 제공. 운영 설정·SDK를 대체하고 CSP로 외부 API 호출을 차단한다. 세션 종료 시 합성 DB도 사라진다. 운영 페이지에 테스트 계정 선택 UI를 넣지 않는다.
- `operations.js`, `operations-utils.js`, `operations-slots.js`의 문법 검사와 375px부터 화면·오류·권한 전환을 확인한다. 입력 화면이므로 전체 reload/scroll-keep 대신 목록만 갱신한다.
