# 재학생 수업 · 과제 · 피드백

## 확정 범위

- 화면은 회차를 나누지 않고 최신 내용을 ‘제출’로 표시한다. 선생님 입력은 ‘피드백’ 한 칸이며 종합 의견·수정안·문장별 의견을 따로 받지 않는다. 이전 제출·피드백 이력은 데이터로 보존한다.
- 2026-10-13 승인: 기존 Supabase Pro로 자체 과제·피드백을 구현한다. Google 문서는 신규 작성 경로에서 제외한다.
- 재학생 영상·음성: 업로드 확인일부터 달력상 2개월(한국 시간). 챌린지 영상·음성: 제출일부터 14일. 글·피드백·수정 이력은 미디어 보관기간과 무관하게 유지한다.
- 저장 위치는 미디어 식별자와 공급자/버킷/경로로 분리한다. 화면과 제출 버전에는 영구 재생 URL을 저장하지 않는다.
- 기존 재학생 무료 혜택(`academy_students`), 답변 프로그램, 결제·참가 판정은 변경하지 않는다.
- 수료생과 과거 글·피드백은 전체 이전 대상이다. 2개월 지난 과거 미디어의 이전 범위는 미확정이다. 이번 구현은 신규 수업 흐름이며 과거 자료를 가져오거나 삭제하지 않는다.

## 화면과 원장

- `academy.html` + `academy.js` + `academy.css`: 내 수업, 과제, 자동 저장, 최신 제출, 피드백 확인. `MONC.requireSession()`·`requireConsent()`를 통과한다.
- `academy-desk.html`: 배정된 수업의 제출 목록, 과제 등록, 피드백 작성, 수정 요청/완료 전달. 원장은 수업별 `staff` 배정이다. 기존 monk-academy의 분류별 권한은 자료 이전 때 명시적으로 매핑하며 전체 교사에게 관리자 권한을 주지 않는다.
- 관리자는 같은 화면에서 수업 생성, 가입 회원 검색·수강 등록, 수업별 교사 권한 부여·해제를 한다. 회원 이름·이메일을 대조하며 전화번호 조회 창구를 추가하지 않는다.
- `academy_students`는 기존 무료 혜택 표다. 새 `academy_private.enrollments`와 합치지 않는다. 정규/올케어/개인 수업의 수강 종료일을 한 값으로 고정하지 않는다. 첫 구현은 과제별 종류·마감 등록이며 반별 자동 주간 생성과 주간 종합 평가는 후속 범위다.
- 테이블은 `academy_private` 스키마 + RLS + 직접 접근 권한 회수. 공개 `academy_api`는 invoker이며 비공개 dispatcher가 호출자·동의·수강 기간·담당 수업을 확인한다. 서비스 역할 전용 정리 액션은 일반 회원이 호출할 수 없다.

## 글 · 피드백 저장 규칙

- 초안 저장은 버전 번호를 비교한다. 다른 창에서 바뀐 글을 덮어쓰지 않는다. 저장 실패 시 입력을 보존하고, 계정/과제별 sessionStorage 복원 버튼을 제공한다.
- 제출은 트랜잭션 안에서 원문 스냅샷과 제출 상태를 함께 기록한다. 요청 UUID로 네트워크 재시도 중복을 막는다. 제출 후에는 수정 요청이 있어야 새 버전을 낼 수 있다.
- 피드백 초안은 작성한 선생님만 본다. 전달한 피드백은 불변이며 선생님별로 저장한다. 기존 형식의 종합 의견·수정안·문장 의견은 한 피드백으로 합쳐 표시한다. 새 입력은 body 한 필드로 저장하고 suggestion·notes는 빈 값으로 보낸다. 실시간 공동 편집은 제공하지 않는다.
- 상태는 작성 중 → 제출 → 수정 요청/완료다. 지각 여부는 제출 시각과 마감일로 따로 기록한다.
- 학생 탈퇴 시 연결된 수강·글·피드백은 삭제하고 파일은 즉시 만료 대상으로 넘긴다. 교사 탈퇴는 기존 피드백을 보존하되 작성자 계정 연결을 제거한다. 외래키가 기존 탈퇴 기능을 막지 않는다.

## 파일과 정리 작업

- `media-storage.js`가 프런트 업로드 공급자를 선택한다. `academy-media/index.ts`의 저장소 어댑터가 업로드 서명·재생 서명·파일 삭제를 담당한다. 공급자는 행마다 저장하므로 전환 기간에 이전/새 저장소를 병행할 수 있다.
- 현재 공급자는 Supabase, 재학생은 비공개 `academy-media` 버킷이다. 파일마다 새 UUID 경로를 사용하고 덮어쓰지 않는다. 최대 50MB. 20MB는 압축 목표일 뿐 보장값/강제 규칙이 아니다.
- 재학생 파일은 TUS(6MB 조각)로 직접 전송하고, 같은 화면의 재시도 버튼으로 이어 올린다. 서명 토큰은 `/storage/v1/upload/resumable/sign` 전용 주소에 보낸다. `media-storage.js`가 서버의 기본 TUS 주소를 이 주소로 정규화하며 일반 업로드 RLS를 열지 않는다. 탭을 닫은 뒤의 업로드 복원은 제공하지 않는다. 파일 크기·Storage 기록을 확인한 뒤 제출을 허용한다.
- 화면의 음성 녹음은 MediaRecorder 지원 브라우저에서 제공하며 미지원 브라우저는 녹음 파일을 선택한다. 실제 iPhone MOV/HEVC·Safari 녹음 호환성은 운영 전 파일 시험 대상이다. 자동 동영상 압축·변환 서버는 아직 없다.
- 챌린지는 기존 `challenge_submissions`·legacy `recordings`를 유지한다. 새 업로드 경로는 `<uid>/<challenge>-<type>/<uuid>.<ext>`다. 같은 경로의 재사용으로 만료를 연장할 수 없다. 피드백 변경도 만료일을 연장하지 않는다.
- 만료 뒤에는 신규 재생 서명을 발급하지 않는다. 새 서명은 최대 10분이며 파일 만료일을 넘지 않는다. 삭제는 **Storage API**로 수행하며 메타데이터만 SQL로 지우지 않는다.
- 정리 워커는 최대 50개씩 임대 잠금으로 처리한다. 실패 시 1시간 후 재시도하고 피드백 관리자 화면에 실패 건수와 삭제 대기를 표시한다. 기존 파일 중 연결된 챌린지 자료만 초기 등록한다. 새 패턴의 미등록 파일과 제출되지 않은 업로드는 24시간 이후 정리한다. 알 수 없는 과거 고아 경로는 임의 삭제하지 않는다.
- `supabase/academy-cleanup.sql`은 10분 간격 예약이다. `MEDIA_CLEANUP_SECRET` + JWT가 필요하고 비밀값은 Vault에서 읽는다. 반복 적용 시 기존 같은 이름 예약을 교체한다. 예약 실패는 `net._http_response`·Cron 기록으로 확인한다.
