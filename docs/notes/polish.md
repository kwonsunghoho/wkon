- `polish.html` — **첨삭(2026-07-30 신설).** 진단(AI킬러)의 짝인 **처방** — 강점(지킬 것)·글 전체 방향·문장 단위 '지금 → 이렇게' 리포트. 유료 도구 2개(소재·킬러)가 둘 다 진단이라 **진단 직후 결제 의사가 가장 높은 시점에 제공할 처방 상품이 없던 문제**를 메운 것(오너 확정 — 리허설은 이 위의 상위 상품으로 보류, 자산은 `claude/rehearsal-wip`). 진입 2곳: 킬러 결과 dock `.dock-cta`('이 글 첨삭받기 · 첫 1회 무료/10크레딧') + answers.html 카드 이력·CTA. 입력부는 ai-killer.html 과 같은 문법(종류·항공사·문항·바텀시트·충전), 결과부는 dock 순회가 아니라 **통독하는 리포트**(그래서 dock 없음 — 액션은 리포트 끝).
  - **서버 = 별 함수가 아니라 `ai-killer` 함수의 `mode:'polish'` 분기.** 필요한 맥락(항공사 프로필·문항 매칭·답변 소유 확인·차감·자동 저장)이 킬러와 전부 같아서다 — 별 파일로 떼면 대한항공 프로필이 들어올 때 두 파일을 고쳐야 한다. 모델 Opus 5 · **effort high**(킬러는 medium — 첨삭은 처방의 질이 상품) · max_tokens 16000. 구조화 출력 + **상투어 사전을 첨삭 문장에도 돌려**(self-check) 걸리면 재생성 — fix 는 학생이 그대로 옮겨 쓸 수 있는 문장이라 킬러보다 더 절실하다.
  - **⚠️⚠️ 제출 전 프로브 게이트를 지우지 말 것**(`checkReady()` — features `polish` + `polish_table` 확인). 구버전 함수는 mode 를 몰라 요청이 **킬러 검사로 흘러가 3크레딧이 깎이고 밑줄 목록이 온다.** 배포 순서와 무관하게 안전한 건 이 게이트 덕분이다.
  - **⚠️ 서버 p-1: `answer_polishes` count 실패(마이그레이션 미적용) 시 반드시 차감 전에 `not_ready`.** 무시하고 진행하면 차감 키(`<answer_id>#p<이전횟수>`)의 횟수가 늘 0 → 두 번째부터 spend_credit 이 'already' 통과 — **첨삭이 영구 무료가 되는 과금 결함**이다.
  - **⚠️ 재검사 무차감 없음** — 킬러의 MAX_RECHECK 와 다른 점. 첨삭은 매 회 차감(무료는 가입 후 총 1회 — `credit_free_limits.polish`, DB 적용 완료). 고친 뒤 확인은 킬러(3)가 담당하는 설계 동선: **첨삭 → 고침 → 'KILL AI로 확인'**(결과 화면 링크가 같은 답변을 그대로 이어받아 넘어간다).
  - **⚠️ fix 는 학생이 쓴 사실만 재료로**(프롬프트 '첨삭의 선'). 없는 숫자·일화를 지어내면 학생이 그 거짓을 면접장까지 들고 간다 — 부족한 자리는 **(괄호 빈칸)**으로 남기고 화면이 그 괄호를 칠해 준다(`markBlanks`). 합격자 문장 모방·옮겨쓰기 금지는 킬러와 동일(결정 10).
  - 기록 = `answer_polishes`(migration `20260730130000_answer_polishes.sql` — **owner 실행 필요**). `ai_killer_checks` 를 본뜬 구조(1:N · on delete set null · 쓰기는 service role 만). 미적용 degrade: 첨삭만 '준비 중', 킬러·소재 영향 없음. 이력 복원은 `polish.html?polish=<id>`(차감 없음), answers.html 이 검사·첨삭 이력을 시간순 한 줄로 합쳐 그린다.
