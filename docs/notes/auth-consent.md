# 로그인·동의·개인정보 — 상세 기록

## 인앱 브라우저에서 구글 버튼 — 누르면 브라우저로 여는 우회 (2026-08-08 오너 지시, 같은 날 2차 개정)

인스타·카톡 등 인앱 웹뷰는 **구글이 로그인 자체를 정책으로 거부한다**(disallowed_useragent).
1차는 버튼 disabled + 이유 안내문이었는데 **같은 날 기각** — "아무리 친절하게 설명해도
그냥 안 된다고 생각하지, 읽어보는 사람은 없잖아"(오너). 죽은 버튼 + 글은 답이 아니다.
전면 삭제도 기각 그대로: 구글로 가입한 기존 회원이 로그인 길을 잃는다.

- **동작**: 인앱이면 login.html 이 ① 카카오 버튼을 첫 번째로 올리고 ② `.sub` 문구를
  '카카오 계정으로'로 교체. 구글 버튼은 **활성인 채로 두고**, 누르면 `inappGoogleDetour()` —
  안드로이드는 `MONC_INAPP_OPEN()`(크롬 인텐트)으로 이 페이지를 바로 열고, 아이폰은
  프로그램으로 못 열므로 그 자리에서 alert 한 줄(`MONC_INAPP_HOWTO` — 카톡/기타 문구 분기).
  일반 브라우저는 아무것도 안 바뀐다. **OAuth 로는 절대 안 보낸다.**
- **⚠️ 탈출 로직은 inapp.js 단일 소스**: `window.MONC_INAPP_OPEN(url)`(안드로이드 true /
  아이폰 false)과 `window.MONC_INAPP_HOWTO`(여는 법 문구). 배너 닫힘(sessionStorage)과
  무관해야 하므로 HIDE_KEY early return **앞에서** 내보낸다. 인텐트 URL·여는 법 문구를
  login 에 복사하지 말 것.
- **⚠️ 판정은 `window.MONC_INAPP` 단일 소스** — UA 목록 복사 금지. inapp.js 가 `defer` 라
  플래그·함수는 DOMContentLoaded 에야 있다(버튼 클릭 시점엔 항상 있다).
- **실패 방향은 '평소 화면'**: 플래그가 없으면(구버전 캐시·로드 실패) 우회 없이 평소 OAuth 로
  간다 — 인앱 잠금이 아니라 우회이므로 최악이 '구글 오류 화면'(1차 이전과 동일)이다.
- **인앱에서 카카오 OAuth 완주는 실측 완료**(2026-08-08 오너 폰 — "카카오 로그인 잘 되네").
  카카오는 구글 같은 웹뷰 차단 정책이 없다. 인앱 구글 버튼 탭 동작(안드로이드 크롬 열림 /
  아이폰 alert)은 아직 실기기 실측 전.

## 전화번호 필수 + 중복 가입 차단 — 2026-08-20 오너 확정

구글·카카오 이중 가입("아직 중복가입이 되거든?")의 최종 방어. 카카오가 이메일을 안 줘
자동 대조가 불가능하므로(아래 절), **유일한 공통 식별자인 전화번호를 저장 시점에 서버가
대조**한다. 아래 8-08 선택 강제 게이트(자진 신고)는 1차 방어로 유지 — 이 절이 사실 기반
2차 방어다(카카오→구글 역방향까지 잡는다).

- **전화번호는 가입 필수**: 온보딩 '나중에 할게요'(건너뛰기) 폐지 + `monc_onboard_done`
  기기 기억 폐지. `requireConsent()` 에 **가입 완성 가드** 추가 — 동의 통과 후 번호가
  없으면 `onboarding.html?returnTo=…` 로 보낸다(회원 페이지 12곳이 이미 이 가드를 부르므로
  주소창 우회 불가). 예전에 건너뛴 기존 회원도 다음 방문 때 한 번 입력하게 된다.
  ⚠️ 온보딩 자신은 제외(무한 이동), **실패 방향은 통과**(fail-open — 조회 오류로 회원
  전체가 잠기면 안 된다). 동의 게이트(법적 필수) 판정 자체는 안 건드렸다.
- **저장은 `MONC.saveMyProfile()` → 서버 RPC `save_my_profile` 한 곳**(migration
  `20260820170000_phone_dedup`). 온보딩·마이페이지 연락처 저장 + **apply·lecture 의 신청 시
  프로필 백필 3곳**이 함께 쓴다(백필은 중복이면 조용히 건너뛴다 — 신청·결제 흐름은 안
  건드린다). admin 회원 편집의 직접 update 만 관리자 권한으로 남는다. 같은 정규화
  번호(`monc_norm_phone` — 신청 중복 방지와 동일 함수)의 다른 회원이 있으면 저장을 막고
  `{ code:'dup_phone', provider, me_fresh }` 를 준다. RPC 미적용 환경은 PGRST202 를 감지해
  구 직접 update 로 조용히 폴백(대조 없이 저장 — 사이트는 안 멈춘다).
- **중복이면 선택 강제**(onboarding `#dupView` — 8-08 게이트와 같은 원칙, 안내문+버튼 금지):
  '기존 계정으로 로그인하기' / '번호를 잘못 입력했어요'. **`me_fresh`(계정 생성 60분 내)일
  때만 삭제 흐름** — `MONC.deleteMyAccount()` 재사용 후 세션만 끝내고 login 으로(결제·신청
  기록은 `applications.member_id` 가 `on delete set null` 이라 남는다). **fresh 아니면 삭제
  없이 로그아웃만**(예전에 번호 없이 가입해 기록이 쌓인 계정을 지우면 사고). 번호를 옮기고
  싶은 잔여 케이스는 메일 문의 → admin 이 정리한다.
- **"전화번호로 남을 조회할 창구 금지" 규칙의 승인된 예외**(오너 확정 2026-08-20 — 기존
  계정의 로그인 수단(구글/카카오)까지 안내): 짝으로 **계정당 24시간 10회 시도 제한**
  (`phone_save_attempts` — RLS 잠금, RPC 만 쓴다)을 건다. provider 외 다른 정보(이메일 등)는
  안 내보낸다. 제한·안내 수위를 완화하려면 오너 확인 먼저.
- **가라(가짜) 번호는 못 잡는다**(오너 인지) — 본인인증이 아니라 정직한 실수 방지 장치다.
  문자 본인인증을 붙일 때 이 RPC 앞단에 끼운다. 카카오 비즈앱 전환 시 카카오 쪽은 인증된
  번호·이메일을 OAuth 로 받을 수 있다(후속 검토 항목).
- 저장형은 하이픈 표준형(`MONC_PHONE.format` — `010-1234-5678`)으로 통일: 서버 정규화
  대조·마이페이지 마스킹·문자 발송이 한 형으로 맞는다. +82 붙여넣기도 국내형이 된다.

## 휴대폰 본인인증 — 2026-08-26 (KG이니시스 통합인증 · 포트원 경유)

위 절이 "문자 본인인증을 붙일 때 이 RPC 앞단에 끼운다"로 남겨 둔 그 후속. 가라 번호가
원천 차단된다. 설계 원장: `docs/superpowers/specs/2026-08-26-identity-verification-design.md`.

- **경로는 포트원 V2**(`PortOne.requestIdentityVerification`) — 이니시스 직접 연동 금지
  (SEED 암호화·결과수신 서버를 자작해야 한다). 이니시스 상점관리자 KEY(MID·API KEY·SEED IV)는
  **포트원 콘솔에만** 들어간다 — 비밀값, 레포 반입 금지. **본인인증 채널 키(공개 가능)는
  `pay-methods.js` 의 `identityChannel` 한 곳.** 비우면 온보딩이 인증 UI 를 안 켠다(스위치 겸용).
  이니시스 상점관리자 **도메인 등록에 `monc.ai.kr` 필수** — 미등록이면 인증창이 안 뜬다.
- **온보딩 인증 모드 켜는 조건 셋**: 채널 키 + 포트원 SDK 로드 + `verify-identity` 프로브.
  하나라도 빠지면 **직접 입력 폼 폴백**(전화번호 필수·중복 차단 그대로) — 죽은 버튼 금지.
- **판정은 전부 서버**: 브라우저는 `identityVerificationId` 하나만 보낸다. verify-identity 가
  포트원 API 재조회(`VERIFIED` 확인) → RPC `apply_identity_verification`(**service_role 전용** —
  authenticated 에 열면 화면이 인증 없이 아무 실명·CI 나 넣는다) → **CI 우선 중복 판정**
  (같은 사람이면 번호를 바꿔도 잡힌다) + 번호 대조 → `members` 실명·번호·생년월일·CI·DI·
  `verified_at` 저장 + `identity_verifications` 감사 기록(verification_id UNIQUE = 재사용 차단).
  중복이면 기존 `dup_phone` 모양 그대로 → 온보딩 `#dupView` 선택 강제 재사용.
- **verified 회원은 name·phone 잠금**: `save_my_profile` 이 입력을 무시하고 전공만 갱신
  (`phone_locked:true`). 마이페이지 연락처 칸도 잠금 표시("본인인증으로 확인된 번호예요").
  번호 변경은 문의 → admin. **인증 회원의 번호를 화면 저장으로 덮는 경로를 다시 열지 말 것.**
- **모바일은 리다이렉트 복귀**: 포트원이 온보딩 주소에 `identityVerificationId` 쿼리를 붙여
  돌아온다 — 로드 시 감지해 서버 확정, 쿼리는 `history.replaceState` 로 지운다(새로고침 재확인
  방지). 인증창으로 나가는 버튼이라 bfcache 복귀 시 버튼 복원(`_idvRestore`)을 같이 단다.
- **적용 범위는 신규 가입 온보딩만**(오너 확정) — 기존 회원 재인증 강요 없음. 이미
  verified 인 회원이 온보딩에 다시 오면 인증을 다시 시키지 않고 확인된 값만 보여 준다.
- CI·DI·생년월일은 privacy.html 에 이미 고지돼 있다(2026-08 심사 대응 때 선반영).
  `verified_at` 등 신규 컬럼은 **공용 `getMyProfile()` 셀렉트 금지** — 방어 조회만(major 전례).

## 카카오 중복 가입 차단 — 2026-08-08 오너 지시(선택 강제 구조)

구글로 가입한 회원이 카카오로 로그인하면 **항상 별개의 새 계정이 생긴다** — 카카오는
이메일을 아예 안 받아서(`profile_nickname` 만 — KOE205 회피, supabase-config.js) 서버가
같은 사람인지 대조할 방법이 없다. 자동 링크·이메일 대조 RPC 는 **원리적으로 불가능**하다.

- **막는 자리는 동의 게이트 하나뿐**: 새 계정이 만들어진 직후이자 가입 확정(동의) 전.
  `showConsentGate(session)` 이 ① 동의 기록 없음(isReturning=false) ② provider=kakao 일 때
  동의 폼을 감추고(`#consentView.choosing`) `#dupChoice` — "몬크에 처음 가입하시나요?" —
  를 먼저 보인다. 동의가 끝난 뒤엔 늦다.
- **⚠️ 안내문+버튼(수동 상자)으로 되돌리지 말 것** — 1차 구현이 그거였고 당일 기각:
  "아무리 친절하게 설명해도 안 읽는다"(오너). 답하기 전엔 동의 폼이 안 보이는
  **선택 강제**가 핵심이다. '네, 처음이에요'(`#dupNew`) 한 탭이면 평소 게이트로 간다.
- '아니요, 구글로 가입한 적 있어요'(`#dupGoogle`) → confirm → **기존
  `MONC.deleteMyAccount()` 재사용**(방금 만들어진 빈 계정 — 두 벌 금지) → 세션만 종료 후
  로그인 뷰 복귀. ⚠️ `MONC.signOut()` 금지 — 홈으로 이동해 버려 구글로 이어갈 수 없다.
  `MONC.sb.auth.signOut()` 으로 세션만 끝낸다. 인앱이면 `inappGoogleDetour()` 와 같은 길
  (안드로이드 크롬 인텐트 즉시 / 아이폰 여는 법 alert).
- 실패 방향은 '평소 게이트': provider 판정이 안 되면 선택 단계 없이 동의 폼이 바로 보인다.
  게이트의 다른 버튼들과 서로 disabled 를 걸어 이중 삭제를 막는다.
- ⚠️ 자동 삭제·자동 차단으로 바꾸지 말 것 — 카카오만 쓰는 진짜 신규 가입자가 대부분이라
  본인 확인(자진 신고) 없이 막으면 정상 가입이 막힌다.

## 로그인 뒤 '가려던 화면' 복귀 — returnTo (2026-08-02 오너 "로그인하면 마지막 페이지로 돌아가야지")

- `requireSession()`·`requireConsent()` 가 `login.html?returnTo=<파일명+쿼리+해시>` 로 보낸다(`pageRef()` — 파일명만, 절대경로 금지: GitHub Pages 하위 경로에서도 성립).
- OAuth 왕복은 쿼리가 사라지므로 **login.html 도착 즉시 sessionStorage(`monc_return_to`)에 보관**하고, `routeByRole()` 이 꺼내 쓴다(1회용 — 꺼내면 지운다). 온보딩으로 갈 땐 `onboarding.html?returnTo=…` 로 넘긴다(온보딩 `nextPage()` 가 이미 읽는다).
- ⚠️ **열린 리다이렉트 방지 — `safeReturnTo()` 를 지우지 말 것**: `파일명.html(?…)(#…)` 형식만 통과, `login/onboarding` 자신 제외. 외부 URL·`//`·`javascript:` 는 형식에서 걸러진다(2026-08-02 Playwright 실측: 정상값 보관·악성값 거부 확인).
- 되돌리면 안 되는 이유: 도구(소재·킬러·첨삭·기출) 때문에 가입한 사람이 전부 마이페이지에 떨어져 유입이 끊겼다. 관리자도 returnTo 가 있으면 그쪽 우선(없으면 admin.html).

## login.html · 동의 게이트

- `login.html` — 구글·카카오 OAuth. **두 뷰**: `#loginView`(로그인 버튼 — 항상 활성) / `#consentView`(최초 1회 동의 게이트). **⚠️ 법적 필수(2026-07-15 개편):** 약관·개인정보 동의는 **가입 시 딱 한 번** 받는다 — OAuth는 로그인 전 사용자를 식별할 수 없어 구 방식은 "로그인할 때마다" 체크를 강요했다(오너 피드백). 이제 OAuth 복귀 후 `hasConsented()`가 false면 게이트를 띄우고, `#agreeChk`(만14세+약관·개인정보)를 **사용자가 직접 체크해야** `#consentGo`가 열린다. 동의 시 `MONC.recordConsent()`가 `members.agreed_at`·`terms_version`에 기록 → 이후 **어떤 기기에서도 다시 묻지 않음**. 거부 시 `signOut()`. **금지:** 체크박스 사전 체크·"간주 동의"·게이트 삭제. 회원 페이지(`mypage`·`onboarding`)는 `MONC.requireConsent()`로 가드 — 동의 없이 우회 불가. 약관 개정 시 `supabase-config.js`의 `TERMS_VERSION`을 올리면 전원 재동의.
- **동의 마이그레이션** (`20260715120000_member_consent.sql`, owner 실행): `members.agreed_at`·`terms_version` + **`delete_my_account()` RPC**. **미적용이어도 동작** — `getConsent()`가 조회 실패를 감지해 계정별 로컬 기록으로 폴백하고, 나중에 컬럼이 생기면 `hasConsented()`가 서버로 백필한다. ⚠️ `getMyProfile()` 공용 select엔 넣지 말 것(컬럼 미생성 시 프로필 조회 전체가 깨짐 — `major`와 동일 방어).
- **⚠️ 동의 3대 함정(리뷰에서 실제로 터진 것 — 되돌리면 법적 리스크):**
  1. **로컬 동의 캐시는 계정별 키** `monc_consent_v1:<uid>`. 무기명 기기 키로 되돌리면 **공용·가족 기기에서 A의 동의 흔적으로 신규 회원 B가 게이트를 건너뛰고, B 명의의 허위 동의 기록이 서버에 저장**된다.
  2. **거부 = 즉시 파기.** OAuth가 끝나는 순간 `handle_new_user()` 트리거가 `members`(이름·이메일) 행을 만든다 → 게이트에서 '동의하지 않고 나가기'는 `MONC.deleteMyAccount()`로 **계정을 삭제**한 뒤 로그아웃한다(RPC 미적용 시 이름·이메일만 즉시 null로 비우는 폴백). 로그아웃만 시키면 미동의자·만14세 미만의 개인정보가 잔존한다. privacy.html §2가 이 흐름을 고지한다.
  3. **동의 가드는 회원 페이지 전체에.** `mypage`·`onboarding`·`sojae`·`admin` 모두 `MONC.requireConsent()`를 호출한다 — 한 곳이라도 빠지면 주소창으로 게이트를 우회할 수 있다.
- **⚠️ 밖으로 나갔다 뒤로 돌아오는 화면은 상태를 되돌려야 한다(bfcache · 2026-07-24 오너 신고 "카카오 로그인 눌렀다 뒤로가기하니 이지랄"):** 브라우저는 페이지를 떠날 때 문서를 **그대로 얼려 뒀다가 뒤로가기 때 스크립트 재실행 없이 되살린다.** 그래서 '버튼 비활성 + …중 문구'를 띄운 채 외부(카카오/구글 OAuth·결제사)로 나가는 화면은 돌아왔을 때 **비활성 상태의 버튼이 그대로 남아 로그인·결제를 다시 할 수 없다.** 모바일은 결제도 리다이렉트 방식이라 `requestPayment`의 promise가 영영 안 끝나 `finally`도 못 돈다 — 스스로 풀리지 않는다. **처리 규칙: 입력값이 없는 화면은 통째로 새로고침**(`login`·`mypage`·`answers`: `pageshow`에 `location.reload()`), **입력값이 있는 화면은 버튼만 되돌린다**(`apply`·`lecture`: 결제 시작 시 `_payRestore` 클로저를 담아 뒀다가 `pageshow`에서 호출 — 이름·전화·선택한 챌린지는 살려야 하므로 reload 금지). 외부로 나가는 버튼을 새로 만들면 이 처리를 같이 달 것.
- `terms.html`, `privacy.html` — footer 법적 페이지. privacy는 실제 스택 기준(수탁자 Supabase 서울/Google/Kakao, 국외이전 고지, CPO 권성호, 14세 미만 조항). 수집 항목·수탁자 변경 시 갱신.
- **`applications` RLS** (`20260711120000_applications_rls.sql`, owner 실행): INSERT 공개(비회원 신청), SELECT 관리자+본인, UPDATE/DELETE 관리자만.

## onboarding.html(구 CLAUDE.md Pages 항목)

- `onboarding.html` — 첫 로그인 후 `login.html`의 `routeByRole()`이 `!profile.phone`이면 여기로(건너뛰기·`monc_onboard_done` 은 2026-08-20 폐지 — 위 '전화번호 필수' 절). 이름·전화·전공(major) → `MONC.saveMyProfile()`(RPC 경유 — 중복 번호 차단). ⚠️ `members.major`는 migration `20260708120000_member_major.sql`(owner 실행); 미적용 시 major만 방어적으로 무시(RPC 폴백 경로가 처리). `getMyProfile()` 공용 셀렉트엔 major 미포함(컬럼 미생성 시 전체 조회가 깨지므로 별도 방어 조회).

## 2026-08-02 동의 게이트 — 파괴적 동작에 이름과 확인 (B-1)

`login.html` 의 '동의하지 않고 나가기'가 **confirm 없이 바로 cascade 삭제**를 호출했다.
게이트 화면에 '계정이 삭제된다'는 말이 한 줄도 없었다.

- ⚠️ **삭제 호출 자체는 법적 필수라 그대로 둔다**(거부 = 즉시 파기). 없앤 게 아니라 확인을 더한 것.
- 라벨 → **'동의하지 않고 계정 삭제하기'**. 파괴적 동작이 이름에 드러나야 한다.
- `confirm` + 지워질 것 명시.
- **이 화면을 보는 사람은 두 종류다.** ① 방금 가입한 사람(지울 것이 빈 계정) ② 약관 개정으로
  재동의를 요구받은 기존 회원(저장한 답변·경험 카드·구매한 크레딧이 걸려 있다).
  ②에게는 **'나중에 하기'(로그아웃만)** 를 연다 — '나가기'로 읽고 오탭하면 몇 달치가 사라진다.
  판정은 `MONC.getConsent()` 의 `agreed_at` 유무. `undefined`(컬럼 미생성)면 **안전한 쪽인
  기존 회원으로 취급**한다.
  ⚠️ '나중에 하기'가 **간주 동의가 아니다**: 동의 기록이 없으므로 다음 로그인에 게이트를
  다시 만나고 회원 페이지는 `requireConsent()` 가 계속 막는다. 결정을 미루는 길일 뿐이다.
- ⚠️ 지금은 `TERMS_VERSION` 이 최초값이라 ②가 0명이다. **약관을 올리는 순간 전원이 ②가 된다** —
  그때 급히 만들면 늦는다.

## 2026-08-02 회원 탈퇴 창구 (B-2)
`privacy.html` 이 회원 정보를 '회원 탈퇴 시까지' 보관한다고 고지하는데 학생이 그 요구를
행사할 창구가 사이트에 없었다(`deleteMyAccount()` 호출처가 동의 게이트 하나뿐).
- 마이페이지 '내 정보' 접이 맨 아래. **접이 안에 둔 것은 의도** — 자주 누를 것이 아니고
  로그아웃 버튼과 나란히 두면 오탭 위험이 커진다.
- confirm + '탈퇴' 타이핑 2단계. 삭제는 **동의 게이트와 같은 `MONC.deleteMyAccount()`** 재사용
  (두 벌로 나누면 한쪽만 고쳐져 데이터가 남는다).
