# 매일 답변 프로그램 — 제품 명세 (MVP · 2026-07-30)

정의: **"매일 한 문제씩, 내 경험으로 완성하는 항공사 면접답변 프로그램."**
기출문제는 유입 콘텐츠이고, 제품의 핵심 가치는 경험 수집 → 적합 경험 매칭 → 부족 사실 질문 → 학생 직접 작성 → 사실 안에서만 첨삭 → 연구원 검수 → 전 과정 데이터화다.

> **화면 이름은 '일문일답'**(2026-08-07 오너 개명 — 구 '필수 기출 하루 한 개' ← 구 '매일 기출'). '매일 답변 프로그램'은 시스템 이름(admin 탭·마이그레이션·문서), '필수 기출'은 1차 상품 구성(전 항공사 공통 기출 30) 이름으로만 남는다. 학생이 보는 자리는 전부 일문일답으로 통일(2026-08-09 nav.md 참조).

> **'경험 창고 → 소재 창고' · '경험 카드 → 소재 카드'**(2026-08-16 오너 개명). 파일명(`experiences.html`)·테이블(`experience_cards`)·클래스·상태 코드는 그대로 — 화면 글자만. 바꾼 자리: experiences(제목 3벌·머리·h1·목록·버튼·폼) · program(고르기 단계 문구·버튼·근거 경고) · programs(3단계·창고 링크) · program-common(단계 라벨 '소재 고르는 중'·데모 안내) · mypage/login/admin/review-desk 의 '경험 카드' 문구 · **index.ts 응답 문구·근거 라벨(FN_VERSION `2026-08-16a`·PROMPT_VERSION `ap-2026-08-16a` — 재배포해야 서버 문구까지 새 이름, 안 해도 동작 무관)**. 이 문서를 포함한 과거 기록의 '경험 창고·경험 카드'는 개명 전 이름이다. AI 프롬프트의 판정 지시는 안 건드렸다(명칭 라벨만).

## 기본 정책 (default_product_policy 반영)

- **1차 상품은 '필수 기출'(전 항공사 공통, airline null — 2026-07-30 오너 확정).** 어느 항공사든 무조건 나오는 필수 기출 30개를 하루 한 문제씩 먼저 완성하는 구성. 항공사별 프로그램은 구조만 갖춰 두고 후속.
- 프로그램은 항공사 단위(또는 공통) 상품. 기본 20일(1~60 관리자 조정), 하루 한 문제.
- 공개 방식 3종: `daily`(기본) / `all` / `by_date`. 지난 문제는 항상 다시 볼 수 있고, 미래 문제는 서버가 내용 자체를 내보내지 않는다.
- 이용권: MVP는 관리자 지급(`admin`) + 무료 프로그램 자가 등록(`promo`). `price>0` 결제는 후속(verify-payment `programId` 분기 자리만 설계).
- 임시 저장: 초안은 세션에 자동 저장(0.8초 디바운스), 다듬기 글은 localStorage + 마일스톤 버전.
- 확정 후에도 수정 이력은 버전(append-only)으로 전부 남는다. 확정본은 답변노트(`answers`)로 합류해 기존 AI킬러·첨삭이 그대로 붙는다.
- 질문은 은행(`interview_questions`)에 있고 배치(`answer_program_days`)로 재사용된다. 항공사·전형·유형 10종·출처 신뢰도(검증/제보/예상)로 분류.

## 학생 흐름 (core_user_flow 구현 상태)

1. 등록 → 대시보드(일차 타임라인) → 오늘 문제 + 의도·주의점(접기)
2. 경험 고르기: 카드 목록 + AI 추천(fit: good/partial/weak + 부족 사실) + 새 카드 링크 + '경험 없이 바로 쓰기'
3. 사실 모으기: AI 추가 질문 1~2개씩(왜 묻는지 포함), '기억나지 않아요' 허용, 세션당 8문답 상한
4. 초안: 학생이 직접 작성(60자 미만이면 첨삭 거절 — 대필 방지), 유형별 구조 힌트
5. AI 첨삭: 사실 정리(확인/누락/충돌) + 적합성 판정 + **두 버전**(말투 유지형 A / 전달력 강화형 B) + 문장별 근거(탭하면 근거 시트) + 근거 없는 문장 빨간 표시 + 진정성 지표 7항목 + 예상 말하기 시간
6. 다듬기: 버전 선택 → 직접 수정 → 재첨삭(하루 3회 상한) / 말하기용 정리 / 검수 요청 / 최종 확정
7. 확정: final 버전 + answers 합류 + 경험 use_count 증가 + 예상 꼬리질문 연습 + KILL AI 연계 링크 + 모델 학습 동의(선택) 노출

## 연구원 흐름

대기열(오래된 순) → 열면 자동으로 '검수 중' 전환 → 좌: 문항·의도·경험 카드·문답·학생 원문·AI 버전(근거·경고 포함)·품질 지표 / 우: 편집기 + 수정 코드(분류별) + 코드별 이유 → 승인 또는 보완 요청(코드 필수). 결과는 학생 화면 `revision_requested`/`approved` 상태로 전달.

## 답변 진정성 지표 (authenticity_quality_score)

경험 근거 25 · 구체성 20 · 본인 행동 15 · 판단·가치관 15 · 말투 자연스러움 10 · 질문 적합성 10 · 일관성 5.
**경험 근거 25점은 AI 자평이 아니라 서버 측정값**(문장 근거 커버리지 × 25). 합격 예측으로 쓰지 않는다는 문구를 화면에 고정.

## 잘라낸 것 (not_in_initial_mvp + 이 MVP의 추가 보류)

- 음성 답변 입력(구조상 experience_facts.source='voice' 자리만 존재)
- 결제 연동(이용권 테이블·payment_id 자리만) / 자체 파인튜닝 / 영상·발성 분석 / 다국어 / 자동 배정
