# 매일 답변 프로그램 — 개인정보·동의 (2026-07-30)

학생의 경험·답변은 개인정보이자 이 서비스의 가장 민감한 데이터다.

## 동의 2단 분리 (privacy_and_consent 1·2·3 구현)

| 동의 | 저장 위치 | 방식 |
|---|---|---|
| 서비스 이용(약관·개인정보) | `members.agreed_at`(기존, 가입 시 1회) | 기존 게이트 그대로 — 전 페이지 `MONC.requireConsent()` |
| **모델 개선(학습) 활용** | `member_consents(kind='model_training')` | **선택 동의** — 확정 화면의 체크박스, 기본 꺼짐, 언제든 철회. 미동의여도 모든 기능 사용 가능 |

미동의 데이터는 서비스 제공(첨삭·검수)에는 쓰이고, 학습 데이터셋 추출에서는 제외한다.

## 데이터 최소화·비식별 (4·9·10·11)

- 경험 카드에 `has_pii` 표시 칸 — 학생이 실명·매장명 포함 여부를 스스로 표시하고, 화면이 일반화(○○카페)를 권한다.
- 학습·분석용 추출 시 절차(후속 작업 시 지킬 것): consent=true 회원만 → 이름·연락처·이메일 미포함(테이블 조인 금지) → 카드 has_pii=true 는 수동 검수 후 포함 → member_id 는 가명 키로 치환.
- 모델 공급자(Anthropic API)로 나가는 것: 기출 문항 메타 + 학생 본인의 초안·카드 필드·문답·말투 프로필 + 감점 사전(coach) + 항공사 프로필 요약. **다른 회원의 데이터는 절대 실리지 않는다**(소스 조립이 본인 행만 조회).
- 서버 로그(console.log)에는 세션 id·개수·usage 만 남기고 글 본문을 남기지 않는다.
- 소스코드에 키·개인정보 하드코딩 없음(ANTHROPIC_API_KEY 는 Supabase 시크릿).

## 접근 권한 (7)

| 역할 | 접근 |
|---|---|
| 학생 | 본인 데이터 전부(RLS member_id) — 확인·수정·삭제 가능(5·6) |
| 연구원(`researchers`) | 세션·버전·카드·사실·말투 **읽기** + 검수 상태 전이 + researcher_edit 작성. `members` 도 select(이름 표시용) — **내부 인력 전제**, admin 탭에서만 지정 |
| 관리자 | 전체. 이용권·연구원 지정·수정 코드 관리 |
| service role(중계 함수) | JWT 로 본인 확인 후 그 회원 범위에서만 조회·기록 |

## 삭제·보존 (6·8)

- 학생의 자기 삭제: 카드·사실·세션은 본인 RLS delete 허용(세션 삭제 시 버전 cascade — 본인 데이터 자기결정권). 계정 삭제는 기존 `delete_my_account()` → members cascade 로 프로그램 데이터 전부 소거.
- 감사 추적: 검수·수정은 append-only 버전(author_id·created_at)이 그 자체로 감사 로그다. 관리자 지급·회수는 program_enrollments 행(source·created_at)으로 남는다.
- 대기·검수 목적이 끝난 데이터의 별도 파기 정책은 운영 개시 전에 오너와 확정할 것(현재는 회원 탈퇴 시 cascade 만).
