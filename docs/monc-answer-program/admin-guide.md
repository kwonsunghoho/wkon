## 처음 켜는 순서

1. SQL Editor 에서 `20260730150000_answer_program.sql` 실행(재실행 안전).
2. (선택) `docs/monc-answer-program/seed-demo.sql` 실행 — 제주항공 무료 5일 + 티웨이 예시.
3. Edge Functions > Deploy new function > 이름 `answer-program` > `supabase/functions/answer-program/index.ts` 전체 붙여넣기 > Deploy. (ANTHROPIC_API_KEY 는 프로젝트 공용 시크릿이라 추가 등록 불필요)
4. **verify-payment 재배포**(이용권 결제에 필요 — 2026-07-30 배포 완료) — 기존 함수 코드 전체를 `supabase/functions/verify-payment/index.ts` 로 교체 > Deploy. 확인: anon key 로 body `{"paymentId":"probe","programId":"00000000-0000-0000-0000-000000000000"}` → `not_authenticated` 면 신버전(JWT 확인이 프로그램 조회보다 먼저), 구버전은 `bad_request`. 결제 생성·DB 쓰기 없는 안전한 프로브다.
5. 배포 확인 — 로그인 없이:
   `POST /functions/v1/answer-program` body `{"probe":true}` (anon key) → `version`·`programs`·`questions` 숫자가 나오면 정상. 404=미배포.
6. admin '답변 프로그램' 탭에서 기출 입력 → 프로그램 생성 → '일차 배치' → 가격 확인 → 공개.

## 탭 사용법 (admin.html '답변 프로그램')

- **① 기출 은행**: 질문 원문 + 항공사/유형/전형/신뢰도. '고급'에 의도·평가역량·꼬리질문 — 채울수록 학생 화면·AI 질이 올라간다. 일괄 등록은 탭 구분(질문⇥항공사코드⇥유형⇥의도). ⚠️ 의도 비어 있으면 목록에 경고가 뜬다.
  - **목록 필터('유형별 보기')는 질문 유형이다**(2026-07-31 오너 요청 — 구 항공사 select 대체). 실존하는 유형만 개수와 함께 칩으로 세우고, 없는 유형은 칩을 만들지 않는다(신청자 현황 세부 필터와 같은 규칙). 사전(`AP_QTYPES`)에 없는 구 데이터는 원본 코드 그대로 뒤에 붙어 보인다 — 눈에 띄어야 고칠 수 있으니 숨기지 말 것. 칩은 이미 받아 둔 `_apQ` 안에서 거르므로 **누를 때 다시 조회하지 않는다**(`renderApQuestions()`), 항공사는 각 줄 부제에 그대로 남고 **일차 배치 후보는 여전히 항공사로 좁혀진다**(그 항공사+공통).
- **② 프로그램**: 가격 칸 — **비움=지급 전용 / 양수=유료 판매(카드·간편결제)**. 0은 판매되지 않는다(체험판 없음 — 무료로 줘야 하면 ③ 이용권 지급). 항공사에 '공통'을 고르면 필수 기출 프로그램. '일차 배치'에서 일차마다 기출 선택(그 항공사+공통 기출만 후보). by_date 정책이면 일차별 날짜 칸이 생긴다.
- **③ 이용권**: 회원 검색(2자+) → 클릭 즉시 지급. 시작일을 지정하면 그날이 1일차. 회수해도 학생 작성 기록은 남는다.
- **④ 연구원**: 검색 → 클릭 지정. 연구원은 `review-desk.html` 접속 + 학생 이름·자료 열람 권한이 생긴다 — 내부 인력만.
- **⑤ 수정 코드**: 기본 31종 시드. 끄기(비활성)를 권하고 삭제는 없다(과거 검수 기록의 라벨이 사라진다).
- **⑥ 진행률**: 프로그램별 이용권 수·완성 답변 수·상태 분포.

## 자주 물을 것

- **학생이 "오늘 문제가 안 열려요"** → 이용권 시작일 확인(1일차 기준). 관리자·연구원 계정은 전 일차가 열려 보인다(직접 확인 가능).
- **관리자 확인용 통로(2026-08-15 오너 지시)** — 관리자 계정은 **이용권 없이** 전 일차를 실제로 진행할 수 있다(구매 화면을 건너뛰고 작성 흐름, 세션 심판 트리거도 관리자 면제). **비공개 상품도 허브 목록에 '비공개' 표시로 뜬다**(학생·비로그인은 RLS 가 걸러 안 보인다) — 공개 전에 AI 첨삭 품질을 본인 계정으로 확인하는 용도. 화면 위에 '운영진 확인용' 한 줄이 뜨고 기본 일차는 1일차부터. ⚠️ 연구원(비관리자) 계정은 전 일차가 **보이기만** 한다 — 이용권 없이 시작을 누르면 '세션을 열지 못했어요(not_enrolled)'가 뜬다(DB 트리거가 관리자만 면제).
- **첨삭이 '준비 중'** → probe 로 함수 배포 확인, `sessions_table` false 면 마이그레이션 미적용.
- **첨삭 상한** → 세션당 하루 3회(서버 상수). 더 필요하면 함수의 `MAX_REVISE_PER_DAY` 수정 후 재배포.
- **검수 요청이 안 보인다** → review-desk 는 연구원 지정된 계정만. 대기열은 오래된 순.
- **기출 삭제하면?** → 배치된 일차는 '문제 준비 중'으로 뜬다(신청 데이터는 무영향). 은행에서 숨기기(노출 토글)를 권한다.
