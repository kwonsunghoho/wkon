# 소재 발굴 v2 — 교재 방법론 이식 (1단계)

> 2026-07-30 오너 확정(브레인스토밍 세션). 배경: 오너가 소재 발굴의 네 영역(되묻기 질·다듬기 질·
> 문항 풀·흐름 구조) 전부를 부족하다고 진단했다. 원인은 AI킬러 때와 같다 — 프롬프트가
> 2026-07-05에 받은 짧은 지침 그대로라 **연구진의 실제 방법론이 들어 있지 않다.**
> **이 문서가 소스오브트루스.** '답변 만들기 상품'(필수 기출 30, 총량제)과는 **별개 작업**이다(오너 확정).

## 무엇인가

소재 발굴(sojae.html + sojae-chat)을 몬크 정규반 교재의 방법론으로 재구축한다.
구조의 핵심 전환: 지금은 **문제가 먼저**(오늘의 문제 → 대화 → 그 문제의 답변 1개)인데,
교재는 **경험이 먼저**다(경험 정리 → 역량 재해석 → 어떤 기출이 와도 그 소재를 꺼내 씀).
고도화가 끝나면 학생 손에는 답변과 함께 **재사용 가능한 소재 자산(소재 카드)**이 남는다.

## 확정 사항

| # | 결정 | 이유 |
|---|---|---|
| 1 | 산출물 = **소재 자산 + 답변** (교재 방식) | 교재의 '경험정리 → 재해석 → 변형 대응' 루프가 이 도구의 최종 형태. 답변 1개짜리 구조로는 변형 질문에 못 써먹는다 |
| 2 | 문제 유형을 **BEI 5유형**으로 재편 | 교재와 도구의 언어가 같아진다. 취미·영화 같은 개인신상 문항이 제자리를 찾는다 |
| 3 | 유형 **코드는 4종 유지 + `personal`만 신설**, 라벨만 교체 | 기존 문제·답변 데이터 무이동. 체크 제약 확장만으로 끝난다 |
| 4 | 소재 카드는 **다듬기 AI가 자동 생성** | 학생 추가 부담 0. 교재 원형(학생이 재해석 표 직접 작성)은 온라인에서 이탈 지점이 된다 |
| 5 | 다듬기 **2크레딧 유지** | 산출물이 늘어도 호출은 한 번 — 원가 증가 미미. 하루 무료 5의 '소재 1 + 킬러 1' 구조도 유지 |
| 6 | **2단계 분할** — 1단계 = 지능 고도화 + 소재 서랍, 2단계 = 문제↔소재 매칭 추천 | 핵심 가치부터 빠르게 내고 실측 반응을 보고 2단계 판단 |
| 7 | ⚠️ **이탈 가드: 다듬기 버튼은 지금처럼 두 번째 답변부터 항상 열려 있다** | AI의 "재료 충분" 판정은 추천 시점일 뿐 관문이 아니다. 게이트로 만들면 급한 학생이 이탈한다 — 유일하게 실재하는 이탈 위험이라 설계로 고정 |
| 8 | ⚠️ **교재 노하우는 공개 레포에 넣지 않는다** | 프롬프트 본문은 `sojae_playbook` 테이블(RLS 닫힘)에, 시드는 SQL로 대화창에 제공해 콘솔에서 실행. 레포에는 스키마만 |
| 9 | **계측 포함** | 되묻기 턴 수·다듬기 전환율 실측 데이터가 없어 이탈 예측이 불가능했다. 이번에 심어 2단계 판단 근거로 쓴다 |

## 유형 체계 — BEI 5유형

| 코드 | 구 라벨 | 신 라벨 | 교재 BEI |
|---|---|---|---|
| `experience` | 경험 발굴형 | 과거경험검증형 | 과거경험검증 |
| `values` | 가치관형 | 직무핵심역량형 | 직무핵심역량 |
| `judgment` | 상황 판단형 | 상황대처형 | 상황대처능력 |
| `company` | 정보·기업 분석형 | 기업관심도형 | 기업관심도 |
| `personal` | (신설) | 개인신상형 | 개인신상 |

- 마이그레이션: `questions.category`·`answers.category` **체크 제약 2곳에 `personal` 추가**. 데이터 이동 없음.
- 라벨 소비처(전부 갱신): `sojae-common.js`의 `CAT_LABEL`(sojae·mypage·admin이 공유),
  `answers.html`·`mypage.html`의 자체 라벨/칩, admin 문제 관리 탭의 유형 select, 서버 `CAT_LABEL`·`ASK_TYPES`.
- ⚠️ CLAUDE.md의 "유형을 새로 만들지 않는다" 원칙과의 관계: 이 재편은 **단일 체계의 확장**이다.
  questions와 answers가 계속 같은 코드를 공유하므로 필터가 갈라지는 문제(원칙이 막으려던 것)는 생기지 않는다.
- `sojae.html`의 canned 폴백 `FOLLOWUPS`에도 `personal` 세트를 추가한다(미배포·실패 시 폴백이 깨지지 않게).

## 되묻기 — "몇 번 물었나"에서 "뭐가 모였나"로

- **재료 체크리스트**가 진행 기준: ① 장면(언제·어디서) ② 행동(뭘 어떤 순서로)
  ③ 판단 기준(왜 그렇게) ④ 결과·상대 반응 ⑤ 감정 한 줄.
  "재료 충분" 판정을 횟수가 아니라 이 체크리스트 충족으로 한다. 이것이 '대화가 얕게 끝난다'의 답이다.
- **유형별 질문 의도(BEI)를 인터뷰어가 안다**: 갈등 질문은 갈등 얘기가 아니라 대처 역량을 묻는 것.
  유형별 지침 5종을 교재 기반으로 재작성한다.
  - 과거경험검증: 상황은 짧게, 행동·판단에 깊이. "이겨낸 방법이 그 사람이다"
  - 직무핵심역량: 사전적 정의가 나오면 자기 경험으로 재해석시킨다(역량 재해석 프레임)
  - 상황대처: 판단 기준(안전 vs 서비스)부터. 교재의 기내 상식(등받이=안전규정, 터뷸런스 행동지침)을
    판단 힌트로 싣는다
  - 개인신상: 사소한 질문일수록 의도가 있다(바탕화면=성향). 솔직함과 나다움을 파낸다
  - 기업관심도: 정보 → 왜 끌렸나 → 그 항공사에 어떤 의미인가로 연결. 사실 기반 확인
- **파고들기 기법**(공통): 추상적 답 → 구체적 장면 / 승객·관찰자 관점 → 실무자 관점 /
  "열심히·최선" 같은 아무나 쓰는 단어 → 나만의 언어로 되묻기.
- 막힘 대응(예시 던지기·각도 바꾸기·실마리 되비추기)은 유지. 상한은 **4문답**(2026-08-05 오너 확정 — 아래 재료 게이지 절 참고. 원래 6턴이었다).
- 서버 응답을 **구조화**한다: `{message, materials_sufficient, missing}`.
  현재의 정규식 판정(`/재료가 충분/`)을 없앤다. `missing`(아직 안 모인 재료)은 화면 힌트로 쓸 수 있다.
- ⚠️ 확정 7 가드: `userMsgCount >= 2 → showRefine()` 로직은 **그대로 둔다.**
  `materials_sufficient`는 CTA를 여는 추가 신호일 뿐이다.

## 다듬기 — 산출물 2개 (호출 1번, 2크레딧)

구조화 출력으로 한 번에 받는다:

- **소재 카드** `card`: `{ title(경험 한 줄 제목), one_line(요약), scene(핵심 장면),
  actions(행동·판단), competencies[](역량 태그), reinterpretation(역량 재해석 문장) }`
  - 역량 태그 값은 `competency_dict`의 역량 명칭(한국어)을 그대로 쓴다.
    별도 코드 체계를 만들지 않는다 — 화면 표시·서버·playbook이 같은 문자열 하나를 공유한다.
- **답변 뼈대** `skeleton`: `{ steps[2~4: {what(무슨 내용), fill(학생이 채울 방향)}],
  strengths(재료 중 강점 포인트), closing(스스로 완성하게 하는 한마디) }`
- 뼈대 작성 규칙 = **답변구조화공식 4원칙** + **자가체크 6기준** 관점(playbook에서 로드):
  첫 문장은 질문 의도의 알맹이 / 상황은 짧게·판단과 행동에 무게 / 아무나 쓰는 단어는 나만의 언어로 /
  쿠션어. 유형별 주의(상황대처형은 판단·대처 흐름)는 유지.
- **지어내기 금지 + 빈칸은 (괄호)** — 첨삭(polish)의 '첨삭의 선'과 같은 규칙. 화면이 괄호를 칠해 준다.
- 서버가 카드를 `sojae_materials`에 **자동 upsert**(문제당 1카드). 저장 실패해도 뼈대는 정상 반환(degrade).
- 원가 통제 불변: `effort: medium`, `max_tokens 8192`, 재료 상한 `MAX_MATERIALS_CHARS 4000` 유지.
- 응답에 기존 `message` 필드(뼈대 텍스트 병합본)를 유지해 **구버전 화면도 안 깨진다.**

## 소재 서랍

- 새 테이블 **`sojae_materials`**: `id, member_id, question_id(유래 문제, null 허용),
  session_id(null 허용), title, one_line, scene, actions, competencies jsonb, reinterpretation,
  status(active/archived), created_at, updated_at`. `unique(member_id, question_id)`(문제당 1카드 upsert).
- RLS: 본인 전체 CRUD + 관리자. 서버(service role) 쓰기.
- 1단계 UI는 최소:
  - `answers.html`에 **[내 답변 | 내 소재] 탭** 추가. 소재 카드 = 제목 + 역량 태그 + 유래 문제,
    펼치면 전체 내용, 수정·삭제 가능.
  - 다듬기 결과 화면에 "소재 서랍에 저장됨" 표시 + 서랍 링크.
  - mypage `#sec-answers` 미리보기는 불변.
- 조회는 `select('*')`(마이그레이션 미적용 방어 — 사이트 관례).

## sojae_playbook — 노하우 저장

- 새 테이블 **`sojae_playbook`**: `key text pk, content text, active boolean, updated_at`.
  RLS: **관리자만**(일반 회원 조회 불가 — `ai_killer_terms`와 같은 이유). 서버는 service role로 읽는다.
- 행 구성: `ask_core`(되묻기 공통 방법론), `ask_experience`·`ask_values`·`ask_judgment`·`ask_company`·`ask_personal`(유형별),
  `refine_core`(구조화공식 4원칙 + 자가체크 6기준), `competency_dict`(역량 재해석 12종 사전),
  `cabin_knowledge`(상황대처용 기내 상식).
- 서버가 **매 요청 로드**해 system 프롬프트를 조립한다 → 내용 수정이 **재배포 없이** 반영.
  내용이 같으면 프롬프트 캐시도 그대로 맞는다(안정 프리픽스 유지).
- **시드는 SQL로 대화창에 제공**(레포 커밋 금지 — 확정 8). 오너가 SQL Editor에서 실행.
- 미시드·조회 실패 → 함수 내장 **축소 프롬프트**(현재 수준)로 폴백. 조용히 죽지 않는다.
- admin 편집 UI는 1단계에서 만들지 않는다(자주 안 바뀌는 방법론이라 SQL 수정으로 충분).
  자주 고치게 되면 그때 감점 사전 패턴으로 탭을 단다.

## 문항 풀

- 교재 문항을 `questions`에 시드: 필수 경험정리 10 · 기초질문 BEST 10 · 실전문제 30 ·
  돌발질문 30 · 기업분석 기출 10. **중복 제거 후 약 80문항**, 위 유형 표로 매핑해 넣는다.
  영어 면접 문항은 제외(한국어 도구).
- 시드도 SQL로 대화창에 제공(확정 8과 일관). `questions`는 로그인 회원에게 보이는 데이터라
  비밀은 아니지만, 문항 풀 자체도 자산이라 레포에는 넣지 않는다.
- 하루 순환 로직(`sojae-common.js`) 불변 — 풀이 커지면 순환 주기만 길어진다.
- admin 문제 관리 탭의 유형 select를 5종으로 확장(그 외 변경 없음).

## 서버 계약 — sojae-chat v2

- **한 파일 유지**(오너 콘솔 배포). **`FN_VERSION` 도입 + 프로브** 추가(ai-killer 패턴):
  로그인 없이 `POST {probe:true}` → `{version, features:['ask_v2','refine_v2','materials'],
  playbook_keys(로드된 키 수), has_api_key}`. 배포 상태를 SQL 없이 확인한다.
- ask: 요청 형태 불변. 응답 `{message, materials_sufficient, missing}` — `message` 유지로 하위호환.
- refine: 응답 `{message(하위호환 병합 텍스트), card, skeleton, used, cost, balance, daily_left}`.
- **차감 로직은 손대지 않는다**: 차감 키 `<question_id>#<이전 차감 횟수>`, 부족·실패는
  HTTP 200 + `code`, 실패 시 환급 + `refunded` — 전부 현행 유지.
- 화면의 신구 판정은 **응답 형태**로 한다(다듬기 응답에 `card`/`skeleton`이 있으면 v2 렌더).
  폴리시의 프로브 게이트는 구함수가 과금을 일으키는 사고를 막기 위한 것이었는데, 여기는
  차감 로직이 신구 동일이라 그 위험이 없다(2026-07-30 구현 계획에서 확정). 프로브는 배포 확인용.
  신버전 함수 + 구화면 조합도 `message` 필드 유지로 안전.

## 문제 난이도 4단계 (2026-08-05 신설)

> 오너 지시: "기초 문제가 랜덤으로 계속 나오고 있잖아. 초급·중급·고급·심화 네 단계로 나눠서
> 사용자가 선택할 수 있게 하고, 어드민에서도 그렇게 나눌 수 있게."
> 오너 확정 두 가지: ① **진입하면 난이도 고르는 화면이 먼저** ② **난이도별 오늘의 문제 + '다른 문제 보기'로 그 난이도 전체.**

### 데이터

- `questions.level` — `basic`(초급) / `mid`(중급) / `advanced`(고급) / `deep`(심화), 기본값 `basic`.
  마이그레이션 `20260805120000_sojae_levels.sql`.
- ⚠️ **코드명은 화면 라벨과 짝이다**(`sojae-common.js` `LEVEL_LABEL`). 유형(`category`)과 같은 규칙 —
  DB 는 코드만 알고 라벨은 한 곳에서 바꾼다. 코드명을 바꾸면 기존 데이터가 전부 초급으로 떨어진다.
- **오늘 고정 유일 인덱스가 `(scheduled_date, level)` 로 바뀐다** — 같은 날 난이도마다 하나씩 고정할 수 있어야 해서다.
  admin '오늘 지정'도 **같은 난이도의 고정만** 비운다(다른 난이도의 오늘 문제를 끌어내리지 않게).
- ⚠️ **level 을 `.eq()` 조건에 넣지 않는다** — 마이그레이션 미적용 환경에서 400 이다.
  `select('*')` 로 받아 `levelOf(q)`(없으면 `basic`)로 거른다. 사이트 공통 관례.

### 순환

난이도마다 따로 돈다 — 초급·중급·고급·심화 각각 오늘의 문제가 하나씩 있다.
선정 규칙(오늘 고정 우선 → 없으면 `dayIndex() % 풀길이`)은 그대로고, 푸는 풀만 난이도로 갈린다.
`pickEffective(rows, level)` · `poolOf(rows, level)` · `fetchQuestionPool(sb)` 가 공용(`sojae-common.js`).

### 화면

- **진입 화면(`#pickView`)** — `?q=` 없이 들어오면 대화 대신 이 화면이 먼저다.
  난이도 칩 4개(각 문제 수) → 설명 한 줄 → **그 난이도의 오늘의 문제 카드** → [이 문제로 시작하기]
  → 접힌 [다른 문제 보기]에 그 난이도 문제 전체(이미 쓰던 문제는 '이어쓰기', 오늘 문제는 '오늘').
  ⚠️ 대화(`.chat`)·입력부(`.composer`)와 **같은 자리를 쓴다**(`body.picking` 이 가른다).
- 문제를 고르면 **`sojae.html?q=<id>` 로 화면을 다시 연다** — 대화 상태(대화·뼈대·초안)를 손으로
  초기화하지 않아 되돌릴 자리가 없다. 기존 `?q=` 흐름(answers·mypage 이어쓰기 링크)이 그대로 정본이다.
- **문제 풀이 비었거나 조회 실패면 진입 화면을 건너뛰고** 폴백 문제로 대화를 연다(빈 화면에 갇히지 않게).
- 대화 화면 상단 배지 = `초급 · 과거경험검증형 ▾`, 누르면 진입 화면으로 돌아간다.
  ⚠️ 배지는 22px 알약이라 `::before` 로 누를 자리만 44px 로 넓혔다(보이는 크기는 그대로).
- 학생이 고른 난이도는 `localStorage['monc_sojae_level_v1']` 에 남는다. `?q=` 로 연 문제의 난이도도 여기 기록한다
  — 마이페이지 '오늘의 소재 발굴'이 같은 난이도로 열린다.
- 마이페이지 카드는 라벨에 난이도를 붙이고, 링크를 **그 문제의 `?q=`** 로 바꾼다(고른 화면을 두 번 거치지 않게).

### admin '소재 문제' 탭

- 등록·수정 폼에 **난이도** select. 목록 각 줄에 **난이도 select(바꾸면 바로 저장)** — 재분류가 잦아서다.
- 목록 위 **난이도별 보기 칩**(정본 문법 `.apq-filter + .af-row + .af-chip`), 개수는 숨김 문제까지 센다(관리 기준).
- '▶ 오늘 노출 중'은 **난이도마다 하나씩 최대 네 줄**이다.
- 저장이 `42703`/`PGRST204`(level 없음)로 실패하면 **level 만 빼고 다시 보내고** 마이그레이션 안내를 띄운다.

### 계측

`sojae_pick_open`(진입 화면 열림 · meta.level) · `sojae_level_pick`(난이도 바꿈) 추가,
`sojae_start` meta 에 `level` 추가. 어느 난이도가 실제로 쓰이는지로 문항 보강 순서를 정한다.

### 하지 않는 것

- 난이도를 `answers` 에도 복사하기(문제에만 둔다 — 답변은 `question_id` 로 따라간다).
- 난이도별 가격·권한 차등(값은 다듬기 크레딧 하나뿐 — 크레딧 공통 규칙 불변).
- 진입 화면을 건너뛰고 바로 오늘 문제로 여는 옛 동작으로 되돌리기(오너 확정 ①).

### 소재 발굴 v2 — 교재 방법론 이식 (2026-07-30 신설 · 스펙 docs/superpowers/specs/2026-07-30-sojae-v2-design.md)
구조: 되묻기(Haiku 4.5·무료·재료 체크리스트) → 다듬기(Sonnet 5·2크레딧·**소재 카드+뼈대 두 산출물**) → 최종 작성. 카드는 서버가 `sojae_materials`에 자동 upsert(문제당 1장), answers.html [내 소재] 탭이 서랍.
- **⚠️⚠️ 다듬기 버튼은 두 번째 답변부터 항상 열려 있다(이탈 가드 — 오너 확정).** AI의 `materials_sufficient`는 추천 신호일 뿐 관문이 아니다. `userMsgCount >= 2 → showRefine()`을 지우거나 판정 뒤로 숨기지 말 것.
- **⚠️ 유형은 BEI 5종 — 코드 4종(experience/values/judgment/company) 유지 + `personal`만 신설.** 라벨(과거경험검증형·직무핵심역량형·상황대처형·기업관심도형·개인신상형)은 `sojae-common.js` CAT_LABEL 한 곳. 코드명을 바꾸면 questions·answers 기존 데이터가 깨진다.
- **⚠️ 교재 노하우는 공개 레포에 없다.** 프롬프트 본문 = `sojae_playbook` 테이블(RLS 관리자만, 서버는 service role). 내용 시드는 SQL로 대화창 전달(커밋 금지). SQL Editor에서 고치면 **재배포 없이 즉시 반영**. 함수 내 `FB_*` 상수는 v1 수준 폴백일 뿐 — 새 노하우를 상수에 넣지 말 것.
- **⚠️ 신구 판정은 프로브가 아니라 응답 형태.** 다듬기 응답에 `card`/`skeleton`이 있으면 v2 렌더, 없으면(구함수) `message` 렌더. 차감 로직이 신구 동일이라 과금 위험이 없어 폴리시식 프로브 게이트를 쓰지 않았다. 서버 프로브(`POST {probe:true}` → version·playbook_keys)는 배포 확인용으로 존재 — **코드를 고치면 FN_VERSION도 같이 올릴 것.**
- **⚠️ 응답의 `message` 필드를 지우지 말 것** — 구버전 화면 호환(뼈대 평문 병합본). ⚠️ 되묻기(Haiku 4.5)에 `output_config.effort`를 넣지 말 것(미지원 — 400).
- 카드 upsert 키 = `(member_id, question_id)` — 재다듬기는 카드를 덮는다(의도). `question_id` 없으면 저장 생략. 저장 실패는 뼈대를 막지 않는다(`card_saved:false`).
- 계측: page_events `path:'/sojae'` — sojae_start/turn/refine_click/refine_done/card_saved/save_final. 2단계(소재 매칭 추천) 착수 판단 근거.
- 차감·환급·무료 규칙은 아래 '답변 저장소 + 크레딧' 절 그대로(v2에서 불변).

   → `.chat > :first-child { margin-top: auto }` 한 줄로 아래에서부터 쌓는다(말풍선 y 535~630).
   ⚠️ `justify-content:flex-end` 로 바꾸지 말 것 — 대화가 길어지면 위쪽 메시지가 스크롤로 못 닿게 잘린다. `margin-top:auto` 는 내용이 넘치는 순간 0이 된다(메시지 19개로 확인 — 위·아래 끝 모두 도달 가능).
2. **아이폰은 키보드가 열려도 페이지 높이를 안 줄인다.** 대신 입력칸을 키보드 위로 올리려고 페이지 전체를 밀어 올려서 상단바·단계·질문이 화면 밖으로 나간다.
   → `visualViewport` 의 height 를 셸 높이로 그대로 받아쓴다(`fitShell`). 안드로이드는 뷰포트 메타의 `interactive-widget=resizes-content` 로 해결된다 — **메타에서 이 값을 빼지 말 것.**
   ⚠️ `fitShell` 은 **대화가 바닥에 붙어 있을 때만** 스크롤을 따라 내린다. 무조건 내리면 위쪽 대화를 읽는 중인 사람을 끌어당긴다.

3. **셸이 줄어든 만큼 고정 요소가 대화를 잡아먹는다.** 위 둘만 고치고 올렸더니 질문 말풍선이 흰 띠로 잘렸다(오너 2차 신고). 홈화면 앱으로 열면 키보드가 올라온 뒤 남는 높이가 **427** 인데, 공용 메뉴 57 + 상단 바 68 + 단계 30 + 입력부 214 = **369 를 고정 요소가 먹어 대화에 58 만 남는다**(말풍선 96).
   → 키보드가 올라와 있는 동안만 **공용 메뉴를 접는다**(`body.kb-open` — 여백 0 + `#navbar`·`.iab`·`.iab-space` 숨김). 대화 58 → **115**.
   ⚠️ `.iab-space`(인앱 안내 자리 차지 요소)를 같이 접지 않으면 인앱 브라우저에서 56px 을 또 뺏긴다.
   ⚠️ 키보드 열림 판정은 `vv.height < 처음 높이 - 120`. 주소창이 접힐 때도 50px 남짓 줄어서, 그보다 작게 잡으면 스크롤만 해도 메뉴가 사라진다.

적용 후 실측(키보드 열림·셸 427): 상단 바 68 · 단계 30 · 대화 115 · 입력부 214 — 짧은 질문(96)은 전부 보인다.

4. **키보드가 열려 있는 동안은 카톡 채팅창으로 바꾼다**(2026-08-04 오너 지시 "카카오톡 채팅창처럼 최적화를 시켜봐. 두 번만 물어봐도 채팅창이 없어지잖아").

   보조 줄만 접는 것으로는 부족했다. 2번째 답변부터 다듬기 CTA(108)와 도움 버튼·힌트(74)가 붙으면서 **대화가 17px 까지 눌렸다**(오너 3차 신고). 키보드가 열리면 쓸 수 있는 높이는 415 인데 고정 요소 합이 453 이었다.

5. **입력부는 카톡처럼 '한 줄'뿐이다 — 도구는 고정 줄에서 뺀다**(2026-08-04 오너 지시 "보고 똑같이 맞춰라").

   카톡을 실제로 재면 **마지막 말풍선 아래로 입력줄 끝까지 73pt**다(입력줄 38 · 위 간격 21 · 아래 14). 우리는 **205pt** 였다. 원인 셋: 입력칸 위 도구 줄(52) · 안전영역 여백(34)이 키보드에 가려진 자리에 그대로 들어감 · 입력줄 자체가 두꺼움(62).

   - **다듬기 CTA 는 `#refineWrap` 으로 대화(`#chat`) 안 마지막 요소**다. 고정 줄이 아니라 마지막 말풍선 다음에 붙어 **스크롤과 함께 움직인다**(카톡의 추천 칩 자리). 메시지를 붙일 때마다 `tailTools()` 가 맨 끝으로 다시 옮긴다.
   - **'잘 안 떠올라요'는 입력줄 안 왼쪽 버튼**(`.helpic` 44px — 카톡의 `+` 자리). 8초 멈추면 여기가 울린다.
     **누르면 바로 도움을 부르지 않고 확인 카드가 먼저 뜬다**(2026-08-04 오너 지시). "지금 쓰기 어려우신가요? / 아무 말이나 적기보다, 원하시면 제가 실마리부터 드릴게요." + `[네, 도와주세요] [아니요, 더 써볼게요]`. 입력칸 옆 아이콘이라 잘못 눌리기 쉽고 눌러 보기 전엔 뭘 하는 버튼인지도 모르는데, 확인 한 단계가 그 둘을 같이 해결한다.
     ⚠️ **말풍선(`.bub`)이 아니라 `.askcard` 다.** 처음엔 연구원 말풍선으로 만들었더니 "그냥 대화 같아서 티가 안 난다"고 반려됐다 — 폭을 꽉 채우고(361 vs 말풍선 303), 바탕을 연한 네이비 틴트, 테두리 네이비 1.5px, 'R 연구원' 머리는 뺐다. 흰 말풍선으로 되돌리지 말 것.
     ⚠️ **이 확인 카드는 `transcript` 에 넣지 않는다** — 대화 재료가 아니라 화면 장치라, 넣으면 다듬기의 `{collected_materials}` 와 서버 저장본이 오염된다.
   - **값은 칩 글자 안에** 싣는다(`다듬기 · 오늘 10번 무료` / `다듬기 · 2크레딧` / `다듬기 · 충전 필요`). 크레딧이 모자랄 때만 아래에 '충전하기'가 선다. '되묻기 대화는 무료예요'는 다듬기 칩이 없는 1턴에 그 자리에 선다.
   - **입력줄 아래에는 아무것도 두지 않는다**(2026-08-04 오너 지시 "싹 다 필요없음. 카톡처럼 여백만"). 'Enter 전송 · Shift+Enter 줄바꿈' 안내는 삭제했고(폰에서 누를 수 없는 조작이다), **미니 다듬기 티저(`#quickfix-mount`)도 이 화면에서만 뺐다**(`quickfix.js` 도 같이 — 마운트가 없으면 하는 일이 없다). ai-killer·briefing·answers 의 티저는 그대로다. **다시 달지 말 것.**
   - **키보드가 열린 동안 안전영역 여백을 넣지 않는다**(`body.kb-open .composer { padding: 6px }`). 그 자리는 키보드가 덮고 있어 순전히 버리는 여백이다.
   - 입력줄 = 버튼 44 + 위아래 4 + 테두리 2 = **54**. `.field` 여백을 8px 로 되돌리면 대화가 8px 줄어든다.
   - **⚠️ 입력칸 `font-size` 는 16px 하한.** 15px 이었을 때 아이폰이 누를 때마다 화면을 자동 확대해 오른쪽이 잘렸다(오너 신고). 사이트 공통 규칙(입력칸 16px+)이 이 때문에 있다.
   - `ta.blur()`(보내면 키보드 내리기)는 없앴다 — 칩이 대화 꼬리에 늘 붙어 있어 키보드를 내려야 CTA 를 보는 상황이 사라졌고, 매 턴 키보드가 오르내려 흐름이 끊겼다.

6. **전송 뒤 한글 마지막 글자가 입력칸에 남는 버그**(2026-08-05 오너 신고). 키보드를 안 내리는 구조(위 ta.blur 삭제)라 마지막 글자의 IME 조합이 전송 순간까지 살아 있고, 입력칸을 비우면 IME 가 조합하던 글자를 도로 넣는다. 방어 둘 다 유지할 것: ① Enter 는 조합 중(`isComposing`·keyCode 229)이면 글자 확정만 하고 다음 Enter 에 보낸다(카톡 PC판과 같은 동작) ② 전송 80ms 뒤 입력칸에 딱 한 글자만 남아 있으면 지운다(전송 버튼 경로 방어 — 사람이 80ms 안에 다음 글자를 시작할 수 없어 정상 입력은 안 지워진다). 실기기 IME 는 개발 브라우저에서 재현이 안 되므로 합성 이벤트(isComposing Enter · 전송 직후 잔글자 주입)로 가드와 청소를 각각 검증한다.
