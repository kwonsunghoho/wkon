# 연구실 서가 합치기 — 항공사 자료실 + 기출문제

> 2026-08-03 오너 지시로 설계. 원장의 서가 카드 5장 중 '항공사 자료실'과 '기출문제'를
> **한 서가로 합치고, 그 안에서 두 갈래로 고르게 한다.**

오너: **"우리 연구실에 항공사 자료실이랑 기출문제가 따로있을 이유가없어보여서.
둘이 합치되 효율적으로 구분할 수 있는 장치를 만들면 좋아보이는데"**

지적이 맞았다. 두 서가는 **이미 같은 표(`lab_resources`)에 `shelf` 값만 다르게** 들어가고,
**둘 다 항공사 축 + 유형 축으로 똑같이 고르게** 돼 있었다. 자료실의 유형 추천 목록에는
이미 '기출 정리'가 있었다(`admin.html` 의 `LAB_TYPE_SUGGEST.airline`).

## 오너가 정한 것(되돌리지 말 것)

1. **합치되 화면에서 갈래로 나눈다** — 유형 값 하나로 내려 묻어 버리지 않는다.
2. **갈래 장치는 A안 '갈래 단추 한 줄'**(3안 목업 비교 후 "a안으로 가면 되겠다").
3. **기출에는 모음 파일과 낱개 질문이 둘 다 올라간다**(오너 확인). 낱개 질문은 2단계.
4. **단위는 `건` 으로 통일한다**(기출문제가 쓰던 `개` 는 없어진다).
5. **서가 이름은 '항공사 자료실' 그대로.** 기출을 품는다는 것은 설명 문장이 말한다.

## 1. 화면 — 갈래 단추 한 줄(A안)

목업 `outputs/lab-merge-branch-mockup.html`(3안 비교 + 고른 뒤 모습). 폭·활자·색·간격은
라이브와 같은 값으로 그렸고 글꼴도 `tokens.css` 를 물려 재서 라벨 잘림 실측이 맞는다.

상세 화면(`lab-shelf.html`)의 다크 머리 **아래, 픽커 줄 위**에 갈래 단추가 한 줄 선다.

```
[ 전체 20 | 자료 12 | 기출 8 ]     ← 갈래(새로 생기는 줄)
[ 항공사 ▾ ] [ 자료 유형 ▾ ]        ← 지금 그대로
```

- 고른 칸만 흰 면으로 떠오른다(틀 = `--action-tint`, 고른 칸 = `--surface` + 옅은 그림자).
- **건수를 단추 안에 적는다** — 눌러 보기 전에 어느 쪽이 두꺼운지 안다.
- **갈래를 고르면 유형 픽커의 이름과 목록이 갈린다**(자료 유형 ↔ 질문 유형).
  한 픽커에 유형 12종을 몰아넣지 않는 것이 합치기의 실익이다.
- 옵션은 늘 그렇듯 **데이터에 실제로 있는 값만**, 1개뿐이면 픽커를 감춘다(기존 규칙).

### 줄 단위 구분 — 목록에서 갈래를 읽는 법

- **기출은 아이콘 면을 네이비(`--accent-dark`)로 채운다.** 자료는 지금처럼 옅은 틴트.
  말풍선 안 물음표 아이콘을 쓴다(면접장에서 받은 '질문'이라).
- **'전체'일 때만** 줄에 `기출` 태그를 단다. 기출 갈래를 고르면 화면 전체가 기출이라
  반복하지 않는다 — **admin 열람 이력에서 '전체'일 때만 서가 이름을 적는 규칙과 같다.**

### 실측(375px · 라이브와 같은 글꼴)

| 안 | 고르는 영역 | 머리~목록 | 라벨 잘림 |
|---|---|---|---|
| **A 갈래 단추 한 줄(채택)** | 146px | 326px | 없음 |
| B 갈래도 픽커로 | 78px | 258px | **있음 — '아시아나항공'** |
| C 다크 머리 안 탭 | 78px | 302px | 없음 |

- **B안 탈락 사유는 실측이다.** 알약이 3개면 하나가 106px 이라 항공사 이름이 안 들어간다
  (2개일 때는 164px 이라 멀쩡하다). 고르고 나면 라벨이 길어지는 자리라 그대로 사고가 된다.
- **C안과의 실제 차이는 24px 뿐이다.** C안이 고르는 영역은 68px 짧지만 다크 머리가 46px
  길어진다. 그 24px 을 쓰고 A안이 얻는 것 — 갈래가 가장 큰 글씨로 먼저 읽히고, 건수가
  눌러 보기 전에 보이고, 조작부가 다크 면 밖에 있어 읽는 자리와 누르는 자리가 안 섞인다.
- ⚠️ **갈래 단추는 44px 하한**(4px 안쪽 여백이 있어도 누르는 것은 단추다). 목업 첫 판이
  40px 이었다.
- ⚠️ **단추 안 건수도 읽는 글자다** — `opacity:.62` 는 틴트 면 위에서 3.40:1 로 미달이라
  `.8`(5.48:1)로 올렸다. 다크 탭 안 건수도 같은 이유로 `.7` → `.88`(5.59:1 이상).
  **375px 눈검사로는 둘 다 통과하던 값이다.**

## 2. 데이터 — 마이그레이션 0건

**DB 의 `shelf` 값(`airline` / `question`)은 그대로 둔다.** 합치는 것은 화면뿐이다.

- 목록: 지금 쓰는 `lab_resource_list` 를 **두 번 불러 `published_at` 내림차순으로 합친다.**
  갈래가 하나면 그 shelf 만 한 번 부른다.
- 건수: `lab_shelf_counts()` 가 주는 서가별 값을 **화면에서 더한다**(허브 목차·원장 카드).
  `last_at` 은 둘 중 큰 값.
- 원장 카드의 '최신 1건'은 두 shelf 의 최신을 비교해 더 최신인 것을 쓴다.

**왜 RPC 를 안 고치나** — `p_shelf` 를 배열로 바꾸면 반환 타입 재생성이 필요하고, 오너가
SQL Editor 에서 실행해야 반영된다(미적용 구간이 생긴다). 자료 수가 목록 규모라 두 번
호출의 비용이 그 위험보다 작다. **갈래 단추만 빼면 원상복구**라는 점도 같은 이유다.

⚠️ 조회가 하나라도 실패하면 **합친 결과를 부분으로 그리지 않는다** — 지금의 실패 화면을
그대로 쓴다. 절반만 그리면 '기출이 없다'로 읽힌다.

## 3. 서가 표·색인 재배열

`lab-shelf.html` 의 `SHELVES` 표에서 `question` 줄을 지우고, `airline` 이 두 shelf 값을
품는다. 갈래 값은 `all` | `doc` | `question`(`doc` → DB `shelf='airline'`).

원장·허브의 색인이 한 칸씩 당겨진다.

| 새 색인 | 서가 | 옛 색인 |
|---|---|---|
| 01 | 항공사 자료실(자료 + 기출) | 01 · 03 |
| 02 | 영상관 | 02 |
| 03 | 현장 리포트 | 04 |
| 04 | 채용 캘린더 | 05 |

- 허브(`lab.html`) 콘솔 카드 목차 5줄 → 4줄. 원장(`lab-archive.html`) 카드 5장 → 4장.
- 두 파일의 `UNIT` 표에서 `question` 을 빼고, `airline` 단위는 `건`.
- ⚠️ **`lab.html` 카드 규격(padding 28·제목 32px·화살표 52px·`.ix { max-height:380px }`)은
  건드리지 않는다** — 목차가 한 줄 줄어드는 것뿐이다(lab.md '1.5배 한 벌').

## 4. 기존 링크·주소·미리보기 사진

카톡·DM 에 이미 뿌린 `lab-question.html` 링크가 죽으면 안 된다.

- **스텁 `lab-question.html` 은 남긴다.** 넘기는 주소만 `lab-shelf.html?shelf=airline&kind=question`
  으로 바꾼다 — 눌러 들어오면 **기출 갈래가 선택된 상태**로 열린다. og 제목·사진은 '기출문제'
  그대로다(그 링크를 받은 사람이 기대하는 것이 기출이다).
- 구 주소 `?shelf=question` 으로 들어와도 같은 상태로 해석한다(원장 구 링크·즐겨찾기).
- `history.replaceState` 는 **갈래에 따라** `lab-airline.html` / `lab-question.html` 로 쓴다.
  주소창을 복사해 보내도 미리보기가 그 갈래를 말한다(오너는 주소창에서 복사한다).
- ⚠️ 스텁을 하위 폴더로 옮기지 말 것 · meta refresh 를 쓰지 말 것(lab.md 의 기존 함정).
- **미리보기 사진 2장을 다시 굽는다** — `images/og/lab-report.png`(04→03),
  `lab-calendar.png`(05→04). 사진 안에 색인 번호가 찍혀 있고 생성 스크립트가 안 남아 있다.
  1200×630 HTML 을 같은 팔레트·글꼴로 브라우저에 그려 PNG 로 저장한다.
  `lab-airline.png`·`lab-question.png` 는 번호가 그대로라 손대지 않는다.

## 5. admin — 바뀌지 않는다

자료는 계속 두 서가로 나눠 등록한다. 서가 칩 6개, '전체'일 때 서가별 소제목, 열람 이력
좁히기 전부 그대로다. **화면에서만 한 서가로 보인다**는 사실을 등록 폼에 한 줄 적는다
(어느 서가로 올려야 하는지 헷갈리지 않게).

⚠️ `LAB_TYPE_SUGGEST` 는 서가별로 유지한다 — 갈래별 유형 목록이 갈리는 근거가 이 표다.

## 6. 2단계 — 낱개 질문(이번에 안 한다)

지금 `lab_resources` 는 **파일이나 링크 중 하나가 반드시 있어야 한다**(check 제약).
본문만 있는 질문은 등록 자체가 안 된다.

- `lab_resources` 에 `body text` 를 더하고 check 를 '파일 · 링크 · 본문 중 하나'로 푼다.
- ⚠️ **새 표를 만들지 말 것** — 값·비밀번호·열람 기록·구매가 전부 자료 단위에 붙어 있다
  (`lab_materials` 신설을 폐기했던 2026-08-01 전례와 같은 이유).
- ⚠️ **유료 낱개 질문의 본문을 목록 RPC 로 내보내지 말 것.** 목록에 본문이 실리면 값이
  무의미해진다 — 본문도 `lab-file` 을 거쳐 내주고 열람 기록을 남긴다.
- 합치기와 섞으면 되돌리기가 어려워져 분리했다. 합치기를 올린 뒤 바로 잇는다.

## 7. 검증

- **375px·360px 브라우저 실측** — 갈래 단추 44px, 가로 넘침 0, 라벨 잘림 0,
  건수 활자 대비 4.5:1 이상.
- 갈래를 바꿀 때: 유형 픽커 이름·목록이 갈리는지, 목록이 그 갈래만 나오는지,
  '전체'에서만 `기출` 태그가 붙는지.
- 링크: `lab-question.html` 로 들어가면 기출 갈래로 열리는지, 주소창이 갈래를 따라가는지.
- 숫자: 허브 목차·원장 카드의 항공사 자료실 건수가 **두 shelf 합계**인지.
- 자료 0건인 갈래에서 '준비 중'이 나오는지(0 을 내걸지 않는다는 기존 규칙).

## 8. 기각안(기록)

- **기출을 자료 유형 값 하나로 내리기** — 고칠 곳은 가장 적지만 학생이 제일 많이 찾는
  기출이 유형 12종 중 하나로 묻히고, 뿌려 둔 `lab-question.html` 링크가 죽는다.
- **B안 갈래도 픽커로** — 라벨 잘림 실측(위 표).
- **C안 다크 머리 안 탭** — 24px 차이로 A안에 밀렸다(위 표).
- **항공사를 최상위로 올리는 전면 재편**(서가 대신 항공사 10장) — 학생이 준비하는 단위와
  가장 잘 맞지만 원장·상세·스텁·og·admin 이 전부 다시고, 자료가 적은 항공사는 빈 화면이
  8~9개 생긴다. **자료가 더 쌓인 뒤에 볼 일**로 미뤘다(폐기가 아니다).
