# 커뮤니티 모집 카드 설계 (2026-08-16 오너 확정)

카카오톡 오픈채팅 커뮤니티를 사이트에서 모집한다. 오너 요구 세 가지가 출발점이다.

1. "너무 덕지덕지 오픈하진 말고 꼭 필요한 몇 군데에만."
2. "단순 아이콘보다는 카드처럼 해서 존재감 있게."
3. "클릭하면 회원들만 링크를 보이게 해라. 개나소나 못 들어오게."

⚠️ **오픈채팅 주소와 참여코드는 이 문서를 포함해 레포 어디에도 적지 않는다.** 레포가 공개라 커밋하는 순간 게이트가 무의미해진다. 값은 대화창 SQL로만 전달한다(교재·`sojae_playbook`과 같은 방식).

## 확정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 위치 | `lab-shelf.html`(서가) · `news.html` · `tools.html`(도구 허브) 본문 맨 아래, 3곳 | 오너 선택. 무료 자료·뉴스·도구 이용자가 대상. 홈은 제외(구 홈 커뮤니티 섹션은 부활 금지 목록) |
| 생김새 | 시안 C '컴팩트 배너'(가로 한 줄 흰 카드) | 오너 선택 — "과하지도 않고". A(밝은 카드)·B(네이비 카드)는 기각 |
| 입장 통제 | 주소는 로그인 회원만 서버에서 받는다 + 카톡 방 참여코드 병행 | 오너 선택(코드 걸기). 주소가 새어도 코드만 바꾸면 다시 잠근다 |
| nav 소셜 줄 | 넣지 않는다 | 소셜 줄은 공개 채널 자리 — 회원 전용 취지와 충돌 |
| 참여 인원수 표시 | 없음 | 카카오가 숫자를 안 내려줘 손 관리 = 거짓 숫자 위험 |

## 카드 사양 (시안 C)

- 구조: 카카오 노랑(#FEE500) 40px 아이콘 타일 + 제목/부제 + 네이비 '입장' 버튼이 가로 한 줄.
- 문구: 제목 **승무원 준비생 커뮤니티** / 부제 **몬크가 운영하는 승무원 채용 관련 채팅방 — 회원 전용**(2026-08-16 오너 교체 — 구 "채용 소식 · 정보 교류 · 몬크 답변". '— 회원 전용' 꼬리는 게이트 예고라 유지).
- 흰 카드가 순백 배경에서 뜨는 방식은 팔레트 규칙 그대로: `--border-soft` 테두리 + `--shadow`. 새 색 금지(카카오 노랑은 기능색으로 기존 `.kakao-ask`와 같은 취급).
- 활자 12px 이상, **버튼 터치 영역 44px 이상**(시안의 40px는 축소 렌더 — 구현에서 44 이상으로). 320px에서 넘침 0.
- 값에 이름 붙이기 원칙: 부제에 "회원 전용"이 이미 있어 별도 배지 없음.

## 구현 형태

- **공용 파일 `community-card.js` 하나**(스타일 주입 포함). 세 페이지는 마운트 지점 한 줄 + `<script src="community-card.js?v=1" defer>` 만 싣는다. 문구·동작 수정은 이 파일 한 곳. 페이지별 정확한 삽입 앵커는 구현 계획에서 지정한다.
- 파일을 고치면 세 페이지의 `?v=` 도 같이 올린다(inapp.js 규칙과 동일).
- **bfcache**: news·tools 는 뒤로가기 때 통째 reload 집합이라 펼침이 자연 초기화되지만, **lab-shelf 는 결제 복귀 예외(통째 reload 안 함)** — 공용 기기에서 로그아웃 뒤 뒤로가기로 펼쳐진 코드가 되살아날 수 있다. `community-card.js` 가 `pageshow`(persisted)에서 펼침을 접는 한 줄을 넣어 세 페이지 공통으로 막는다.

## 데이터 — 새 표 `community_config`

- `key text primary key, value jsonb, updated_at`(트리거 `set_updated_at` 재사용). 행 하나: `key='open_chat'`, `value={"url":..., "code":...}`.
- **RLS**: select 는 `authenticated` 만(`using (true)`), 쓰기는 `is_admin()`. anon 정책 없음 — 비회원은 못 읽는다.
- 기존 `site_config` 를 안 쓰는 이유: select 정책이 `anon` 포함 전체 허용이라 비회원도 읽는다(마이그레이션 20260710120000 실측).
- 마이그레이션 파일에는 **표 구조와 RLS만** 담는다(값 없음). 주소·코드를 넣는 insert SQL은 대화창으로 전달해 오너가 콘솔에서 실행.
- 조회는 `select('*')`(컬럼 나열 금지 규칙). 표 미생성(`PGRST205`)이면 콘솔 에러 없이 "아직 준비 중이에요" 안내로 조용히 degrade.

## 동작 흐름

1. 카드 '입장' 클릭 → `MONC.getSession()`.
2. **비회원**: `login.html?returnTo=<현재 주소>` 로 이동. 로그인·동의 후 원래 페이지 복귀(기존 returnTo 흐름 재사용). 자동으로 카드를 다시 열어 주지는 않는다(복귀 후 한 번 더 누르면 됨 — 단순 유지).
3. **회원**: `community_config` 를 읽어 카드 아래를 펼친다 — **참여코드 표시 + 복사 버튼 + '카카오톡으로 입장' 링크**. 링크는 href 가 채워진 `<a>` 를 동기 클릭하는 구조라 인앱 브라우저에서도 막히지 않는다(비동기 뒤 `window.open` 금지 규칙 준수). 코드를 보여준 뒤 이동해야 하므로 자동 이동은 하지 않는다.
4. 조회 실패(미생성·네트워크): "아직 준비 중이에요. 잠시 뒤 다시 눌러 주세요" 한 줄.
5. 계측: 기존 계측 패턴이 있는 페이지 관례를 따라 클릭 이벤트 1개(`community_card_click`)만 심는다(구현 계획에서 기존 함수 확인 후 같은 방식).

## 검증(이 레포의 검증 3종 세트)

- 375px 브라우저 실측: 세 페이지 카드 렌더·비회원 클릭 → 로그인 이동·회원 클릭 → 코드 펼침. 320px 넘침 0.
- RLS 실측: anon 키로 `community_config` select 가 0건/거부인지 확인.
- degrade 실측: 표 미생성 상태를 가정한 `PGRST205` 분기 동작.

## 하지 않는 것

- 홈 커뮤니티 섹션 부활(금지 목록 유지), nav 소셜 줄 추가, 인원수 표시.
- 주소·코드의 레포 반입(HTML·JS·마이그레이션·문서 전부).
- 오픈채팅 방 자체 설정(참여코드 걸기, 방 이름)은 오너가 카카오톡에서 직접 한다 — 사이트 배포와 순서 무관하나, **코드를 걸기 전에 insert SQL부터 실행하면 회원 화면에 빈 코드가 뜨므로 값 전달 SQL에 코드까지 넣어 한 번에 실행한다.**
