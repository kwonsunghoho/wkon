# 챌린지 상세 구매전환 개편 — ①안 '결과 먼저' (2026-09-07 오너 승인)

오너 지시: "각 챌린지 상세페이지가 구매전환에 약한 것 같다. UX/UI 를 매출이 극대화되도록
바꾸고 싶다." → 목업 3안(`outputs/challenge-detail-direction-mockup.html` — 결정 뒤 오너 지시로 삭제, git 이력 4a5b17f) 중 **①안 확정**,
"보신각부터" 적용. 범위는 **상세 5종만**(A안) — 신청 페이지(apply.html)는 이번 범위 밖.

## 진단(2026-09-07 실측 · 375×812)

| 항목 | 값 |
|---|---|
| 보신각 문서 높이 | 10,420px = 12.8화면 |
| 순서 | 히어로 → 커리큘럼(1.2화면) → 얻을 수 있어요·핵심 변화(1.8) → 비포/애프터 7쌍(4.2) → 코치진 → 후기(9번째 화면) → 추천 대상·최종 목표(2.0) → 마지막 버튼 |
| 가격 노출 | 하단 고정 바에만(본문 0회) |
| 환불·FAQ | 상세엔 없음(신청 페이지에만) |
| 계측 | 상세 5종 비콘 0개(`page_view`·`visit` 공통만) |

약점: 결정에 필요한 사실(가격·후기 수·환불·진행 방식)이 흩어져 있고, 살 마음이 없는 사람에게
커리큘럼 목록이 두 번째로 온다. 효과 설명 섹션이 셋(같은 말 세 번)이라 길이의 1/4 을 차지한다.

## 확정 순서(①안 — 클래스101 문법: 첫 화면 = 결과물, 가격은 위에 고정)

1. **히어로**: 허브 카드 사진(`images/hero-<id>.webp`) 4:3 + 배지 + 제목 + 약속 한 줄 +
   **사실 알약 3개**(후기 N건 · 모집 상태/D-day · 참가비) + 신청 버튼 + '시작일 전날까지 취소하면
   전액 환불' 한 줄. 데스크톱(≥860px)은 사진 왼쪽·글 오른쪽 2열.
2. **비포/애프터 1쌍**만 펼치고 나머지는 '다른 챌린저 N명의 변화 더 듣기' 버튼으로 접는다.
3. **이런 학생에게 맞아요** — 카드 6장을 체크 목록 6줄로(제목만).
4. **2주 동안 이렇게 진행돼요** — 사실 4칸(하루 분량·미션 10회차·카카오톡 채널·코치 점검 방식)
   + 커리큘럼 주차 접이(둘 다 접힘) + **담당 코치 한 줄**(`[data-coach-slot]`).
5. **후기 3개** + '후기 N건 전체 보기'(기존 `challenge-reviews.js` 섹션을 이 자리로 이동).
6. **참가비 카드** — 정가 취소선/판매가 + 포함 내역 4줄 + 신청 버튼 + 환불 한 줄.
7. **FAQ 4개**(`<details>`) — 진행 방식·시작 시점·수료 기준·환불.
8. **마무리 CTA**(기존 `.cta-box`) + 법적 고지 한 줄 + 푸터.

지우는 것: 오버뷰 3칸(2주/10강/30초) · '이런 걸 얻을 수 있어요' · '2주 과정의 핵심 변화' ·
'최종 목표' · '← 목록으로' 보조 버튼. 목표 길이 7~8화면.

## 지켜야 하는 규칙

- **숫자는 실데이터만**: 후기 수는 `reviews` 조회 결과(0건이면 알약을 안 그린다), D-day 는
  `challenge_rounds`(`recruit.js` 가 `#recruitChip` 을 채운다 — 폴백 날짜 금지), 참가비는
  `site_config.challenge_price`(`MONC.loadChallengePricing` 한 곳 — 실패 시 숫자를 지어내지 않고 비운다).
  카운트다운·'N명이 보는 중' 같은 가짜 긴급 장치 금지.
- **판매 문구는 실제 제공 내용과 같아야 한다**(apply-and-payment.md '중간 점검 1회' 절):
  보신각·스피닝·영합각 = "담당 코치 1:1 중간 점검 1회", 승자각·댄특완 = "코치 가이던스 영상을
  따라 매일 직접 작성"(1:1 금지). 환불 문구는 '시작일 전날까지 전액 / 시작 이후 불가' 한 벌.
- **상세 5종 인라인 CSS 공통 블록은 건드리지 않는다**(다섯 파일 동일 유지). 새 배치의 스타일은
  공용 파일 **`challenge-detail.css`** 한 곳 — 페이지 인라인에 복사 금지. 다른 넷을 바꿀 때 같은
  파일을 링크한다.
- 공용 JS 는 **선택 적용**으로 확장한다(마크업에 슬롯이 있을 때만 새 동작):
  `challenge-sticky.js` — `[data-ch-price]` 채우기 · `[data-coach-slot]` 있으면 담당 코치 한 줄만 ·
  CTA/도달 비콘. `challenge-reviews.js` — `[data-review-count]`·`[data-review-pill]` 채우기.
  슬롯이 없는 나머지 넷은 종전 동작 그대로다.
- `ba-audio.js` 의 `.ba-cell` 마크업·`controls` 폴백·`preload="none"` 은 그대로(접힌 카드도 같은 마크업).
- 신청 버튼은 전부 `.apply-btn` + `handleApply` — `recruit.js` 가 마감·예정 라벨을 일괄 바꾸고
  `waitlist.js` 오픈 알림 시트로 이어진다. 하단 바 숨김 판정(히어로 버튼·마지막 버튼·푸터)도 그대로.
- 활자 12px+ · 터치 44px+ · 대비 4.5:1(경계선 3:1) · 포커스 표시(design-principles.md).

## 계측(퍼널 비교용 · `page_events`, 이벤트명 규칙 준수)

- `ch_detail_cta` meta `{ c, pos }` — pos = hero / price / final / bar. 모든 `.apply-btn`·하단 바 클릭.
- `ch_detail_reach` meta `{ c, s }` — s = price / faq / end. 섹션이 화면에 들어올 때 1회.
- 분모는 기존 `page_view`. 상세 5종 공용(`challenge-sticky.js`)이라 아직 안 바꾼 넷도 CTA 기준선이 쌓인다.

## 검증

- 375px 실측: 문서 높이 7~8화면, 알약 3개 값(실데이터), 가격 카드 금액 = 하단 바 금액,
  접힌 비포/애프터 펼치기·재생, 아코디언 키보드, 320px 넘침 0, 콘솔 에러 0.
- 비콘: 버튼 클릭 → `page_events` insert 요청 확인(네트워크).
- 마감 상태 시뮬레이션: `window._recruitStatus='closed'` 로 버튼 라벨·오픈 알림 시트.
