## 무엇인가

학생(회원)이 자소서·면접 답변을 넣으면 **AI 같은 문체를 잡아내고 교정**해 주는 도구.
브리핑룸(`briefing.html`) 카드로 들어간다. 사용 감각은 띄어쓰기 검사기 — 글을 넣으면
문제 자리에 밑줄이 그어지고 옆에 "왜 별로인지 / 어떻게 고칠지"가 붙는다.

- **대상**: 회원(학생) — **로그인 필수**
- **위치**: 브리핑룸 — 현재 카드 3장(항공 뉴스 / 소재 발굴 / 답변노트) + 숨김 1장(실전 모의면접) 옆
- **과금**: 무료 2회(답변노트에 글을 올려야 나온다 — 아래 '무료 2회' 참조),
  이후 10회 9,900원 충전

### ⚠️ 왜 규칙 검사까지 서버인가 (결정 3)

성립하지 않는다:

1. **차감을 브라우저가 신고하는 구조**가 되어 F12로 우회된다.

그래서 사전·규칙·프롬프트를 전부 Edge Function 안에 둔다. 대가는 왕복 1회(체감 0.3초)와
①단계를 단독 배포할 수 없다는 것 — ①은 ③과 함께 나간다.

## 판정 엔진 — 무엇을 'AI스럽다'고 잡는가

### 핵심 분업: 자리는 규칙이 찍고, 말은 AI가 한다

규칙이 밑줄 위치를 확정한 뒤, AI는 **그 자리에 대해서만** 칸을 채운다.
AI가 자리까지 고르게 두면 없는 걸 지어내고, 4겹 고삐 ②(자유 작문 공간 제거)가 깨진다.

### 4종

| 종류 | 잡는 것 | 예 |
|---|---|---|
| **상투어** | 서버 사전 2단 — ⑴ 연구진 감점 표현(오너 자료 1) ⑵ 일반 AI 상투어 | "다양한 경험", "역량을 발휘", "~을 통해", "최선을 다하겠습니다", "소중한 경험이 되었습니다" |
| **정형 구조** | 첫째·둘째·셋째 나열, 접속부사 과다(또한/더불어/나아가), **문장 길이가 지나치게 균일**, 모든 문장이 같은 어미 | 문장 길이 표준편차가 임계 이하면 걸린다 — 사람 글과 AI 글의 가장 뚜렷한 차이 |
| **구체성 결여** | 숫자·고유명사·시간·장소가 하나도 없는 문단 (밑줄이 아니라 **문단 단위 지적**) | "많은 손님을 응대하며" → 몇 명? 어디서? 언제? |
| **문맥** | 위 셋에 안 걸리지만 전형적인 자리. **AI가 추가로 최대 3곳까지 지목** | "어릴 적부터 하늘을 동경해왔습니다" |

'문맥'만 예외적으로 AI에게 지목 권한을 주되, 출력 칸 형식은 나머지와 동일하게 강제한다.

### 결과 칸 (고정 형식)

```
[걸린 표현] / 왜 그런지 1문장 / 어떻게 고칠지 1문장
```

AI는 이 칸만 채운다. 인사말·맺음말·요약이 들어갈 자리가 마크업에 없다.

### 등급 (결정 5)

절대 개수는 그대로 보여주되 **등급은 100자당 밀도로 판정**한다 — 200자 답변의 3곳과
1000자 자소서의 3곳은 전혀 다르기 때문.

| 밀도(100자당) | 등급 |
|---|---|
| < 1.0 | 사람 같음 |
| 1.0 ~ 2.5 | 조금 티남 |
| > 2.5 | AI 티 많이 남 |

임계값은 초안이며 ⑤단계 연구진 검수에서 실제 답변으로 조정한다.

### ⚠️ 밑줄 수와 등장 횟수는 다른 수다 (2026-07-25 dry-run에서 발견)

규칙 엔진을 실제 글에 돌려 보고 나온 구조적 문제다. **둘을 한 수로 묶으면 등급이 뒤집힌다.**

| 수 | 뜻 | 쓰는 곳 |
|---|---|---|
| **등장 횟수**(`occurrences`) | 표현이 나온 총 횟수 | **등급(밀도)의 분자** · DB `hit_count` |
| **밑줄 자리**(`hits.length`) | 같은 표현은 한 자리 | 화면 "고칠 곳 N" · 지적 카드 수 |

같은 표현이 일곱 번 나와도 밑줄은 **처음 한 번만** 긋는다(다 그으면 밑줄밭이 된다).
그런데 **개수까지 한 번만 세면** 글이 길수록 밀도가 인위적으로 낮아진다 —
실측: 상투어로 도배한 1,500자가 `조금 티남`으로 나왔다. 등장 횟수로 세니 `AI 티 많이 남`이 됐다.
밑줄은 화면 문제, 개수는 측정 문제다. **다시 묶지 말 것.**

**⚠️ 밑줄 자리 상한 `MAX_HITS=24`** — 371자 실측에서 15자리가 나왔으므로 1,500자면 자리만
30개 가까이 된다. 밑줄이 그만큼이면 원문이 안 읽히고 AI에 채우라고 할 칸도 그만큼 늘어난다.
**등급은 자르기 전 등장 횟수로 매기고**(자른 뒤 세면 심한 글일수록 등급이 좋아진다),
잘린 자리 수는 응답 `truncated`로 알린다 — 조용히 자르지 않는다.

**⚠️ 실측 기준선(규칙을 고치면 여기와 비교할 것)** — `node scripts/ai-killer-dryrun.mjs`
(DB·API 없이 규칙만 돌린다. 뉴스 수집기의 `--dry-run`과 같은 역할):

| 글 | 밑줄 / 등장 | 등급 |
|---|---|---|
| 전형적 AI 자소서 371자 | 15 / 16 | `heavy` |
| 사람이 잘 쓴 글 303자 | 0 / 0 | `human` ← **오탐 0이 가장 중요한 지표** |
| 짧은 면접 답변 92자 | 0 / 0 | `human` |
| 상투어 도배 1,500자 | 25 / 143 | `heavy` |

⚠️ 목업(`ai-killer-mockup.html`)의 "7곳 · 조금 티남"은 **손으로 고른 이상적인 예시**라
같은 글을 실제 엔진에 넣으면 숫자가 다르다(15곳·heavy). 목업은 화면 배치의 결정 기록이지
엔진의 기대값이 아니다 — 숫자를 맞추려고 엔진을 깎지 말 것.

### 입력 제한

- **최소 100자** — 그보다 짧으면 밀도 판정이 무의미하다(한 곳만 걸려도 등급이 튄다)
- **최대 1500자** (결정 7) — 자소서 1문항 + 여유. AI 원가 상한이기도 하다.
  자소서 여러 문항을 한꺼번에 넣는 건 의도적으로 막는다

## 무료 2회 — 올린 글에 붙인다 (결정 8)

무료분을 추상적인 "가입하면 2회"로 주지 않는다. **답변노트에 글을 올리면 그 글에 대한
검사가 무료**다.

- 학생이 답변노트에 **면접 답변 또는 자소서 문항 중 택1**해서 글을 올린다
- 그 글을 AI킬러로 검사할 때 서버가 무료 1회를 지급하고 그 자리에서 차감한다
- **회원당 2회까지**(= 서로 다른 글 2개). 3번째부터는 유료
- **같은 글로는 한 번만** — 고쳐서 다시 검사하는 것은 유료
- **붙여넣기(`source=paste`)로는 무료가 안 나온다.** 그래야 "올려야 준다"가 성립한다

왜 이렇게 하나: 공짜로 주면 가치가 0으로 읽히고 계정만 만들어 2회 쓰고 흔적 없이 떠난다.
반대로 방명록·후기 같은 별도 숙제를 시키면 없던 일을 만드는 셈이고 내용도 부실하다.
**AI킬러는 검사할 글이 있어야 쓰는 도구**라, 글을 올리게 하는 건 숙제가 아니라 순서다 —
마찰이 거의 없으면서 실제로 쓸 사람만 받아간다. 소재발굴 → 답변노트 → AI킬러 동선과도
정확히 맞고, 답변노트 사용률도 같이 오른다.

⚠️ 여러 계정으로 무한 무료를 받는 것까지는 막지 못한다. 진입 마찰을 만드는 게 목적이지
어뷰징 차단이 목적이 아니다 — 차단이 필요해지면 그때 전화번호 기준으로 조인다.

### ✅ 2026-07-25 오너 확정 — **D안(원문 + 하단 바텀시트) + 목록 토글**

원문은 온전히 두고 **카드 목록을 화면에서 뺀다.** 대신 하단 dock이 지적을 하나씩 물고,
**44px 화살표 ‹ ›로 1/7 → 2/7 순회**한다. 넘길 때마다 해당 밑줄이 `.hit`으로 강조되고
화면이 그리로 스크롤된다. '전체 목록으로 보기'를 누르면 **B안 화면(카드 목록)**으로 갈아타고,
목록에서 카드를 누르면 원문으로 돌아와 그 지적을 편다.

- **⚠️ 이 안을 고른 결정적 이유 = 원칙 2(터치 44px)를 지키는 유일한 안.**
  글 속 밑줄은 실측 **32~33px**이고 44px로 키우면 위아래 줄과 겹쳐 **본문에 있는 한 불가능**하다.
  D안은 **필수 조작이 44px 화살표**라 밑줄을 안 눌러도 검사 결과를 전부 볼 수 있다
  (밑줄 탭은 보조 수단으로만 남는다). 실측 확인: `ai-killer.html`에서 44px 미만인 요소는
  인라인 밑줄뿐이어야 한다 — 화살표·토글·저장이 44px 아래로 내려가면 이 안의 근거가 무너진다.

## 서버 — `supabase/functions/ai-killer/index.ts`

`sojae-chat` 패턴 확장. 순서:

1. 로그인 확인 (JWT)
2. 입력 길이 검증 (100~1500자)
3. **무료분 판정 → 잔여 횟수 서버 차감** (advisory lock) — 여기서 막히면 아래로 안 간다.
   `source=answer`이고 그 `answer_id`로 무료를 쓴 적 없고 회원 무료 지급 누적이 2회
   미만이면 무료 1회를 지급한 뒤 차감한다. ⚠️ 지급과 차감이 **한 트랜잭션·같은 lock 안**에
   있어야 한다 — 나누면 동시 요청 두 개가 각자 무료를 받아 2회가 4회가 된다
4. 규칙 검사 — 사전 조회 + 구조·구체성 판정
5. Claude 호출 — 걸린 자리 목록을 주고 칸만 채우게 한다
6. **자기 출력 재검사** (4겹 고삐 ③) — 걸리면 1회 재생성
7. 결과 저장 + 반환

## ⚠️ 결과에서 AI 냄새 빼기 — 4겹 고삐 (이 제품의 생명줄)

AI 티를 잡는 도구가 AI 티 나는 말투로 지적하면 그 자리에서 신뢰가 죽는다.

1. **말투의 원본 = 연구진의 실제 첨삭 문장.**
   ⚠️ **"자연스럽게 써"라고 지시하지 말 것 — 그 지시 자체가 AI스러운 결과를 낳는다.**
   대신 연구진이 실제로 학생에게 썼던 첨삭 문장을 통째로 보여주고 **"이 사람처럼 써라"**.
   지시가 아니라 흉내. 흉내가 지시보다 정확하다. (오너 말투 재현 작업에서 검증된 방식 —
   `anthropic-skills:monc-voice` 스킬과 같은 원리.)
2. **자유 작문 공간 자체를 없앤다.** AI 티는 길게 자유작문할 때 난다(인사말·"물론입니다!"·
   장황한 맺음말). 결과를 문장이 아니라 **정해진 칸**으로 받는다:
   `[걸린 표현 / 왜(1문장) / 고치기(1문장)]`. AI는 칸만 채우고 화면 틀은 우리가 그린다.
   낄 자리가 없으면 티도 못 낸다.
3. **AI킬러가 자기 출력도 킬한다.** 우리가 만든 상투어 사전("다양한", 첫째/둘째,
   "~하시길 바랍니다")을 **AI가 쓴 결과 문장에도 똑같이 돌려** 걸리면 다시 쓰게 한다.
   학생 답변을 재는 잣대로 자기 말도 재는 것 — 도구의 철학과도 맞는다.
4. **출시 전 사람 검수 2~3바퀴.** 실제 답변 20~30건 → 연구진이 "내가 안 할 말" 표시 →
   반영 → 재실행. 출시 후에도 저장된 검사 기록을 훑어 이상한 말투를 고친다
   (데이터를 모으는 이유가 하나 더 생긴다).

### ✅ ⑨단계 충전 — 포트원 자동 (2026-07-25 오너 결정으로 방식 변경)

확정본 초안은 '계좌이체 확인 방식'이었다. **오너가 포트원 자동 결제로 바꿨다.**
> 계좌이체는 3만원 챌린지엔 맞다(프로그램 시작일까지 여유가 있어 입금 확인이 하루 걸려도 된다).
> 그런데 AI킬러는 **9,900원짜리 도구**고, 학생은 자소서를 고치던 중에 '횟수 없음'을 만난다.
> 거기서 입금하고 하루 기다리라고 하면 대부분 나간다. 결제 즉시 크레딧이 들어가고 바로 이어서 쓴다.

- **`verify-payment`에 `creditPack` 분기 추가**(챌린지·특강과 같은 함수). 신청 저장이 아니라 원장에 크레딧을 넣는다.
  - ⚠️ **누구에게 넣을지는 body 가 아니라 JWT 로 정한다.** `memberId`를 믿으면 남의 계정에 넣거나 남의 결제를 가로챌 수 있다.
  - ⚠️ **금액은 DB(`site_config.credit_packs`)에서 다시 읽어 검증**한다. 브라우저가 보낸 금액 불신 — 특강과 같은 규칙.
- **⚠️ 결제 멱등성 = `credit_ledger_purchase_uq` 인덱스**(migration `20260725160000_credit_packs.sql`).
  브라우저가 `verify-payment`를 두 번 부르는 길이 여럿이다(PC 팝업 경로와 모바일 리다이렉트 복귀가 겹침 / 새로고침 / 재시도).
  함수가 사전 조회로 막지만 조회와 insert 사이엔 늘 틈이 있어 **DB 가 마지막으로 막는다.**
  ⚠️ 인덱스 키가 `(tool, ref)`이고 **member_id 가 빠진 게 핵심** — 결제 id 는 전역 고유하므로
  같은 결제를 *다른 계정에* 충전하려는 시도까지 함께 막힌다.
- **가격은 admin '크레딧' 탭에서** 바꾼다(횟수·가격 입력). 함수가 요청마다 DB 를 읽으므로 **재배포 불필요**.
- 화면(`ai-killer.html`): 충전함은 **쓸 수 있는 횟수가 하나도 없을 때만 자동으로 펼친다**(있을 땐 검사가 주인공).
  ⚠️ 모바일 리다이렉트·bfcache 처리는 `lecture.html`의 검증된 코드를 그대로 따랐다 —
  `sessionStorage` 보관 + `?payresult=1` 복귀 처리 + `pageshow`로 버튼 되돌리기.
  ⚠️ 이 화면은 **입력값(글)을 살려야 하므로 복귀 시 새로고침이 아니라 버튼만 되돌린다.**
