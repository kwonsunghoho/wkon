## 판정 엔진 — 무엇을 'AI스럽다'고 잡는가

### 핵심 분업: 자리는 규칙이 찍고, 말은 AI가 한다

규칙이 밑줄 위치를 확정한 뒤, AI는 **그 자리에 대해서만** 칸을 채운다.
AI가 자리까지 고르게 두면 없는 걸 지어내고, 4겹 고삐 ②(자유 작문 공간 제거)가 깨진다.

### 4종

| 종류 | 잡는 것 | 예 |
|---|---|---|
| **상투어** | 서버 사전 2단 — ⑴ 연구진 감점 표현(오너 자료 1) ⑵ 일반 AI 상투어 | "다양한 경험", "역량을 발휘", "~을 통해", "최선을 다하겠습니다", "소중한 경험이 되었습니다" |
| **정형 구조** | 첫째·둘째·셋째 나열, 접속부사 과다(또한/더불어/나아가), **문장 길이가 지나치게 균일**, 모든 문장이 같은 어미 | 문장 길이 표준편차가 임계 이하면 걸린다 — 사람 글과 AI 글의 가장 뚜렷한 차이 |
| **구체성 결여** | 숫자·고유명사·시간·장소가 하나도 없는 문단 (밑줄이 아니라 **문단 단위 지적**) | "많은 손님을 응대하며" → 몇 명? 어디서? 언제? |
| **문맥** | 위 셋에 안 걸리지만 전형적인 자리. **AI가 추가로 최대 3곳까지 지목** | "어릴 적부터 하늘을 동경해왔습니다" |

'문맥'만 예외적으로 AI에게 지목 권한을 주되, 출력 칸 형식은 나머지와 동일하게 강제한다.

### 결과 칸 (고정 형식)

```
[걸린 표현] / 왜 그런지 1문장 / 어떻게 고칠지 1문장
```

AI는 이 칸만 채운다. 인사말·맺음말·요약이 들어갈 자리가 마크업에 없다.

### 등급 (결정 5)

절대 개수는 그대로 보여주되 **등급은 100자당 밀도로 판정**한다 — 200자 답변의 3곳과
1000자 자소서의 3곳은 전혀 다르기 때문.

| 밀도(100자당) | 등급 |
|---|---|
| < 1.0 | 사람 같음 |
| 1.0 ~ 2.5 | 조금 티남 |
| > 2.5 | AI 티 많이 남 |

임계값은 초안이며 ⑤단계 연구진 검수에서 실제 답변으로 조정한다.

### 입력 제한

- **최소 100자** — 그보다 짧으면 밀도 판정이 무의미하다(한 곳만 걸려도 등급이 튄다)
- **최대 1500자** (결정 7) — 자소서 1문항 + 여유. AI 원가 상한이기도 하다.
  자소서 여러 문항을 한꺼번에 넣는 건 의도적으로 막는다

## 무료 2회 — 올린 글에 붙인다 (결정 8)

무료분을 추상적인 "가입하면 2회"로 주지 않는다. **답변노트에 글을 올리면 그 글에 대한
검사가 무료**다.

- 학생이 답변노트에 **면접 답변 또는 자소서 문항 중 택1**해서 글을 올린다
- 그 글을 AI킬러로 검사할 때 서버가 무료 1회를 지급하고 그 자리에서 차감한다
- **회원당 2회까지**(= 서로 다른 글 2개). 3번째부터는 유료
- **같은 글로는 한 번만** — 고쳐서 다시 검사하는 것은 유료
- **붙여넣기(`source=paste`)로는 무료가 안 나온다.** 그래야 "올려야 준다"가 성립한다

왜 이렇게 하나: 공짜로 주면 가치가 0으로 읽히고 계정만 만들어 2회 쓰고 흔적 없이 떠난다.
반대로 방명록·후기 같은 별도 숙제를 시키면 없던 일을 만드는 셈이고 내용도 부실하다.
**AI킬러는 검사할 글이 있어야 쓰는 도구**라, 글을 올리게 하는 건 숙제가 아니라 순서다 —
마찰이 거의 없으면서 실제로 쓸 사람만 받아간다. 소재발굴 → 답변노트 → AI킬러 동선과도
정확히 맞고, 답변노트 사용률도 같이 오른다.

⚠️ 여러 계정으로 무한 무료를 받는 것까지는 막지 못한다. 진입 마찰을 만드는 게 목적이지
어뷰징 차단이 목적이 아니다 — 차단이 필요해지면 그때 전화번호 기준으로 조인다.

### 답변노트 확장 (결정 9) — `20260724175000_answers_free_form.sql`

지금 `answers`는 "우리가 낸 문제에 대한 답변집"이다 — `question_id`가 `NOT NULL`이고
`questions`에 FK로 묶여 있어 **자소서 문항이 들어갈 자리가 없다.** 결정 8(글을 올려야
무료분이 나온다)이 성립하려면 자유 입력 글을 받아야 하므로 그릇을 넓힌다.

```
question_id → nullable
title       → 추가 (자유 글의 문항명. 예: "지원 동기를 기술하시오")
check       → question_id 가 있거나 title 이 있거나 (둘 다 없는 행 금지)
```

- ⚠️ **`unique(member_id, question_id)` 제약은 그대로 둔다.** Postgres unique 인덱스는
  NULL을 서로 다른 값으로 취급하므로(기본 NULLS DISTINCT), 자유 글(`question_id IS NULL`)은
  여러 개가 들어가고 문제별 답변은 여전히 회원당 1개로 유지된다. 제약을 건드릴 필요가 없다.
- `sojae.html`은 저장 시 항상 `question_id`를 채우므로 **무영향**.
- 목록을 그리는 `answers.html`·`mypage.html` 두 곳에 "문제 제목이 없으면 `title`을 쓴다"
  폴백 한 줄씩. ⚠️ **두 화면을 같이 고칠 것** — 한 곳만 고치면 자유 글이 제목 없이 뜬다.
- 답변노트 저장 UI에 종류 택1(면접 답변 / 자소서 문항)을 추가한다.

  한 답변을 고쳐가며 여러 번 검사하는 게 정상 사용이라 1:N이어야 하고, 답변노트 화면은
  그 답변의 최신 검사 1건을 조회해 배지로 보여준다
- `ai_killer_terms` — 사전(표현, 종류, 왜 별로인지, 활성 여부). admin에서 재배포 없이
  수정(리허설 패턴집 `fcd45a8`과 같은 방식)
- RLS: 본인 + 관리자만 읽기, 쓰기는 service role만

⚠️ 마이그레이션은 **오너가 Supabase SQL Editor에서 실행**해야 적용된다. 미적용 시
브리핑룸 카드가 뜨지 않도록 graceful degrade.

## 서버 — `supabase/functions/ai-killer/index.ts`

`sojae-chat` 패턴 확장. 순서:

1. 로그인 확인 (JWT)
2. 입력 길이 검증 (100~1500자)
3. **무료분 판정 → 잔여 횟수 서버 차감** (advisory lock) — 여기서 막히면 아래로 안 간다.
   `source=answer`이고 그 `answer_id`로 무료를 쓴 적 없고 회원 무료 지급 누적이 2회
   미만이면 무료 1회를 지급한 뒤 차감한다. ⚠️ 지급과 차감이 **한 트랜잭션·같은 lock 안**에
   있어야 한다 — 나누면 동시 요청 두 개가 각자 무료를 받아 2회가 4회가 된다
4. 규칙 검사 — 사전 조회 + 구조·구체성 판정
5. Claude 호출 — 걸린 자리 목록을 주고 칸만 채우게 한다
6. **자기 출력 재검사** (4겹 고삐 ③) — 걸리면 1회 재생성
7. 결과 저장 + 반환

모델은 리허설과 같은 Opus 4.8로 시작. 회당 원가는 ③ 착수 시 실측해 9,900원/10회 안에
드는지 확인하고, 여유가 빠듯하면 ⑤단계에서 하위 모델과 품질을 비교한다.

⚠️ **Edge Function 배포는 CLI가 아니라 Supabase 콘솔에서** — 오너 PC에 `supabase` CLI가
없다. `Edge Functions > ai-killer > 코드 교체 > Deploy`.

## ⚠️ 결과에서 AI 냄새 빼기 — 4겹 고삐 (이 제품의 생명줄)

AI 티를 잡는 도구가 AI 티 나는 말투로 지적하면 그 자리에서 신뢰가 죽는다.

1. **말투의 원본 = 연구진의 실제 첨삭 문장.**
   ⚠️ **"자연스럽게 써"라고 지시하지 말 것 — 그 지시 자체가 AI스러운 결과를 낳는다.**
   대신 연구진이 실제로 학생에게 썼던 첨삭 문장을 통째로 보여주고 **"이 사람처럼 써라"**.
   지시가 아니라 흉내. 흉내가 지시보다 정확하다. (오너 말투 재현 작업에서 검증된 방식 —
   `anthropic-skills:monc-voice` 스킬과 같은 원리.)
2. **자유 작문 공간 자체를 없앤다.** AI 티는 길게 자유작문할 때 난다(인사말·"물론입니다!"·
   장황한 맺음말). 결과를 문장이 아니라 **정해진 칸**으로 받는다:
   `[걸린 표현 / 왜(1문장) / 고치기(1문장)]`. AI는 칸만 채우고 화면 틀은 우리가 그린다.
   낄 자리가 없으면 티도 못 낸다.
3. **AI킬러가 자기 출력도 킬한다.** 우리가 만든 상투어 사전("다양한", 첫째/둘째,
   "~하시길 바랍니다")을 **AI가 쓴 결과 문장에도 똑같이 돌려** 걸리면 다시 쓰게 한다.
   학생 답변을 재는 잣대로 자기 말도 재는 것 — 도구의 철학과도 맞는다.
4. **출시 전 사람 검수 2~3바퀴.** 실제 답변 20~30건 → 연구진이 "내가 안 할 말" 표시 →
   반영 → 재실행. 출시 후에도 저장된 검사 기록을 훑어 이상한 말투를 고친다
   (데이터를 모으는 이유가 하나 더 생긴다).

## 오너가 줄 자료 3종

1. **감점 표현 목록(제일 중요)** — 연구진에게 "면접에서 들으면 속으로 한숨 쉬는 표현" 20~50개.
   형식 자유(카톡 나열도 OK). 가능하면 각각 "왜 별로인지" 한 줄.
2. **실제 첨삭 자료** — 학생 답변 원문 + 연구진 첨삭 코멘트. 10건이어도 충분. 개인정보 제거.
   ⚠️ 첨삭 '내용'만이 아니라 **첨삭 '말투'의 원본**이라 가장 값지다(4겹 고삐 ①).
3. **합격자 레퍼런스 — 있는 대로 전부** (2026-07-24 오너 제안으로 용도 확정, 결정 10).
   그동안 작성해 온 합격자 자료. 3~5개가 아니라 **많을수록 정확해진다.** 개인정보 제거.

   ⚠️ **AI에게 "이렇게 쓰라"고 예시로 주지 말 것.** 그러면 AI가 합격자 답변을 베껴
   학생 답변을 전부 그 방향으로 끌고 가고, 결국 모두가 비슷한 글이 된다 — 우리가 잡으려는
   AI스러움을 우리가 만드는 꼴이다.

   **진짜 용도는 오탐 필터다.** 규칙 기반 검사기가 망하는 이유는 못 잡아서가 아니라
   **멀쩡한 표현에 밑줄을 그어서**다. 합격자 레퍼런스 전체에 우리 규칙을 돌려
   **합격한 글에서 자주 걸리는 규칙은 잘못된 규칙이니 버린다.** 감이 아니라 숫자로
   판정되므로 ⑦단계 검수의 뼈대가 된다.

   > 자료 2번(첨삭 코멘트) = **결과 말투의 원본**(4겹 고삐 ①)
   > 자료 3번(합격자 레퍼런스) = **규칙 오탐 필터**
   > 둘은 다른 일을 한다. 섞지 말 것.

## 만드는 순서

원 6단계에서 ①이 서버로 옮겨간 것을 반영한 순서.

| 단계 | 내용 | 막는 것 |
|---|---|---|
| **1. 시안** | `outputs/` 목업 2~3안 → 오너 선택 | 없음 — 지금 착수 |
| **2. 원장·그릇** | 공용 크레딧 원장 + 검사 기록·사전 테이블 | 오너: SQL 실행 |
| **3. 답변노트 확장** | `answers` 자유 글 허용 + 종류 택1 UI + `answers.html`·`mypage.html` 폴백 | 오너: SQL 실행 |
| **4. 규칙 엔진** | 4종 판정 로직. 사전 없이 일반 AI 상투어만으로 먼저 동작 | 없음 |
| **5. 중계 함수** | `ai-killer` Edge Function (무료분 판정→차감→규칙→Claude→자기검사→저장) | 오너: Anthropic 계정 + 카드 + 월 한도, 콘솔 배포 |
| **6. 화면** | `ai-killer.html` + 브리핑룸 카드 + 답변노트 연동 + 동의 게이트 | 없음 |
| **7. 법적** | `privacy.html` 갱신 — 수집 항목 + Anthropic 위탁·국외이전 | 오너: 방침 승인 |
| **8. 말투 조련** | 자료 3종 반영 + 합격자 레퍼런스로 오탐 제거 + 검수 2~3바퀴 | 오너: 자료 + 연구진 검수 |
| **9. 결제·배포** | 10회 9,900원 충전(계좌이체 확인 방식) + 카드 공개 | 없음 |

1~4는 자료 없이 병행 가능 — 오너가 자료를 모으는 동안 진행한다.
3번(답변노트 확장)은 AI킬러와 독립적으로 쓸모가 있어 먼저 배포해도 된다.
