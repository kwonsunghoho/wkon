# AI킬러 · 답변 첨삭 화면 구분 — 설계 (2026-08-06)

## 배경

오너: *"학생 입장에서 두 화면 차이가 잘 보이게 문구, 디자인을 다듬어야해."*

두 도구는 같은 엔진(ai-killer 함수) 위의 다른 상품인데, 입력 화면이 쌍둥이였다 —
글 종류·항공사·문항·본문 칸이 같은 부품이고 다른 건 제목 한 줄과 버튼 글자뿐.
오너부터 "시스템이 똑같은 거야?"라고 물었다.

## 확정안 — B안 '무대 반전' (시안 3벌 중 오너 선택)

**색으로 가른다.** AI킬러(찾기)는 머리만 다크 네이비 무대, 답변 첨삭(고치기)은 순백 유지.
둘 다 머리에 ①찾기→②고치기 순서 띠를 얹어 짝임을 말하고 서로로 넘어가게 한다.
홈 마무리 CTA 와 같은 '다크 무대' 문법이라 사이트 안에서 낯설지 않다.

같이 확정된 결정:
- 손보는 범위 = 도구 화면 2개 + 승준노트 허브 카드 (사이트 전체 아님).
- 관계는 화면에 드러낸다(각자 역할만 키우는 안 기각).

## 파일별 변경

### ai-killer.html (입력 화면 머리만)
- 순서 띠 + 제목 + 부제를 `.stage`(다크 네이비 판, `--bg-dark`)로 감싼다.
- 제목: "어디가 AI처럼 읽히는지 **찾아드려요**" — ⚠️ 다크 위 제목은 색을 자기 규칙에 명시
  (전역 `h1{color:var(--ink)}` 가 이겨서 제목이 배경에 사라진다 — apply 배너 전례).
- 부제: "AI 같은 문장을 밑줄로 짚어요. 고치는 건 ② 첨삭이 해요." — 첨삭이 링크,
  다크 위 강조는 `--action-on-dark`.
- 띠: 현재 화면 알약은 **흰 알약 + 네이비 글씨**(다크 위 CTA 규칙), 반대쪽은 흰 테두리 링크.
- 버튼: "KILL AI — AI 같은 문장 찾기" (HTML 초기값 + JS 리셋 문자열 두 곳).
- 입력칸·항공사·검사 동작·과금·결과 화면은 무변경.

### polish.html
- 순백 유지. 같은 순서 띠(여기선 ②가 네이비로 칠해짐), 제목 옆 만년필 아이콘.
- 제목: "고친 문장까지 써 드려요" / 부제: "잘한 건 지키고, 고칠 문장은 '지금 → 이렇게'로
  보여드려요. 어디가 문제인지 먼저 보려면 ① AI킬러."(링크)
- 버튼: "첨삭 받기 — 고친 예시까지" (HTML + JS 두 곳).
- 이름 통일: nav-t·`<title>`·og:title·twitter:title 전부 "답변 첨삭"
  (제목 3값 동일 규칙 · 허브/nav 라벨과 일치).

### briefing.html (허브 자유 선택 도구)
- 타일 순서 교환: AI킬러가 먼저(①), 답변 첨삭이 다음(②) — 읽는 순서와 단계 순서를 맞춘다.
- 타일 모서리에 번호 배지(24px 네이비 원 + 흰 테두리), 이름 밑에 역할 한 줄(12px):
  "AI 같은 문장을 찾아요" / "고친 문장까지 써 드려요".
- 금액·회원별 상태 문구 없음(허브 카드 금지 규칙). 배지는 근거 있는 '순서'라 '인기/NEW' 금지와 무관.

## 지키는 규칙
- 서버·크레딧·검사 로직 무변경. 도구 이름(AI킬러·답변 첨삭) 유지.
- 순서 띠는 실제 `<a>`(포커스·키보드 원칙), 알약 44px 터치.
- bfcache: 두 페이지 모두 '결제 복귀 화면' 예외(버튼만 복원) — 그 흐름 안 건드림.
- 문구·모양만이라 확인 후 main 직행(오너 푸시 규칙), 375px 실측 후.

## 검증
- 375px 렌더 실측: 가로 스크롤 없음, 띠 알약 44px+, 다크 판 위 제목·링크 대비,
  버튼 문구 잘림 없음. 허브는 배지·역할 줄이 3열 그리드를 깨지 않는지.
