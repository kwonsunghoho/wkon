# 연구실 유료 자료집 — 설계·구현

> 2026-08-01 오너와 확정, 같은 날 구현. 연구실 서가에 올라가는 자료마다 값을 매겨
> 팔고, 구매자만 열람·다운로드하게 한다.

> **⚠️ 이 문서의 첫 판은 새 테이블(`lab_materials`)을 만드는 설계였다.** 같은 날 이미
> `lab_resources`(자료)·`lab-file`(서명 URL·워터마크·비밀번호)·`lab-shelf.html`(서가)
> 이 구현돼 있어 **전량 폐기하고 기존 구조 확장으로 다시 썼다.** 새 표를 만들었다면
> 자료가 두 곳으로 갈라지고 admin·목록 RPC·Edge Function 이 두 벌이 됐다.
> **없던 것은 '값' 하나뿐이었다.**

## 오너가 정한 것(되돌리지 말 것)

1. **자료 하나하나마다 금액을 설정한다.** 항공사 묶음 상품이 아니다 — 무료와 유료가 같은 서가에 섞이고, 값은 `price` 한 칸이 정한다(0 = 무료).
2. **금액은 언제든 바꾼다.** admin '연구실 자료' 탭의 [가격] 버튼, 재배포 불필요. 이미 구매한 사람의 결제액은 `lab_purchases.amount` 가 보존한다(값을 올려도 과거 영수증이 흔들리지 않는다).
3. **웹 열람 + PDF 다운로드 둘 다.** 기존 `delivery`(download/view)가 이미 담당한다.
4. **현금 단건 결제**(포트원 V2 + verify-payment). 크레딧으로 열지 않는다 — 하루 무료 5크레딧이 저가 자료를 매일 공짜로 여는 구멍이 되고(첨삭 잠금과 같은 원리 · credits.md), 자료값과 AI 도구값은 축이 달라 섞으면 둘 다 흔들린다.

## 1. 데이터 — migration `20260801160000_lab_paid.sql`

기존 `lab_resources` 에 값만 붙인다. 새 자료 테이블 없음.

| 대상 | 변경 |
|---|---|
| `lab_resources` | `price integer not null default 0` + `check (price >= 0)` |
| `lab_purchases`(신규) | `resource_id`·`user_id`·`amount`·`payment_id`, **`unique(resource_id, user_id)`**, `unique(payment_id)` |
| `lab_resource_list()` | 반환에 `price`·`owned` 추가(반환 타입이 바뀌어 drop 후 재생성) |
| `lab_my_purchases()`(신규) | 마이페이지 '구매한 자료' — 제목이 필요한데 `lab_resources` 에 회원 읽기 정책이 없어 definer 함수로 제목만 내보낸다 |
| `lab_sales_summary()`(신규) | admin 판매 집계. **함수 본문에 `where public.is_admin()`** — 관리자가 아니면 한 행도 안 나간다 |

- `lab_purchases` RLS: 본인 select + admin all. **INSERT 정책 없음** — 지급은 verify-payment(service_role)와 admin 뿐이다(자가 INSERT 를 열면 결제를 건너뛴 무료 구매 경로가 생긴다).
- **유료 판정은 `price > 0` 하나.** `access`(member/password)는 '어떻게 여는가'로 축이 다르다. 둘을 같이 걸면 산 사람이 또 막히므로 admin 화면이 그러지 말라고 안내한다.
- `lab_sales_summary()` 는 **스칼라 서브쿼리로 센다** — 구매·열람 테이블을 join 두 개로 묶으면 카티전 곱이 나서 `sum(amount)` 가 열람 수만큼 부풀려진다(매출이 몇 배로 보인다).

## 2. 결제 — verify-payment `resourceId` 분기

이용권(`programId`) 분기를 그대로 본떴다. 구조가 같다.

1. **JWT 로 구매자 확정**(body 의 회원 id 를 믿지 않는다)
2. `lab_resources` 에서 `price`·`published` **재조회** — 브라우저가 보낸 금액 불신. `price <= 0` 이거나 미공개면 `resource_not_for_sale`
3. 같은 `payment_id` 기록이 있으면 `{ok:true, already:true}`(모바일 복귀 중복 호출 방어)
4. 포트원 조회 → `PAID` 아니면 402, 금액 불일치면 `amount_mismatch`
5. `lab_purchases` insert. 유니크 위반(23505) = **이미 산 자료를 또 결제** → 전액 자동 환불 + **HTTP 200** + `already_purchased`
6. 다른 이유로 실패해도 전액 환불 + HTTP 200(돈만 나간 상태를 남기지 않는다)

⚠️ **실패를 non-2xx 로 돌려주지 말 것** — supabase-js 가 본문을 감춰 브라우저가 환불 사실을 안내하지 못한다.

## 3. 열람 게이트 — lab-file 함수 (`FN_VERSION 2026-08-01f`)

순서: 회원 확인 → 열람 방식 → **구매 확인(신규)** → 비밀번호 → 파일·링크.

```
if (Number(res.price) > 0) {
  lab_purchases 조회
  조회 실패(buyErr) → not_ready 로 멈춘다      // ★
  기록 없음        → need_purchase + price
}
```

⚠️ **★ 조회가 실패하면 열어 주지 않는다.** 통과시키면 유료 자료가 영구 무료가 된다(프로젝트 공통 규칙 — polish p-1 전례).
⚠️ 구매 확인이 **비밀번호보다 먼저다** — 돈을 안 낸 사람에게 비밀번호부터 묻는 건 순서가 뒤집힌 것이다.

## 4. 화면 — lab-shelf.html

- 목록 카드 오른쪽에 **값을 활자로** 표시. `구매함`은 흐린 회색. **무료에는 아무 표시도 하지 않는다** — 목록 대부분이 무료라 '무료' 알약을 다 붙이면 정작 유료가 묻힌다. 값이 붙은 자료는 자물쇠·눈 아이콘 대신 값을 보여준다.
- `need_purchase` → **구매 바텀시트**(비밀번호 시트와 같은 뼈대): 제목 · 값 · **비교 기준 한 줄** · 결제 버튼 · "한 번 사면 계정에 남는다" 안내.
- **비교 기준 문구를 빼지 말 것** — "학원 항공사 정보 특강은 회당 3~5만 원입니다." 이 한 줄이 없으면 9,900원이 싼지 비싼지 판단이 안 돼 결제가 일어나지 않는다(크레딧 팩에서 확인된 부분).
- 결제 후: 시트를 닫고 목록을 새로 불러 '구매함'을 갱신한 뒤 그 자료를 바로 연다.
- **모바일 복귀**: `sessionStorage['monc_pending_lab_pay']` + `?payresult=1` → `resumePay()`. 다른 서가의 복귀면 무시한다.
- **bfcache**: 결제로 나갔다 돌아오면 버튼이 '진행 중…'에 멈춘다 — `pageshow`(persisted)에서 버튼만 되돌린다(입력값이 없는 화면).

## 5. admin — '연구실 자료' 탭 (화면 버전 `2026-08-01d`)

- 등록 폼에 **가격(원)** 칸. ⚠️ **0 이면 insert 에 `price` 를 아예 넣지 않는다** — 유료 마이그레이션 전 환경에서 없는 컬럼을 보내면 등록 자체가 막힌다.
- 목록 행에 [가격] 버튼(prompt 수정) · 값이 붙은 자료는 `💰 9,900원` · 팔린 자료는 `판매 3건 · 29,700원 · 열람 12회`.
- 판매 집계 RPC 가 없으면(미적용) 조용히 건너뛴다.
- **구매자가 있는 자료는 삭제가 막힌다**(FK `on delete restrict` — 영수증을 지우지 않기 위한 설계). 그때는 [숨기기]를 안내한다.

## 6. 마이페이지

`구매한 자료` 접이 — `lab_my_purchases()`. **산 게 없거나 마이그레이션 전이면 접이를 열지 않는다**(mypage.md: 접이는 데이터 있는 줄만).

## 7. 가격 — 제안값

오너가 자료마다 넣는 값이고, 아래는 기존 상품과 나란히 놓고 잡은 기준선이다
(챌린지 30,000 / 크레딧 기본 팩 10,000·30크레딧 / 학원 자소서 첨삭 한 문항 2~5만).

| 자료 성격 | 제안 | 근거 |
|---|---|---|
| 맛보기(항공사별 1건) | **0원** | 무료 칸이 없으면 유료 자료의 값어치를 판단할 근거가 없다 |
| 단품(리포트 1편·기출 모음) | **2,900~4,900원** | 첫 결제 문턱을 넘기는 자리 |
| 항공사 자료집 본편 | **9,900원** | 크레딧 기본 팩과 같은 값 — 이미 그 값을 내 본 사람들이라 저항이 낮다 |
| 시즌 패키지 | **19,900~29,900원** | 챌린지(30,000) 아래에 둔다. 넘으면 챌린지 결제를 갉아먹는다 |

## 8. 함정 목록

- **자료 테이블을 새로 만들지 말 것** — 이 문서 머리의 경고. `lab_resources` 가 원장이다.
- **`lab_purchases` 에 회원 자가 INSERT 정책 금지** — 무료 구매 경로가 열린다.
- **결제 실패·중복을 non-2xx 로 돌려주지 말 것** — 환불 안내가 사라진다.
- **구매 조회 실패 시 열어 주지 말 것** — 영구 무료 결함.
- **판매 집계를 join 두 개로 만들지 말 것** — 매출이 부풀려진다.
- **admin insert 에 `price: 0` 을 보내지 말 것** — 미적용 환경에서 등록이 막힌다.
- **비교 기준 한 줄을 빼지 말 것** — 값의 근거가 사라져 결제가 멈춘다.
- 유료 자료에 **비밀번호를 같이 걸지 말 것** — 산 사람이 또 막힌다.

## 9. 검증

- **375px 실측**(2026-08-01): 목록 가로 넘침 0(375=375) · 값 활자 12.5px · 제목/값 겹침 없음 · 구매 시트 버튼 52px(터치 44px+) · 시트 활자 12px 이상.
